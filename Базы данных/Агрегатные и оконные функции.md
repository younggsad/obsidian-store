### Агрегатные функции

> Агрегатные функции **сворачивают** множество строк в одно значение. Используются самостоятельно (по всей таблице) или вместе с `GROUP BY` (по каждой группе отдельно).

```sql
SELECT COUNT(*) FROM users;                          -- количество строк

SELECT COUNT(email) FROM users;                       -- количество НЕ-NULL значений в email

SELECT COUNT(DISTINCT country) FROM users;             -- количество уникальных стран

SELECT SUM(total) FROM orders;                         -- сумма всех значений

SELECT AVG(total) FROM orders;                         -- среднее значение

SELECT MAX(total) FROM orders;                         -- максимум

SELECT MIN(total) FROM orders;                         -- минимум

SELECT STRING_AGG(name, ', ') FROM users;              -- склеивание строк в одну (PostgreSQL);
                                                        -- в MySQL — GROUP_CONCAT(name SEPARATOR ', ')
```

**Важный нюанс `COUNT(*)` vs `COUNT(column)`:**

- `COUNT(*)` — считает **все строки**, включая те, где есть `NULL` в любом столбце.
- `COUNT(column)` — считает только строки, где **этот конкретный столбец НЕ NULL**.

```sql
-- Если у 2 из 10 пользователей email = NULL:
SELECT COUNT(*) FROM users;      -- 10
SELECT COUNT(email) FROM users;  -- 8
```

> **Агрегатные функции игнорируют `NULL`** (кроме `COUNT(*)`) — например, `AVG` считает среднее только по не-NULL значениям, не подставляя вместо NULL ноль.

**Комбинация с GROUP BY — типичный практический паттерн:**

```sql
SELECT
  user_id,
  COUNT(*)         AS orders_count,
  SUM(total)        AS total_spent,
  AVG(total)         AS avg_order_value,
  MAX(total)          AS biggest_order
FROM orders
GROUP BY user_id
HAVING SUM(total) > 1000
ORDER BY total_spent DESC;
```

### Оконные функции (window functions)

> Более продвинутая тема, отличается от `GROUP BY` тем, что **не схлопывает** строки в одну — считает агрегат/ранжирование, но **сохраняет** все исходные строки.

```sql
SELECT
  name,
  total,
  SUM(total) OVER (PARTITION BY user_id)      AS user_total,       -- сумма по группе, строки не схлопнуты
  RANK()      OVER (ORDER BY total DESC)       AS rank_by_total,
  ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY total DESC) AS rn
FROM orders;
```

> `PARTITION BY` — аналог `GROUP BY`, но для оконной функции: делит данные на группы, внутри которых считается агрегат, при этом **каждая исходная строка сохраняется** в результате (в отличие от `GROUP BY`, где строки одной группы схлопываются в одну).

**Разница между популярными ранжирующими функциями:**

```sql
-- Данные: total = [100, 100, 90]

ROW_NUMBER() -- 1, 2, 3   — уникальный номер строки, даже при одинаковых значениях
RANK()       -- 1, 1, 3   — одинаковый ранг при равенстве, следующий ранг "прыгает"
DENSE_RANK() -- 1, 1, 2   — одинаковый ранг при равенстве, следующий ранг идёт подряд
```

**Практический пример: убрать дубликаты, оставив по одной "последней" строке на группу** (частая задача на собесах):

```sql
WITH ranked AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at DESC) AS rn
  FROM orders
)
SELECT * FROM ranked WHERE rn = 1; -- последний заказ каждого пользователя
```

**Функции доступа к соседним строкам:**

```sql
SELECT
  user_id,
  created_at,
  total,
  LAG(total)  OVER (PARTITION BY user_id ORDER BY created_at) AS prev_order_total,
  LEAD(total) OVER (PARTITION BY user_id ORDER BY created_at) AS next_order_total
FROM orders;
```

`LAG`/`LEAD` полезны для сравнения текущей строки с предыдущей/следующей — например, посчитать разницу между текущим и прошлым заказом клиента без самостоятельного `JOIN`.
