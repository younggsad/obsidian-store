### Репликация (replication)

> Копирование данных с одного сервера (**primary/master**) на один или несколько других (**replica/slave**).

- **Master-Slave (Primary-Replica)** — запись только на master, чтение можно распределять по репликам. Снижает нагрузку на чтение, даёт отказоустойчивость (replica может стать новым master при падении).
- **Master-Master** — запись возможна на несколько узлов, сложнее (риск конфликтов при одновременной записи одних и тех же данных).

**Синхронная vs асинхронная репликация:**

> **Синхронная** — `COMMIT` на master ждёт подтверждения записи на реплике(-ах) — гарантирует отсутствие потери данных, но медленнее. **Асинхронная** — `COMMIT` на master происходит сразу, реплика догоняет с задержкой (**replication lag**) — быстрее, но при падении master до синхронизации возможна потеря последних изменений.

### Шардирование (sharding)

> Горизонтальное разбиение данных **по строкам** между разными серверами — на каждом сервере (шарде) хранится только часть данных (например, пользователи с id от 1 до 1 000 000 на шарде 1, остальные — на шарде 2).

Способы выбора шарда: по диапазону значений ключа (range-based), по хэшу ключа (hash-based, обычно даёт более равномерное распределение), по географии/тенанту.

Плюсы: позволяет масштабировать запись горизонтально (в отличие от репликации, где вся запись всё равно идёт через один master). Минусы: сложные `JOIN`/транзакции между шардами, сложность перешардирования при росте.

### Партиционирование (partitioning)

> Разбиение **одной логической таблицы** на физические части (партиции) **в пределах одной базы данных**, обычно по диапазону значений (дате, id) или по списку значений.

```sql
CREATE TABLE orders (
  id SERIAL,
  created_at DATE NOT NULL,
  total NUMERIC
) PARTITION BY RANGE (created_at);

CREATE TABLE orders_2025 PARTITION OF orders
  FOR VALUES FROM ('2025-01-01') TO ('2026-01-01');
```

Отличие от шардирования: партиции обычно живут на одном сервере (хотя есть и распределённые варианты), это способ ускорить запросы и обслуживание (например, быстро удалить старые данные, просто дропнув партицию целиком) внутри одной СУБД, а не способ масштабировать её на несколько машин.
