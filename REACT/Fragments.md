## 💡 Суть

JSX-выражение обязано возвращать **один корневой элемент**. Но часто не хочется оборачивать группу элементов в лишний `<div>` — это засоряет DOM и может ломать вёрстку (например, в `<table>`, `flex`/`grid` раскладках).

**Fragment** — это способ сгруппировать несколько элементов **без создания лишнего узла в реальном DOM**.

> [!info] Почему это вообще нужно 
> React-компонент технически возвращает одно значение. `<A /><B />` — это два выражения, JSX так не работает. Fragment оборачивает их в одно валидное выражение, но не добавляет тег в итоговый HTML.

## 📌 Синтаксис

```jsx
// Полная запись
import { Fragment } from 'react';

function List() {
  return (
    <Fragment>
      <li>Раз</li>
      <li>Два</li>
    </Fragment>
  );
}
```

```jsx
// Короткий синтаксис (наиболее частый)
function List() {
  return (
    <>
      <li>Раз</li>
      <li>Два</li>
    </>
  );
}
```

> [!warning] Короткий синтаксис `<>...</>` не поддерживает атрибуты 
> Если нужен `key` — придётся использовать полную форму `<Fragment>`.

## 🔑 Fragment с key

Единственный случай, когда нужна полная форма — рендер списка фрагментов, где каждому нужен уникальный `key` (см. [[Keys and Lists]]):

```jsx
function Glossary({ items }) {
  return (
    <dl>
      {items.map((item) => (
        <Fragment key={item.id}>
          <dt>{item.term}</dt>
          <dd>{item.description}</dd>
        </Fragment>
      ))}
    </dl>
  );
}
```

Здесь `<dt>` и `<dd>` должны идти на одном уровне вложенности (для корректной семантики `<dl>`), и обернуть их в `<div>` нельзя — это сломает вёрстку. Fragment решает проблему.

## ✅ Когда использовать

- Компонент должен вернуть несколько соседних элементов
- Нужно избежать лишней обёртки в семантически строгой разметке (`<table>`, `<dl>`, flex/grid-контейнеры)
- Компонент возвращает список из нескольких элементов в цикле

## ⚠️ Частые ошибки / нюансы

> [!danger] Лишние div-обёртки как антипаттерн
> 
> 
> ```jsx
> function Row() {
>   return (
>     <div> {/* лишний узел в DOM */}
>       <td>1</td>
>       <td>2</td>
>     </div>
>   );
> }
> ```
> 
> Внутри `<tr>` это сломает таблицу — браузер проигнорирует невалидную структуру. Fragment решает это без побочных эффектов.

> [!tip] Fragment не создаёт DOM-узел 
> Значит на нём **нельзя** повесить `ref`, `className`, `style` и т.д. (кроме `key` в полной форме) — Fragment не существует в реальном DOM, только в дереве React-элементов.
