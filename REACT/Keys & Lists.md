## 💡 Суть

Когда React рендерит список элементов (через `.map()`), ему нужно понимать, **какой элемент — какой**, чтобы при изменении данных не перерисовывать весь список заново, а точечно обновить, добавить или удалить нужные узлы.

Для этого используется специальный проп — **`key`**. Он не передаётся в сам компонент, а служит подсказкой для React во время **reconciliation** (сверки Virtual DOM).

> [!info] Связь с Reconciliation 
> `key` — это как раз тот механизм, который позволяет алгоритму сверки понять: элемент просто переместился, а не был удалён и создан заново. Подробнее — [[Reconciliation]].

## 📌 Ключевые моменты

- `key` должен быть **уникальным среди соседних элементов** (не обязательно глобально уникальным во всём приложении)
- `key` должен быть **стабильным** — не меняться между рендерами для одного и того же элемента
- `key` **не передаётся** в компонент как обычный проп (если нужно его использовать внутри — передавайте отдельным пропом)
- React **не гарантирует порядок**, в котором применяются key при сравнении — важна сама привязка "id → элемент"

## ⚠️ Частые ошибки

> [!danger] Использование index в качестве key
> 
> 
> ```jsx
> {items.map((item, index) => (
>   <Item key={index} {...item} />
> ))}
> ```
> 
> Работает, но **опасно**, если список может:
> 
> - менять порядок элементов
> - добавлять/удалять элементы не с конца
> - фильтроваться
> 
> В этих случаях React будет неправильно сопоставлять старые и новые элементы — это может привести к багам с состоянием компонентов (например, в контролируемых инпутах внутри списка) и к лишним перерисовкам.

> [!tip] Когда index как key — это нормально
> 
> - Список статичен и никогда не меняется
> - Элементы никогда не переупорядочиваются и не фильтруются
> - У элементов нет своего состояния (state) и рефов

## ✅ Как правильно

```jsx
// Хорошо: используем уникальный стабильный id из данных
{todos.map((todo) => (
  <TodoItem key={todo.id} todo={todo} />
))}
```

Если в данных нет `id` — либо сгенерировать его при создании элемента (например, `crypto.randomUUID()`), либо использовать комбинацию уникальных полей (но не рекомендуется, если поля могут повторяться).

## 🔬 Что происходит без key вообще

Если `key` не указан, React:

- выводит **warning** в консоль (`Warning: Each child in a list should have a unique "key" prop`)
- по умолчанию использует индекс элемента — с теми же рисками, что описаны выше

## 🧠 Как React использует key при сверке

1. React сравнивает список ключей **старого** дерева со списком ключей **нового** дерева
2. Элементы с совпадающими key считаются "тем же" элементом → React переиспользует DOM-узел и сохраняет его внутреннее состояние
3. Элементы с новыми key → создаются заново
4. Элементы, ключи которых пропали → размонтируются (unmount), теряя state

> [!example] Демонстрация проблемы с index 
> Список из инпутов, где пользователь начал печатать в третьем элементе. Если удалить первый элемент списка, а key = index — React решит, что "элемент под key=2" — это тот же элемент, что и раньше, просто с новыми пропсами, и текст в инпуте "переедет" не туда, куда ожидалось.
