>**Prop drilling** — это ситуация, когда данные нужно передать из компонента верхнего уровня в глубоко вложенный компонент, и приходится прокидывать пропсы через **все промежуточные компоненты**, которым эти данные сами по себе не нужны — они просто передают их дальше.


```jsx
function App() {
  const user = { name: "Alice" };
  return <Layout user={user} />;
}

function Layout({ user }) {
  return <Sidebar user={user} />; // Layout сам не использует user, просто прокидывает
}

function Sidebar({ user }) {
  return <Profile user={user} />; // Sidebar тоже просто прокидывает
}

function Profile({ user }) {
  return <div>{user.name}</div>; // а вот тут наконец используется
}
```

Проблема: если структура компонентов глубокая, каждое изменение (добавить новый проп, переименовать) требует правки **всех** промежуточных компонентов — это хрупко и неудобно поддерживать.

**Реальные способы решения:**

**1. Context API** — встроенный в React механизм, позволяет "положить" значение в дерево компонентов на верхнем уровне и **напрямую** забрать его в любом глубоко вложенном компоненте, минуя все промежуточные:

```jsx
const UserContext = createContext();

function App() {
  const user = { name: "Alice" };
  return (
    <UserContext.Provider value={user}>
      <Layout />
    </UserContext.Provider>
  );
}

function Profile() {
  const user = useContext(UserContext); // напрямую, без прокидывания через Layout/Sidebar
  return <div>{user.name}</div>;
}
```

**2. State management библиотеки** — Redux, Zustand, MobX, Recoil и т.д. — выносят состояние в отдельное "глобальное" хранилище вне дерева компонентов, и любой компонент может подписаться на нужную часть состояния напрямую, независимо от того, насколько глубоко он вложен.

**3. Композиция компонентов (component composition)** — менее очевидный, но важный способ, который часто забывают: вместо того чтобы прокидывать данные через промежуточные компоненты, можно передавать **сам JSX** через `children` или пропсы-компоненты — тогда промежуточному компоненту вообще не нужно знать про эти данные:

```jsx
function Layout({ children }) {
  return <div className="layout">{children}</div>; // не знает про user вообще
}

function App() {
  const user = { name: "Alice" };
  return (
    <Layout>
      <Profile user={user} /> {/* Profile получает user напрямую от App */}
    </Layout>
  );
}
```

**Практическое правило:** Context — для данных, которые действительно нужны широко по дереву (тема оформления, авторизованный пользователь, язык интерфейса). Для сложного, часто изменяющегося состояния с множеством взаимодействий — обычно берут выделенную библиотеку (Redux/Zustand), так как Context не оптимизирован для частых обновлений (любое изменение контекста триггерит ре-рендер всех подписанных компонентов). Композиция — недооценённый, но часто самый простой способ, если проблема не в "глобальности" данных, а просто в неудачной структуре дерева компонентов.
