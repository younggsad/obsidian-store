## 💡 Определение

**SyntheticEvent** — это кроссбраузерная обёртка над нативным событием DOM (`Event`), которую React создаёт и передаёт в обработчики событий вместо "сырого" браузерного объекта.

Формальная причина существования: спецификация событий DOM реализована в разных браузерах неодинаково (разные названия свойств, разное поведение `bubbling`/`capturing`, разная поддержка). SyntheticEvent предоставляет **единый, предсказуемый API**, идентичный во всех браузерах, поверх нативной реализации.

> [!info] Формулировка для собеседования 
> "SyntheticEvent — это обёртка React над нативным событием, реализующая тот же интерфейс, что и `Event` в W3C-спецификации (включая `stopPropagation()`, `preventDefault()`), но гарантирующая единообразное поведение вне зависимости от браузера."

## 🏗️ Как это устроено технически

1. Браузер генерирует нативное событие (например, `click`) в реальном DOM
2. React **не** навешивает обработчики на каждый DOM-узел индивидуально. Вместо этого он использует **делегирование событий**: с React 17+ единый обработчик подписан на **корневой контейнер приложения** (до React 17 — на `document`)
3. React перехватывает событие на этапе всплытия (или погружения — для событий с `Capture` в названии), создаёт объект `SyntheticEvent`, оборачивающий нативное событие, и вызывает соответствующий обработчик из виртуального дерева
4. После завершения всех обработчиков в текущем цикле событие возвращается в пул (в React ≤ 17) или сборщику мусора (React 18+)

> [!info] Почему делегирование, а не прямые listeners 
> Один обработчик на корне вместо тысяч индивидуальных — существенная экономия памяти и издержек на подписку/отписку при монтировании/размонтировании компонентов. Это же архитектурное решение упрощает работу с динамически добавляемыми элементами.

## ⏳ Событийный пулинг (актуально для React ≤ 17)

До React 17 объекты `SyntheticEvent` **переиспользовались** между разными событиями в целях оптимизации: после выполнения обработчика все поля объекта обнулялись, а сам объект возвращался в пул для повторного использования.

```jsx
function handleClick(e) {
  console.log(e.type); // 'click'

  setTimeout(() => {
    console.log(e.type); // null — объект уже очищен пулом
  }, 0);
}
```

**Решение** в старых версиях — `e.persist()`, который изымал событие из пула:

```jsx
function handleClick(e) {
  e.persist();
  setTimeout(() => {
    console.log(e.type); // 'click' — событие сохранено
  }, 0);
}
```

> [!warning] Начиная с React 17 
> Пулинг событий **убран**. `SyntheticEvent` больше не переиспользуется, `e.persist()` остался в API как no-op (для обратной совместимости) и официально считается deprecated. Это частый вопрос на собеседовании: важно уточнять, о какой версии React идёт речь.

## 🔬 Ключевые отличия от нативного события

|Характеристика|Нативное событие|SyntheticEvent|
|---|---|---|
|Кроссбраузерность|нет, отличается|да, унифицирован|
|Механизм подписки|напрямую на элемент|делегирование на корень (React 17+)|
|Доступ к нативному объекту|—|через `e.nativeEvent`|
|Пулинг (React ≤17)|нет|да (обнуление после обработчика)|

Доступ к исходному нативному событию всегда возможен через свойство `nativeEvent`:

```jsx
function handleClick(e) {
  console.log(e.nativeEvent); // исходный, необёрнутый Event
}
```

## 🎯 Порядок выполнения относительно нативных обработчиков

Важный нюанс для собеседования: если на странице одновременно есть обработчик, добавленный через `addEventListener` напрямую на DOM-элемент, и React-обработчик (`onClick`), **нативный обработчик выполнится раньше**, так как React перехватывает событие уже на этапе его всплытия к корню контейнера.

## ⚠️ Частые вопросы на собеседовании

> [!example] "Почему в React используется `onClick`, а не `onclick`?" 
> Именование в camelCase — соглашение JSX для согласованности с остальным JS-кодом и явного отличия синтетических обработчиков от нативных HTML-атрибутов (`onclick` в чистом HTML — это строка с кодом, а не функция).

> [!example] "Что будет, если вызвать `e.stopPropagation()` в обработчике React-компонента — остановится ли всплытие и на уровне нативных listeners?" 
> С точки зрения делегирования: `stopPropagation()` на SyntheticEvent останавливает распространение внутри системы событий React (между React-компонентами), но не обязательно останавливает всплытие на уровне реального DOM для нативных обработчиков, подписанных вне React. Это тонкость, о которой стоит явно упомянуть, демонстрируя понимание архитектуры.
