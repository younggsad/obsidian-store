## 💡 Определение

**Custom Hook** — это обычная JavaScript-функция, название которой начинается с префикса `use`, и которая вызывает внутри себя один или несколько встроенных хуков React (или других custom-хуков) для инкапсуляции и переиспользования **stateful-логики** между разными компонентами.

Ключевое отличие от обычной вспомогательной функции: custom hook может использовать `useState`, `useEffect`, `useContext` и т.д. — то есть подключаться к внутренним механизмам React (state, lifecycle, context), тогда как обычная функция этого делать не может.

> [!info] Формулировка для собеседования 
> "Custom Hook — это механизм повторного использования _логики_, работающей со state и side-эффектами, в отличие от HOC и render props, которые решают ту же задачу через повторное использование _компонентов_. Custom hook не создаёт новый экземпляр state — при каждом вызове хука в новом компоненте создаётся полностью независимый, изолированный state."

## 🏗️ Пример

```jsx
function useCounter(initialValue = 0) {
  const [count, setCount] = useState(initialValue);

  const increment = useCallback(() => setCount(c => c + 1), []);
  const decrement = useCallback(() => setCount(c => c - 1), []);
  const reset = useCallback(() => setCount(initialValue), [initialValue]);

  return { count, increment, decrement, reset };
}

function Counter() {
  const { count, increment, decrement, reset } = useCounter(10);

  return (
    <div>
      <button onClick={decrement}>-</button>
      <span>{count}</span>
      <button onClick={increment}>+</button>
      <button onClick={reset}>Сброс</button>
    </div>
  );
}
```

## 📏 Правила хуков (Rules of Hooks) и почему они обязательны

Custom hooks подчиняются тем же правилам, что и встроенные хуки — это отдельный частый вопрос на собеседовании:

1. **Хуки вызываются только на верхнем уровне** — не внутри условий, циклов, вложенных функций
2. **Хуки вызываются только из React-функций** — из функциональных компонентов или из других custom hooks (не из обычных JS-функций)

> [!info] Почему это не стилистическое соглашение, а техническое требование 
> React связывает состояние, создаваемое хуками, не с именем переменной, а с **порядковым номером вызова** хука за один рендер (это реализовано через связный список ячеек состояния — fiber hooks list). Если вызов хука пропускается в одном рендере из-за условия, порядок вызовов сдвигается, и React сопоставит state неправильной ячейке — начиная со следующего хука после пропущенного, все значения "съедут". Правило "только на верхнем уровне" гарантирует, что при каждом рендере хуки вызываются в строго одинаковом порядке.

```jsx
// Некорректно — нарушение правила хуков
function Component({ condition }) {
  if (condition) {
    const [state, setState] = useState(0); // условный вызов хука
  }
  // ...
}
```

## 🔬 Изоляция состояния между вызовами

Принципиальный момент: каждый вызов custom hook в разных компонентах создаёт **независимый** экземпляр состояния — хук не является синглтоном и не разделяет данные между компонентами автоматически (в отличие, например, от глобального стора).

```jsx
function ComponentA() {
  const { count } = useCounter(); // собственный, изолированный state
}

function ComponentB() {
  const { count } = useCounter(); // отдельный, независимый state
}
```

Если необходимо **разделяемое** состояние между компонентами — custom hook не решает эту задачу сам по себе, требуется дополнительный механизм: Context API, внешний стор (Zustand, Redux) или паттерн "Lifting State Up" (см. [[Context]]).

## 🎯 Типичные сценарии применения

- **Работа с внешними API / данными**: `useFetch`, `useQuery`
- **Работа с браузерными API**: `useLocalStorage`, `useMediaQuery`, `useGeolocation`
- **UI-логика без визуального представления**: `useToggle`, `useDebounce`, `useOnClickOutside`
- **Подписки на внешние источники данных**: `useWindowSize`, `useOnlineStatus`

```jsx
function useDebounce(value, delay) {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebouncedValue(value), delay);
    return () => clearTimeout(timer); // очистка предыдущего таймера
  }, [value, delay]);

  return debouncedValue;
}
```

## 🆚 Custom Hooks vs альтернативные паттерны переиспользования логики

|Критерий|Custom Hooks|HOC|Render Props|
|---|---|---|---|
|Что переиспользуется|логика (state, эффекты)|компонент-обёртка|компонент через функцию-пропс|
|Добавляет обёртку в дерево компонентов|нет|да (лишний уровень вложенности)|да (через children-функцию)|
|"Wrapper Hell" при композиции|не возникает|частая проблема при многих HOC|частая проблема при вложенности|
|Читаемость композиции нескольких источников логики|высокая (явные вызовы хуков)|низкая (неявное происхождение пропсов)|средняя|

> [!info] Историческая справка 
> Custom Hooks были введены в React 16.8 (2019) как решение проблем, свойственных HOC и Render Props — в первую очередь избыточной вложенности компонентов ("wrapper hell") и неявного источника пропсов, затрудняющего отслеживание того, откуда конкретный проп пришёл в компонент.

## ⚠️ Частые ошибки

> [!danger] Нарушение изоляции — ожидание общего состояния 
> Начинающие разработчики иногда ошибочно полагают, что два вызова одного custom hook в разных компонентах будут делить один и тот же state — это не так, каждый вызов полностью независим.

> [!warning] Хук без реального использования механизмов React 
> Если функция не вызывает внутри себя ни одного встроенного хука, называть её с префиксом `use` избыточно и вводит в заблуждение относительно её природы — это признак того, что абстракцию стоит оформить как обычную utility-функцию, а не как хук.

## ⚠️ Частые вопросы на собеседовании

> [!example] "Чем custom hook отличается от обычной вспомогательной функции?" 
> Custom hook вызывает внутри себя другие хуки React и, соответственно, подключается к внутреннему состоянию и жизненному циклу конкретного компонента, в котором он используется. Обычная функция таким доступом не обладает и не подчиняется Rules of Hooks.

> [!example] "Будет ли общим state, если два разных компонента используют один и тот же custom hook?" 
> Нет. Каждый вызов хука создаёт собственную, независимую ячейку состояния, привязанную к конкретному экземпляру компонента, вызвавшего хук. Для разделяемого состояния между компонентами нужен отдельный механизм — Context, внешний стор или поднятие состояния (lifting state up).

> [!example] "Почему хуки нельзя вызывать внутри условий?" 
> React сопоставляет состояние хуков не по имени, а по порядковому номеру вызова за рендер. Условный вызов хука меняет этот порядок между рендерами, что приводит к рассинхронизации state с ячейками — начиная с хука после условного, все последующие значения будут ошибочно смещены.
