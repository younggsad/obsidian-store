# ЧАСТЬ 7. REACT 18

## 7.1 Concurrent Rendering — центральная идея релиза

>React 18 ввёл **конкурентный рендеринг** — возможность React готовить несколько версий UI одновременно "в фоне", прерывать менее срочную работу ради более срочной, и не блокировать основной поток надолго. Это не отдельная "фича", которую включают явно — это внутренняя возможность, которую **задействуют** конкретные новые API (`useTransition`, `useDeferredValue`, Suspense-улучшения).

## 7.2 Новый Root API

```jsx
// React 17 и раньше
import ReactDOM from 'react-dom';
ReactDOM.render(<App />, document.getElementById('root'));

// React 18
import { createRoot } from 'react-dom/client';
const root = createRoot(document.getElementById('root'));
root.render(<App />);
```

Именно `createRoot` **включает** конкурентные возможности — приложения, всё ещё использующие старый `ReactDOM.render`, продолжают работать в прежнем, синхронном режиме без доступа к новым фичам.

## 7.3 Automatic Batching (автоматическая пакетная обработка обновлений)

```jsx
function handleClick() {
  setCount(c => c + 1);
  setFlag(f => !f);
  // React 17: внутри обработчиков событий React batch'ил их в ОДИН перерендер
  // React 17: внутри setTimeout/промисов/нативных event listener'ов — КАЖДЫЙ setState вызывал ОТДЕЛЬНЫЙ перерендер
  // React 18: batching происходит ВЕЗДЕ автоматически — в setTimeout, промисах, любых колбэках
}

setTimeout(() => {
  setCount(c => c + 1);
  setFlag(f => !f);
  // React 18: ОДИН перерендер вместо двух, даже внутри setTimeout
}, 1000);
```

До React 18 batching (объединение нескольких `setState` в один перерендер) работал только внутри React-обработчиков событий; React 18 расширил это на **любой** асинхронный код — существенное автоматическое улучшение производительности без изменений в коде приложения.

## 7.4 Улучшения Suspense — теперь официально для загрузки данных, не только `lazy()`

```jsx
<Suspense fallback={<Spinner />}>
  <ProfileDetails />   {/* компонент, который может "приостановиться" в ожидании данных */}
</Suspense>
```

React 18 расширил и стабилизировал возможности `Suspense` для реальных сценариев загрузки данных (в связке с фреймворками типа Next.js или Relay) — компонент может "выбросить" промис во время рендера, и React покажет `fallback`, пока промис не разрешится, без ручного управления состоянием `loading`.

## 7.6 Strict Mode — двойной вызов эффектов в development

В React 18 `<StrictMode>` начал **намеренно вызывать дважды** монтирование/размонтирование компонентов и `useEffect` в режиме разработки (только в dev, не в production-сборке) — чтобы разработчики раньше замечали код, не устойчивый к повторному монтированию (например, забытую функцию очистки эффекта, или побочные эффекты, которые не должны выполняться дважды).
