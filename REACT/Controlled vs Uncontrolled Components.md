## 💡 Суть

Речь про то, **кто хранит "источник правды"** (source of truth) для значения поля формы — React (через state) или сам DOM (браузер).

- **Controlled** — значение поля полностью управляется React-состоянием. Инпут отображает то, что лежит в `state`, и меняется только через `setState`.
- **Uncontrolled** — значение хранит сам DOM-элемент. React получает доступ к значению по требованию — обычно через `ref`.

> [!info] Аналогия 
> Controlled — React диктует, что показывать в поле, как режиссёр со сценарием. 
> Uncontrolled — поле живёт своей жизнью, React лишь иногда подглядывает в него через `ref`.

## 🎛️ Controlled Component

```jsx
function ControlledInput() {
  const [value, setValue] = useState('');

  return (
    <input
      value={value}
      onChange={(e) => setValue(e.target.value)}
    />
  );
}
```

Каждое нажатие клавиши → `onChange` → `setValue` → ре-рендер → инпут отображает новое значение из state.

### ✅ Плюсы

- Значение всегда доступно в state — легко валидировать "на лету", форматировать ввод, блокировать невалидные символы
- Легко синхронизировать несколько полей друг с другом
- Предсказуемое поведение, проще тестировать

### ⚠️ Минусы

- Ре-рендер при каждом нажатии клавиши (обычно не проблема, но критично для очень больших форм/списков)
- Больше кода на каждое поле

## 🎚️ Uncontrolled Component

```jsx
function UncontrolledInput() {
  const inputRef = useRef(null);

  const handleSubmit = () => {
    console.log(inputRef.current.value);
  };

  return (
    <>
      <input ref={inputRef} defaultValue="" />
      <button onClick={handleSubmit}>Отправить</button>
    </>
  );
}
```

Значение живёт в DOM. React не участвует, пока не понадобится прочитать его через `ref` (см. [[Refs]]).

> [!tip] defaultValue, а не value 
> Для uncontrolled-полей используется `defaultValue` / `defaultChecked` — это задаёт **начальное** значение, но дальше DOM управляет им сам. Если указать `value` без `onChange` — React выдаст warning и превратит поле в read-only.

### ✅ Плюсы

- Меньше ре-рендеров — производительнее для больших/простых форм
- Меньше кода для простых случаев (например, интеграция со сторонними non-React библиотеками)
- Хорошо подходит, когда значение нужно только в момент submit

### ⚠️ Минусы

- Сложнее валидировать в реальном времени
- Сложнее синхронизировать значения между полями
- Меньше контроля — сложнее программно менять значение поля

## 🆚 Сравнение

|Критерий|Controlled|Uncontrolled|
|---|---|---|
|Источник правды|React state|DOM|
|Доступ к значению|сразу, в любой момент|по требованию через ref|
|Ре-рендер при вводе|да|нет|
|Валидация в реальном времени|легко|сложнее|
|Начальное значение|`value`|`defaultValue`|
|Программное изменение|просто (`setState`)|сложнее (`ref.current.value = ...`)|

## ⚠️ Частые ошибки

> [!danger] Смешивание controlled и uncontrolled
> 
> 
> ```jsx
> // Проблема: value то undefined, то строка
> <input value={user?.name} onChange={handleChange} />
> ```
> 
> Если `user` изначально `undefined`, `value` будет `undefined` — поле становится uncontrolled. Когда `user` подгрузится, `value` станет строкой — поле "переключится" на controlled. React выдаст warning: _"A component is changing an uncontrolled input to be controlled"_.
> 
> **Решение:** всегда задавать явное значение по умолчанию: `value={user?.name ?? ''}`.

## 🧩 Практическое правило выбора

> [!tip] Когда что использовать
> 
> - **Controlled** — по умолчанию для большинства форм, особенно если нужна валидация, форматирование, зависимые поля
> - **Uncontrolled** — простые формы (например, одна кнопка "отправить"), интеграция с не-React кодом, файловые инпуты (`<input type="file">` — почти всегда uncontrolled, так как значение нельзя установить программно из соображений безопасности)
