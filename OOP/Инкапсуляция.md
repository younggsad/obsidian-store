# ЧАСТЬ 1. ИНКАПСУЛЯЦИЯ

## 1.1 Общее определение

>**Инкапсуляция** — принцип объединения данных (свойств) и методов работы с ними в единую сущность (объект/класс), с ограничением прямого доступа к части этих данных извне. Цель: скрыть внутреннюю "кухню" реализации и предоставить наружу только контролируемый интерфейс — набор методов, через которые можно безопасно взаимодействовать с объектом.

Практический смысл:

- Защита данных от случайного или некорректного изменения извне
- Возможность менять внутреннюю реализацию, не ломая код, который использует объект (пока публичный интерфейс остаётся прежним)
- Валидация данных при изменении (через методы, а не прямое присваивание)

**Важная особенность JS:** в отличие от классических ООП-языков (Java, C#), где `private`/`protected`/`public` были встроены изначально, в JavaScript истинная приватность появилась относительно недавно (приватные поля классов, 2022). До этого использовались соглашения и обходные приёмы. На собеседовании часто просят перечислить **все** подходы — от старых до современных.

## 1.2 Способ 1 — Соглашение об именовании (нижнее подчёркивание)

```javascript
function User(name) {
  this._name = name; // подчёркивание — сигнал "не трогай напрямую"
}

User.prototype.getName = function() {
  return this._name;
};

const user = new User("Аня");
console.log(user.getName()); // "Аня"
console.log(user._name);     // "Аня" — но обращение НАПРЯМУЮ технически работает!
user._name = "Максим";        // никто не мешает изменить извне
```

**Особенности:**

- Это **не настоящая приватность** — просто договорённость между разработчиками: "если видишь `_` перед именем — не трогай это напрямую".
- Синтаксически ничто не мешает получить доступ или изменить такое свойство извне.
- Плюс: простота, работает в любой версии JS, знаком всем разработчикам.
- Минус: не даёт реальной защиты, полагается только на дисциплину команды.

## 1.3 Способ 2 — Замыкания (closures)

Самый надёжный способ приватности до появления `#`-полей — переменные внутри функции-конструктора или фабричной функции, не привязанные к `this`, а значит недоступные снаружи вообще никак.

```javascript
function createUser(name) {
  let _name = name; // "приватная" переменная — существует только в замыкании

  return {
    getName() {
      return _name;
    },
    setName(newName) {
      if (typeof newName === "string" && newName.length > 0) {
        _name = newName;
      } else {
        console.log("Некорректное имя");
      }
    }
  };
}

const user = createUser("Аня");
console.log(user.getName()); // "Аня"
console.log(user._name);      // undefined — доступа нет вообще никакого
user.setName("Максим");
console.log(user.getName()); // "Максим"
```

**Особенности:**

- Настоящая приватность — переменную физически невозможно достать снаружи, не через сам объект.
- Каждый вызов `createUser()` создаёт свою собственную, независимую копию `_name` (как разбиралось в теме замыканий).
- Минус: методы (`getName`, `setName`) создаются заново при **каждом** вызове `createUser()` — если создать тысячи объектов, это менее эффективно по памяти, чем методы на прототипе (которые создаются один раз и используются всеми экземплярами).
- Часто применяется в **модульном паттерне (Module Pattern)** и **IIFE** для создания изолированного пространства данных.

### Модульный паттерн (комбинация замыкания + IIFE)

```javascript
const BankAccount = (function() {
  let balance = 0; // приватная переменная, общая для всех методов модуля

  return {
    deposit(amount) {
      balance += amount;
      return balance;
    },
    getBalance() {
      return balance;
    }
  };
})();

BankAccount.deposit(100);
console.log(BankAccount.getBalance()); // 100
console.log(BankAccount.balance);       // undefined
```

## 1.4 Способ 3 — WeakMap

Продвинутый приём: хранить приватные данные во внешней структуре `WeakMap`, где ключом выступает сам экземпляр объекта, а значением — его приватные данные.

```javascript
const _privateData = new WeakMap();

class User {
  constructor(name) {
    _privateData.set(this, { name });
  }

  getName() {
    return _privateData.get(this).name;
  }

  setName(newName) {
    _privateData.get(this).name = newName;
  }
}

const user = new User("Аня");
console.log(user.getName()); // "Аня"
console.log(user.name);      // undefined — свойства нет на самом объекте
```

**Особенности:**

- `WeakMap` хранит связь "объект → приватные данные" вне самого объекта, поэтому обычный перебор свойств (`for...in`, `Object.keys()`) их не увидит.
- `Weak` в названии означает: если сам объект-ключ (`user`) будет удалён (нет других ссылок на него), сборщик мусора автоматически удалит и связанные с ним данные в `WeakMap` — не будет утечек памяти.
- Методы при этом можно определять на прототипе класса (эффективно по памяти), а не заново на каждом экземпляре, как при чистых замыканиях.
- Минус: более сложный, "тяжёлый" синтаксис по сравнению с современными приватными полями.

## 1.5 Способ 4 — Symbol в качестве ключа

```javascript
const _name = Symbol("name");

class User {
  constructor(name) {
    this[_name] = name;
  }
  getName() {
    return this[_name];
  }
}

const user = new User("Аня");
console.log(user.getName()); // "Аня"
console.log(user[_name]);    // "Аня" — доступно, ЕСЛИ есть ссылка на сам Symbol
console.log(Object.keys(user)); // [] — не появляется при обычном переборе
```

**Особенности:**

- `Symbol` — уникальный, непересекающийся идентификатор; свойство с таким ключом не попадает в обычный перебор (`for...in`, `Object.keys()`, `JSON.stringify()`).
- Это **не настоящая приватность** — если у кого-то есть ссылка на сам `Symbol`, доступ к свойству получить можно (через `Object.getOwnPropertySymbols()` его в принципе можно найти).
- На практике используется реже, чем другие способы — больше для "скрытия от посторонних глаз" (например, от библиотек), чем для настоящей защиты.

## 1.6 Способ 5 — Приватные поля классов (`#`) — современный стандарт (ES2022)

```javascript
class User {
  #name; // объявление приватного поля

  constructor(name) {
    this.#name = name;
  }

  getName() {
    return this.#name;
  }

  setName(newName) {
    if (typeof newName === "string" && newName.length > 0) {
      this.#name = newName;
    }
  }

  #validate(value) { // приватный МЕТОД — тоже возможно
    return typeof value === "string";
  }
}

const user = new User("Аня");
console.log(user.getName()); // "Аня"
console.log(user.#name);      // ❌ SyntaxError — обращение к # снаружи класса запрещено на уровне синтаксиса!
```

**Особенности:**

- Это **настоящая, встроенная в язык приватность** — единственный способ, который защищён на уровне синтаксиса JS, а не соглашением или обходным путём.
- Приватные поля объявляются с префиксом `#`, доступны **только внутри тела класса** — обращение снаружи вызывает `SyntaxError` ещё на этапе разбора кода (не просто `undefined`, как с `_`).
- Работают и приватные поля (`#name`), и приватные методы (`#validate()`).
- Есть приватные **статические** поля/методы: `static #count = 0;`.
- Проверка существования приватного поля: `#name in obj` (специальный синтаксис, появился позже).
- Минус: относительно новая возможность — в очень старых окружениях может не поддерживаться (хотя сейчас поддержка практически повсеместная).

## 1.7 Геттеры и сеттеры (`get`/`set`) — контролируемый доступ

Отдельная, дополняющая техника — не столько про "скрытие", сколько про **контроль** доступа к свойствам через удобный синтаксис (выглядит как обычное свойство, а на деле вызывает функцию).

```javascript
class User {
  #name;

  constructor(name) {
    this.#name = name;
  }

  get name() {          // геттер — вызывается при user.name
    return this.#name;
  }

  set name(value) {      // сеттер — вызывается при user.name = "..."
    if (typeof value !== "string" || value.length === 0) {
      throw new Error("Некорректное имя");
    }
    this.#name = value;
  }
}

const user = new User("Аня");
console.log(user.name); // "Аня" — выглядит как обычное свойство, но вызывает get name()
user.name = "Максим";    // выглядит как присваивание, но вызывает set name()
user.name = "";          // ❌ Error: Некорректное имя
```

**Особенности:**

- Синтаксически обращение выглядит как к простому свойству (`user.name`), но на деле выполняется функция — можно добавить валидацию, логирование, вычисление "на лету".
- Часто комбинируется с приватными полями (`#`) — снаружи доступ идёт только через геттер/сеттер, которые контролируют, что именно происходит с реальными данными.
- Работают и в обычных объектах (не только в классах):

```javascript
const obj = {
  _value: 10,
  get value() { return this._value; },
  set value(v) { this._value = v * 2; }
};
```

## 1.8 Сравнительная таблица способов инкапсуляции

| Способ          | Настоящая приватность?               | Где появился   | Особенность                                                    |
| --------------- | ------------------------------------ | -------------- | -------------------------------------------------------------- |
| `_underscore`   | ❌ Нет                                | всегда был     | просто соглашение                                              |
| Замыкания       | ✅ Да                                 | всегда был     | методы дублируются на каждом экземпляре                        |
| `WeakMap`       | ✅ Да (почти)                         | ES6            | эффективна по памяти, сложный синтаксис                        |
| `Symbol`        | ⚠️ Частично                          | ES6            | скрыт от перебора, но не от прямого доступа при наличии ссылки |
| `#privateField` | ✅ Да, на уровне языка                | ES2022         | стандартный современный способ                                 |
| `get`/`set`     | — (это про контроль, не про скрытие) | ES5/классы ES6 | часто комбинируется с `#`                                      |

**Что важно унести для собеседования:** современный стандартный ответ — **приватные поля класса (`#`)**, но полезно знать историю и уметь объяснить, зачем нужны были более старые обходные приёмы (замыкания, WeakMap, `_underscore`) — это показывает глубину понимания темы.
