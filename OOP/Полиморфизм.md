# ЧАСТЬ 3. ПОЛИМОРФИЗМ

## 3.1 Общее определение

>**Полиморфизм** ("много форм") — способность объектов разных классов отвечать на **одинаковый** вызов метода **по-разному**, каждый в соответствии со своей собственной реализацией. Позволяет писать код, который работает с разными типами объектов единообразно, не заботясь о конкретном классе каждого из них.

---

## 3.2 Полиморфизм через переопределение методов (method overriding)

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  makeSound() {
    console.log(`${this.name} издаёт какой-то звук`);
  }
}

class Dog extends Animal {
  makeSound() { // переопределение
    console.log(`${this.name} лает: Гав!`);
  }
}

class Cat extends Animal {
  makeSound() { // своё переопределение
    console.log(`${this.name} мяукает: Мяу!`);
  }
}

const animals = [new Dog("Рекс"), new Cat("Мурка"), new Animal("Неизвестное")];

animals.forEach((animal) => {
  animal.makeSound(); // одинаковый вызов, разное поведение для каждого класса
});
// Рекс лает: Гав!
// Мурка мяукает: Мяу!
// Неизвестное издаёт какой-то звук
```

**Суть:** вызывающий код (`animal.makeSound()`) **не знает и не должен знать**, какой конкретно класс у каждого элемента массива — JS сам находит подходящую реализацию метода благодаря цепочке прототипов (сначала ищется в собственном классе объекта, и если там переопределения нет — используется версия из родителя).

## 3.3 Полиморфизм без наследования — "утиная типизация" (duck typing)

В JS полиморфизм не обязательно требует общего родительского класса — достаточно, чтобы у разных объектов был метод с одинаковым именем ("если что-то крякает как утка — работаем с этим как с уткой").

```javascript
const square = {
  area() { return this.side ** 2; },
  side: 4
};

const circle = {
  area() { return Math.PI * this.radius ** 2; },
  radius: 3
};

const shapes = [square, circle];

shapes.forEach((shape) => {
  console.log(shape.area().toFixed(2)); // одинаковый вызов для разных, никак не связанных объектов
});
```

Это отличает JS от строго типизированных языков — полиморфизм здесь достигается за счёт гибкости объектов, а не обязательной формальной иерархии классов/интерфейсов.

## 3.4 Полиморфизм через параметры функций (условно)

В более широком смысле, функции, которые ведут себя по-разному в зависимости от типа переданного аргумента, тоже иногда относят к проявлениям полиморфизма (хотя строже это называют **перегрузкой**, которой в чистом виде в JS нет — нельзя объявить две функции с одинаковым именем, но разными параметрами, как в Java/C#). Эффект перегрузки эмулируют через проверку типов внутри одной функции:

```javascript
function process(value) {
  if (Array.isArray(value)) {
    console.log("Обработка массива:", value.length, "элементов");
  } else if (typeof value === "string") {
    console.log("Обработка строки:", value.toUpperCase());
  } else if (typeof value === "number") {
    console.log("Обработка числа:", value * 2);
  }
}
```
