# ЧАСТЬ 4. АБСТРАКЦИЯ

## 4.1 Общее определение

>**Абстракция** — принцип выделения только существенных характеристик объекта, важных в конкретном контексте, и сокрытия избыточной, ненужной "конечному пользователю" сложности реализации. Если инкапсуляция — про то, **как** спрятать данные, то абстракция — про то, **что именно** нужно показать наружу, а что оставить "деталями реализации", не важными для того, кто использует объект.

Практический пример из повседневной жизни: чтобы завести машину, нужно повернуть ключ (или нажать кнопку) — водителю не нужно знать, как устроен двигатель внутри. Интерфейс ("завести машину") абстрагирован от сложной внутренней реализации.

## 4.2 Абстракция через ограничение публичного интерфейса

```javascript
class CoffeeMachine {
  #waterAmount = 0;
  #temperature = 0;

  #heatWater() {          // приватный метод — деталь реализации
    this.#temperature = 100;
  }

  #pourWater(amount) {     // тоже приватный
    this.#waterAmount = amount;
  }

  makeCoffee(waterAmount) { // ЕДИНСТВЕННЫЙ публичный метод — простой интерфейс
    this.#pourWater(waterAmount);
    this.#heatWater();
    console.log("Кофе готов!");
  }
}

const machine = new CoffeeMachine();
machine.makeCoffee(200); // пользователю не нужно знать про нагрев/заливку воды по отдельности
```

Тут используется тот же механизм (`#` приватные поля/методы), что и в инкапсуляции — но смысловой акцент другой: инкапсуляция защищает данные от изменения, абстракция **упрощает** взаимодействие, скрывая ненужные детали за простым интерфейсом.

## 4.3 Абстрактные классы/методы (эмуляция — в JS нет встроенного `abstract`)

В отличие от языков вроде Java/C#, в JS нет ключевого слова `abstract`. Понятие "абстрактного класса" (который нельзя создать напрямую, только через наследников) эмулируется вручную:

```javascript
class Shape {
  constructor() {
    if (this.constructor === Shape) {
      throw new Error("Нельзя создать экземпляр абстрактного класса Shape напрямую");
    }
  }

  area() {
    throw new Error("Метод area() должен быть переопределён в дочернем классе");
  }
}

class Circle extends Shape {
  constructor(radius) {
    super();
    this.radius = radius;
  }
  area() {
    return Math.PI * this.radius ** 2;
  }
}

new Shape();          // ❌ Error: Нельзя создать экземпляр абстрактного класса
const c = new Circle(5);
console.log(c.area()); // 78.5...
```

**Идея:** `Shape` описывает **общий контракт** ("у любой фигуры должен быть метод `area()`"), но сам по себе не предназначен для использования — только как база для конкретных фигур. Если наследник не переопределит `area()`, при вызове получит явную ошибку, а не тихо неработающий код.

## 4.4 Абстракция через интерфейсы-соглашения (в языках без встроенных интерфейсов)

Так как в JS нет формальных `interface` (как в TypeScript или Java), абстракция часто достигается через **документированное соглашение**: "любой объект, который передаётся сюда, должен иметь такие-то методы" — это снова похоже на "утиную типизацию", но уже применительно к идее абстракции, а не полиморфизма.

```javascript
// Функция абстрагирована от конкретной реализации хранилища —
// ей важно только, что у переданного объекта ЕСТЬ методы get/set
function saveUserPreference(storage, key, value) {
  storage.set(key, value);
}

const localStorageAdapter = {
  set(key, value) { localStorage.setItem(key, value); },
  get(key) { return localStorage.getItem(key); }
};

const memoryStorageAdapter = {
  data: {},
  set(key, value) { this.data[key] = value; },
  get(key) { return this.data[key]; }
};

saveUserPreference(memoryStorageAdapter, "theme", "dark"); // работает с любым адаптером
```

Код, работающий с `storage`, не знает и не должен знать, что конкретно за ним стоит — `localStorage`, объект в памяти, или что-то ещё. Это и есть абстракция: важен только контракт (какие методы доступны), а не детали реализации.
