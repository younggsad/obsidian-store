# ЧАСТЬ 2. НАСЛЕДОВАНИЕ

## 2.1 Общее определение

>**Наследование** — механизм, позволяющий одному объекту/классу перенимать свойства и методы другого, чтобы не дублировать код и выстраивать иерархию "общее → частное" (например, `Animal` → `Dog`, `Cat`).

В JS наследование в своей основе построено на **прототипах** — уникальная особенность языка по сравнению с классическими ООП-языками, где используется "классическое" наследование через классы. Синтаксис `class`/`extends` в JS — это лишь удобная "обёртка" поверх прототипного механизма.

---

## 2.2 Прототипное наследование — основа основ

У каждого объекта в JS есть внутренняя скрытая ссылка на другой объект — его **прототип** (`[[Prototype]]`, доступен через `__proto__` или `Object.getPrototypeOf()`). Если свойство/метод не найден в самом объекте, JS ищет его в прототипе, и так далее по цепочке — **цепочка прототипов (prototype chain)**.

```javascript
const animal = {
  eats: true,
  walk() {
    console.log("Идёт");
  }
};

const rabbit = Object.create(animal); // rabbit получает animal как прототип
rabbit.jumps = true;

console.log(rabbit.eats);  // true — не своё, найдено в прототипе
console.log(rabbit.jumps); // true — своё собственное
rabbit.walk();              // "Идёт" — метод найден в прототипе
```

`Object.create(proto)` — создаёт новый объект с явно указанным прототипом. Это самый "низкоуровневый" способ настроить наследование.

## 2.3 Функции-конструкторы + `prototype` (до появления `class`)

```javascript
function Animal(name) {
  this.name = name;
}

Animal.prototype.walk = function() {
  console.log(`${this.name} идёт`);
};

function Dog(name, breed) {
  Animal.call(this, name); // вызываем "родительский конструктор" вручную
  this.breed = breed;
}

Dog.prototype = Object.create(Animal.prototype); // настраиваем цепочку прототипов
Dog.prototype.constructor = Dog; // восстанавливаем ссылку на конструктор

Dog.prototype.bark = function() {
  console.log(`${this.name} лает`);
};

const rex = new Dog("Рекс", "Овчарка");
rex.walk(); // "Рекс идёт" — унаследовано от Animal
rex.bark(); // "Рекс лает" — собственный метод Dog
```

**Что здесь происходит:**

- Каждая функция автоматически имеет свойство `.prototype` — объект, который станет прототипом для всех экземпляров, созданных через `new`.
- `Animal.call(this, name)` — вызов родительского "конструктора" с явно переданным `this` (это `call`/`apply`, которые разбирали ранее).
- `Object.create(Animal.prototype)` — создаёт новый пустой объект с прототипом `Animal.prototype`, и именно он становится прототипом `Dog` — так выстраивается цепочка: `rex → Dog.prototype → Animal.prototype → Object.prototype → null`.

Это исторический, "низкоуровневый" способ — сегодня почти всегда используют синтаксис `class`, но он работает **поверх точно такого же** механизма.

## 2.4 Наследование через `class`/`extends` — современный синтаксис

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }

  walk() {
    console.log(`${this.name} идёт`);
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name); // вызов конструктора родителя — ОБЯЗАТЕЛЕН до обращения к this
    this.breed = breed;
  }

  bark() {
    console.log(`${this.name} лает`);
  }

  walk() { // переопределение (override) родительского метода
    super.walk(); // можно вызвать оригинальную реализацию родителя
    console.log(`${this.name} виляет хвостом при ходьбе`);
  }
}

const rex = new Dog("Рекс", "Овчарка");
rex.walk();
// Рекс идёт
// Рекс виляет хвостом при ходьбе
rex.bark(); // Рекс лает
```

**Особенности:**

- `extends` — устанавливает цепочку прототипов автоматически (то, что раньше делалось вручную через `Object.create`).
- `super(...)` в конструкторе — вызывает конструктор родительского класса; **обязателен**, если в дочернем классе определён свой `constructor`, и должен быть вызван **до** первого обращения к `this`.
- `super.метод()` внутри обычного метода — вызывает реализацию метода из родительского класса (полезно, когда нужно и переопределить, и всё равно выполнить оригинальную логику).
- Классы в JS — это по сути "синтаксический сахар": `class` создаёт функцию-конструктор и настраивает `prototype` автоматически, но под капотом всё та же прототипная модель.
- Классы **не поднимаются (no hoisting)** так, как функции-объявления — нельзя использовать класс до его объявления в коде (попадают в temporal dead zone, как `let`/`const`).

## 2.5 Множественное наследование через миксины (mixins)

### Проблема классического наследования (почему цепочка "ломается")

Классическое наследование через `extends` в JS — **линейное**: у класса может быть только **один** родитель (single inheritance). Проблема возникает, когда объекту нужно **несколько независимых наборов поведения**, которые не связаны иерархически.

**Пример проблемы:**

```js
class Animal {
  eat() { console.log('eating'); }
}

class Flyable {
  fly() { console.log('flying'); }
}

class Swimmable {
  swim() { console.log('swimming'); }
}

// Утка должна и летать, и плавать, и есть — но extends позволяет только ОДИН класс
class Duck extends Animal {
  // Как добавить fly() И swim() одновременно?
  // extends Flyable, Swimmable — так писать НЕЛЬЗЯ, JS это не поддерживает
}
```

Если попытаться решить это через глубокую иерархию (`Animal → FlyingAnimal → FlyingSwimmingAnimal`), очень быстро возникает так называемая **проблема ромба (diamond problem)**: если `FlyingAnimal` и `SwimmingAnimal` оба наследуются от `Animal`, а `Duck` должен унаследоваться от обоих — непонятно, какую версию общих методов/свойств использовать, и в каком порядке. JS **сознательно не поддерживает** множественное наследование через `extends` именно чтобы избежать этой неоднозначности.

Более того, глубокие цепочки наследования (`A extends B extends C extends D`) сами по себе — плохая практика: они создают жёсткую, хрупкую связь между классами (изменение в `D` может неожиданно сломать поведение в `A`), и это называется **fragile base class problem**.

### Решение — миксины (mixins)

>**Миксин** — это способ добавить объекту/классу набор методов **без использования наследования** — то есть "подмешать" (mix in) функциональность горизонтально, а не выстраивать вертикальную иерархию.

#### Способ 1: функция, которая расширяет класс (самый распространённый паттерн в JS)

Миксин — это **функция, принимающая класс и возвращающая новый класс**, расширенный дополнительными методами:

```js
const FlyableMixin = (Base) => class extends Base {
  fly() {
    console.log(`${this.name} is flying`);
  }
};

const SwimmableMixin = (Base) => class extends Base {
  swim() {
    console.log(`${this.name} is swimming`);
  }
};

class Animal {
  constructor(name) {
    this.name = name;
  }
  eat() {
    console.log(`${this.name} is eating`);
  }
}

// Композиция миксинов через последовательное применение
class Duck extends SwimmableMixin(FlyableMixin(Animal)) {}

const duck = new Duck('Duck');
duck.eat();  // "Duck is eating"
duck.fly();  // "Duck is flying"
duck.swim(); // "Duck is swimming"
```

**Как это работает:** каждый миксин — функция, которая берёт базовый класс (`Base`) и возвращает **новый анонимный класс**, наследующий от `Base` и добавляющий свои методы. Вызовы вкладываются друг в друга (`SwimmableMixin(FlyableMixin(Animal))`), создавая цепочку прототипов **динамически**, а не через жёстко прописанную статическую иерархию классов. По сути под капотом там всё ещё используется prototype chain — но она **собирается на лету**, комбинируя нужные куски поведения, а не вынуждает создавать реальные промежуточные классы типа `FlyingAnimal`, `SwimmingAnimal`, которые могут быть не нужны сами по себе.

#### Способ 2: `Object.assign` — простое копирование методов в прототип

Более простой, "плоский" способ без создания промежуточных классов:

```js
const flyable = {
  fly() {
    console.log(`${this.name} is flying`);
  }
};

const swimmable = {
  swim() {
    console.log(`${this.name} is swimming`);
  }
};

class Duck {
  constructor(name) {
    this.name = name;
  }
}

Object.assign(Duck.prototype, flyable, swimmable);

const duck = new Duck('Duck');
duck.fly();  // "Duck is flying"
duck.swim(); // "Duck is swimming"
```

Здесь миксины — просто **объекты с методами**, и `Object.assign` копирует эти методы прямо в прототип класса. Никакой цепочки наследования вообще не создаётся — методы просто оказываются "рядом" в одном прототипе.

### Ключевое отличие от наследования

**Практическое правило**, которое стоит запомнить и озвучить на собесе: наследование стоит использовать, когда есть настоящая иерархическая связь "является" (`Dog extends Animal` — собака **является** животным). Если же нужно просто "добавить возможность" объекту, которая не связана иерархически с тем, чем этот объект **является** (может летать, может логировать, может сериализоваться в JSON) — это сигнал использовать композицию через миксины, а не пытаться натянуть это на цепочку `extends`.

### Как это связано с React (если вопрос всплывёт в контексте фреймворка)

Кстати, именно с этой проблемой столкнулись в старых версиях React — там миксины использовались, но были признаны **антипаттерном** именно из-за неявных зависимостей и конфликтов имён методов между несколькими миксинами (непонятно, что откуда пришло, если смотреть на код компонента). Это одна из причин, почему React перешёл сначала на **Higher-Order Components (HOC)**, а затем на **Hooks** — оба этих подхода решают ту же задачу "переиспользуемой логики без глубокого наследования", но более явно и без скрытых конфликтов.

## 2.6 `instanceof` и проверка цепочки прототипов

```javascript
console.log(rex instanceof Dog);    // true
console.log(rex instanceof Animal); // true — Dog наследует от Animal
console.log(rex instanceof Object); // true — всё в JS в итоге наследует от Object
```

`instanceof` проверяет, встречается ли `Constructor.prototype` где-либо в цепочке прототипов объекта — то есть работает и для родительских классов, не только для непосредственного класса объекта.
