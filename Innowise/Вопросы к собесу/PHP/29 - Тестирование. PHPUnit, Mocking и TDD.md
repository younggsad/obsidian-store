# 29 — Тестирование. PHPUnit, Mocking и TDD

## 1. Теория

### Виды тестов
1. **Unit Tests (Модульные тесты)**: Проверка изобилованной логики отдельных классов/методов без обращения к БД и сети (с использованием заглушек/моков).
2. **Integration Tests (Интеграционные тесты)**: Проверка взаимодействия нескольких компонентов (например, работа репозитория с реальной тестовой базой данных).
3. **Functional / E2E Tests**: Проверка приложения целиком через симуляцию HTTP-запросов.

### PHPUnit и Mocking
- **PHPUnit**: Стандартный фреймворк тестирования в PHP.
- **Mocks & Stubs**: Объекты-заглушки для изоляции тестируемого кода от внешних зависимостей (через встроенные механизмы PHPUnit или библиотеку Mockery).

---

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

use PHPUnit\Framework\TestCase;

class CalculatorTest extends TestCase {
    public function testAdd(): void {
        $calc = new Calculator();
        $result = $calc->add(2, 3);
        
        $this->assertEquals(5, $result);
    }
}
```

## 3. Вопросы на собеседовании

1. **В чем разница между Stub (Стаб) и Mock (Мок)?**
   *Ответ*: `Stub` (заглушка) предоставляет заранее заготовленные ответы на вызовы методов во время теста (не проверяет поведение). `Mock` (мок) — это объект, у которого заранее заданы ожидания (assertions) относительно того, какие методы, с какими аргументами и сколько раз должны быть вызваны.
2. **Что такое TDD (Test-Driven Development)?**
   *Ответ*: Разработка через тестирование. Цикл Red-Green-Refactor: сначала пишется падающий тест на новую функциональность (`Red`), затем пишется минимальный код, чтобы тест прошел (`Green`), после чего код рефакторится (`Refactor`).
3. **Что такое покрытие кода тестами (Code Coverage) и гарантирует ли 100% покрытие отсутствие багов?**
   *Ответ*: Code Coverage показывает процент строк/ветвлений кода, выполненных во время прогона тестов. 100% покрытие не гарантирует отсутствие багов, так как оно проверяет факт выполнения кода тестами, но не проверяет корректность всех возможных бизнес-сценариев и граничных условий.
