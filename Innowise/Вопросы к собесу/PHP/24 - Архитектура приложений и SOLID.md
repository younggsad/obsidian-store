## 1. Фундаментальная теория и архитектура

### Принципы SOLID
- **S**: Single Responsibility.
- **O**: Open/Closed.
- **L**: Liskov Substitution.
- **I**: Interface Segregation.
- **D**: Dependency Inversion.

### Архитектура приложений
- Разделение на слои (Domain, Application, Infrastructure, Presentation) для обеспечения слабой связанности.

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

interface MailerInterface {
    public function send(string $to, string $subject): void;
}

class UserRegistrationService {
    public function __construct(private MailerInterface $mailer) {}

    public function register(string $email): void {
        // Бизнес логика
        $this->mailer->send($email, 'Welcome!');
    }
}
```

## 3. Детальные вопросы на техническом собеседовании

1. **Опишите принцип инверсии зависимостей (DIP) на примере.**
   *Ответ*: Модули верхнего уровня не должны зависеть от модулей нижнего уровня; оба должны зависеть от абстракций. В коде это выражается в передаче зависимостей через интерфейсы (`MailerInterface`), а не через жесткое создание экземпляров классов (`new Mailer()`).
2. **Что утверждает принцип подстановки Барбары Лисков (LSP)?**
   *Ответ*: Объекты в программе должны быть заменяемыми на экземпляры их подтипов без изменения правильности выполнения программы (потомок не должен сужать контракт или выбрасывать неожиданные исключения).
3. **В чем польза разделения приложения на слои в Clean Architecture?**
   *Ответ*: Независимость бизнес-логики от фреймворков, баз данных и внешних API, что упрощает модульное тестирование и поддержку кода.
4. **Какую проблему решает принцип разделения интерфейсов (ISP)?**
   *Ответ*: Предотвращает создание «толстых» универсальных интерфейсов, заставляя клиентов реализовывать только те методы, которые им реально необходимы.
