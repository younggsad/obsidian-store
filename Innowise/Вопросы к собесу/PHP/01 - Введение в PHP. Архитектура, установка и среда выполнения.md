## 1. Фундаментальная теория и архитектура

### Что такое PHP и его эволюция
**PHP** (Hypertext Preprocessor) — динамически типизированный язык программирования общего назначения с преобладающим применением в серверной веб-разработке. 
- Начиная с PHP 7.x и особенно в PHP 8.x, язык совершил колоссальный скачок в производительности и выразительности (JIT-компилятор, нативные типы, Union/Intersection types, атрибуты, enums).
- **Парадигма**: Мультипарадигмальный (процедурный, ООП, функциональный элементы).
- **Модель выполнения**: Shared-nothing архитектура (каждый HTTP-запрос инициализирует новое чистое окружение в памяти, выполняет скрипт и полностью очищает ресурсы по завершении).

### Жизненный цикл HTTP-запроса (FPM Model)
1. **Клиент** отправляет HTTP-запрос на сервер.
2. **Nginx** принимает запрос, определяет, является ли файл статическим (отдает сразу) или динамическим (`.php`).
3. **Nginx** передает запрос в **PHP-FPM** (FastCGI Process Manager) через TCP-сокет или Unix-сокет.
4. PHP-FPM передает запрос свободному рабочему процессу (worker).
5. **Zend Engine** компилирует (или берет из OPcache) байт-код и выполняет скрипт.
6. Результат возвращается через FastCGI в Nginx, который отправляет его клиенту.
7. Процесс PHP-FPM очищает состояние памяти и ожидает следующий запрос.

### Компоненты движка Zend Engine
- **Лексер (Scanner)**: Преобразует исходный текст PHP в последовательность токенов.
- **Парсер**: Строит из токенов абстрактное синтаксическое дерево (AST — Abstract Syntax Tree).
- **Компилятор**: Преобразует AST в промежуточный байт-код (Opcodes).
- **Zend Virtual Machine**: Интерпретатор, выполняющий скомпилированные опкоды.
- **JIT (Just-In-Time) компилятор** (появился в PHP 8.0): Компилирует горячие участки байт-кода напрямую в машинный код процессора, ускоряя вычислительные задачи.

## 2. Примеры кода и конфигурации

```php
<?php
declare(strict_types=1);

/**
 * Проверка расширенной информации о среде выполнения PHP
 */
function inspectEnvironment(): array {
    return [
        'version' => PHP_VERSION,
        'sapi' => PHP_SAPI,
        'os' => PHP_OS,
        'memory_limit' => ini_get('memory_limit'),
        'max_execution_time' => ini_get('max_execution_time'),
        'opcache_enabled' => function_exists('opcache_get_status') && (bool)opcache_get_status(false),
    ];
}

header('Content-Type: application/json; charset=utf-8');
echo json_encode(inspectEnvironment(), JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR);
```

## 3. Детальные вопросы на техническом собеседовании

1. **Опишите детальный пайплайн выполнения PHP-скрипта от исходного кода до ответа клиенту.**
   *Ответ*: Исходный код $\rightarrow$ Лексер (токены) $\rightarrow$ Парсер (AST) $\rightarrow$ Компилятор (Opcodes) $\rightarrow$ OPcache (кэширование опкодов) $\rightarrow$ Zend VM (исполнение байт-кода или JIT-компиляция в машинный код) $\rightarrow$ Выдача ответа клиенту.
2. **В чем суть архитектуры «shared-nothing» и какие у нее плюсы и минусы?**
   *Ответ*: Каждый запрос изолирован, что исключает утечки памяти между запросами и избавляет от необходимости вручную очищать глобальное состояние. Минус — накладные расходы на инициализацию приложения (бутстрап фреймворка, подключение к БД) на каждый запрос.
3. **Как работает JIT-компилятор в PHP 8 и для каких задач он эффективен?**
   *Ответ*: JIT компилирует горячие участки байт-кода в нативный машинный код «на лету». Он малоэффективен для типичных I/O-bound веб-приложений (где узкое место — запросы в БД и сеть), но дает ощутимый прирост в CPU-bound задачах (математические вычисления, обработка изображений, криптография).
4. **В чем разница между SAPI CLI и FPM?**
   *Ответ*: CLI предназначен для работы в терминале, не имеет веб-окружения, суперглобальные массивы запросов пусты. FPM управляет пулом долгоживущих процессов для обработки веб-трафика через FastCGI.
