## 1. Теория

### Что такое PHP

**PHP** (PHP: Hypertext Preprocessor) — это серверный интерпретируемый язык программирования общего назначения, который изначально создавался для разработки динамических веб-страниц, а сегодня широко применяется для построения бэкендов, REST API, CLI-утилит и микросервисов.

- **Типизация**: Динамическая, по умолчанию слабая (с возможностью включения строгой типизации через `declare(strict_types=1);`).
- **Парадигма**: Мультипарадигмальный (поддерживает процедурное, объектно-ориентированное и функциональное программирование).
- **Управление памятью**: Автоматическое с использованием подсчета ссылок (Reference Counting) и сборщика мусора (Garbage Collector) для циклических ссылок.
- **Жизненный цикл**: Shared-nothing архитектура (по умолчанию каждый HTTP-запрос инициализирует новое окружение, выполняет скрипт и уничтожает все состояние по завершении).

### Архитектура и выполнение кода

1. **Zend Engine**: Ядро PHP, отвечающее за разбор исходного кода (лексер, парсер в Abstract Syntax Tree) и компиляцию в байт-код (opcodes), который затем исполняется виртуальной машиной.
2. **OPcache**: Модуль кэширования опкодов в оперативной памяти. Избавляет от необходимости парсить и компилировать PHP-файлы на каждый запрос, многократно ускоряя приложение.
3. **SAPI (Server API)**: Интерфейс взаимодействия PHP с внешним окружением:
   - **CLI**: Интерпретатор командной строки для скриптов, миграций и тестов.
   - **FPM (FastCGI Process Manager)**: Менеджер процессов для работы с веб-серверами (Nginx, Apache).
   - **Embed**: Встраивание PHP в другие приложения на C/C++.
   - **Долгоживущие рантаймы (Worker mode)**: Swoole, RoadRunner, FrankenPHP (держат приложение в памяти между запросами).

## 2. Примеры кода

```php
<?php
// Объявление строгой типизации (рекомендуется в современном PHP)
declare(strict_types=1);

/**
 * Проверка версии PHP и вывод информации о среде
 */
function getEnvironmentInfo(): string {
    return sprintf(
        "PHP Version: %s\nSAPI: %s\nOS: %s",
        PHP_VERSION,
        PHP_SAPI,
        PHP_OS
    );
}

echo getEnvironmentInfo();
```

## 3. Вопросы на собеседовании

1. **Что такое Zend Engine и каков пайплайн выполнения PHP-кода?**
   *Ответ*: Zend Engine компилирует исходный PHP-код в байт-код (opcodes), который затем выполняет виртуальная машина. Пайплайн: Исходный код $\rightarrow$ Лексер (токены) $\rightarrow$ Парсер (AST) $\rightarrow$ Компилятор (Opcodes) $\rightarrow$ Zend VM (Исполнение).
2. **В чем суть архитектуры «shared-nothing» в PHP?**
   *Ответ*: Каждый входящий запрос запускает изолированный жизненный цикл: инициализация, выполнение скрипта, выдача ответа и полное уничтожение состояния памяти. Переменные не сохраняются между запросами (если не использовать кэш, БД или сессии).
3. **Для чего нужен OPcache?**
   *Ответ*: OPcache сохраняет скомпилированный байт-код в разделяемой памяти (shared memory), предотвращая повторный парсинг и компиляцию файлов PHP на каждый HTTP-запрос.
4. **В чем разница между CLI и FPM?**
   *Ответ*: CLI предназначен для запуска скриптов из консоли (без веб-окружения, суперглобальные массивы вроде `$_GET` пусты). FPM (FastCGI Process Manager) управляет пулом процессов для обработки веб-запросов от веб-серверов.
