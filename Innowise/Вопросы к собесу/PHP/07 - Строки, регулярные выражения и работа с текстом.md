## 1. Фундаментальная теория и архитектура

### Строки как массивы байт
- В PHP строки представляют собой массив байт (не символов Unicode). Максимальный размер строки ограничен 2GB (в 64-битных системах).
- **Кавычки**:
  - Одинарные (`''`): Литералы. Не парсят переменные и экранирование (кроме `\'` и `\\`). Работают быстрее.
  - Двойные (`""`): Поддерживают интерполяцию переменных и управляющие символы (`\n`, `\t`).
  - Heredoc (`<<<TXT`) и Nowdoc (`<<<'TXT'`): Удобны для многострочных блоков текста (Heredoc интерполирует, Nowdoc — нет).

### Мультибайтовые строки (MBString)
- Функции вроде `strlen()`, `substr()`, `strpos()` считают **байты**, а не символы. В UTF-8 кириллические символы занимают по 2 байта. Для корректной работы с текстом используются функции `mb_*()`.

### Регулярные выражения (PCRE)
- Движок PCRE (Perl Compatible Regular Expressions) используется для сложных проверок и парсинга через `preg_match()`, `preg_replace()`, `preg_split()`.

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

// Безопасное обрезание строки с учетом мультибайтовых символов
$text = "Привет, мир!";
$shortText = mb_substr($text, 0, 6, 'UTF-8'); // "Привет"

// Использование Heredoc для генерации HTML
$title = "Dashboard";
$html = <<<HTML
    <div class="panel">
        <h1>{$title}</h1>
    </div>
HTML;
```

## 3. Детальные вопросы на техническом собеседовании

1. **Почему использование `strlen()` для проверки длины UTF-8 строки является ошибкой?**
   *Ответ*: `strlen()` возвращает количество байт, а не символов. Символы юникода (например, кириллица или эмодзи) могут занимать от 2 до 4 байт. Для подсчета символов нужно использовать `mb_strlen()`.
2. **В чем разница между Heredoc и Nowdoc с точки зрения производительности и синтаксиса?**
   *Ответ*: Heredoc (`<<<TXT`) ведет себя как двойные кавычки (парсит переменные). Nowdoc (`<<<'TXT'`) ведет себя как одинарные кавычки (не парсит переменные и экранирование), что идеально подходит для вставки исходного кода или шаблонов без лишнего парсинга.
3. **Как оптимизировать производительность частых манипуляций со строками в циклах?**
   *Ответ*: Вместо конкатенации строк через `+=` на каждой итерации (что приводит к постоянному выделению новой памяти под строку), лучше собирать куски в массив, а затем объединить их один раз через `implode()`.
4. **Каковы особенности работы с модификаторами в PCRE регулярных выражениях (`u`, `i`)?**
   *Ответ*: Модификатор `u` (PCRE_UTF8) включает поддержку UTF-8, заставляя регулярное выражение корректно обрабатывать многобайтовые символы вместо побайтового сравнения.
