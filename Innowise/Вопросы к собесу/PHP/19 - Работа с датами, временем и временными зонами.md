# 19 — Работа с датами, временем и временными зонами

## 1. Теория

### Классы DateTime и DateTimeImmutable
- Исторически функции вроде `date()` и `time()` работали с глобальным состоянием временной зоны.
- В современном PHP рекомендуется использовать классы **`DateTime`** и **`DateTimeImmutable`**.
- **DateTimeImmutable**: Создает неизменяемые объекты дат. Любые операции (`modify()`, `add()`) возвращают **новый** объект, не изменяя оригинал (предотвращает баги с мутацией состояния).

### Временные зоны и интервалы
- Класс `DateTimeZone` управляет часовыми поясами.
- Класс `DateInterval` представляет временные интервалы (например, для добавления дней или часов).
- Класс `DatePeriod` позволяет генерировать последовательности дат.

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

// Использование DateTimeImmutable (рекомендация)
$now = new \DateTimeImmutable('now', new \DateTimeZone('Europe/Minsk'));
$future = $now->modify('+7 days');

echo $now->format('Y-m-d H:i:s');
echo "\n";
echo $future->format('Y-m-d H:i:s');

// Интервалы
$interval = new \DateInterval('P1M'); // Один месяц
$nextMonth = $now->add($interval);
```

## 3. Вопросы на собеседовании

1. **В чем разница между `DateTime` и `DateTimeImmutable`?**
   *Ответ*: `DateTime` мутабелен (изменяет внутреннее состояние объекта при вызове методов вроде `modify()`). `DateTimeImmutable` немутабелен: все операции возвращают новый экземпляр класса, что делает код более безопасным и предсказуемым.
2. **Как правильно хранить даты и время в базе данных?**
   *Ответ*: Рекомендуется хранить в формате UTC (метки времени `TIMESTAMP` или строки в формате ISO 8601 / DATETIME) без привязки к локальной временной зоне пользователя. Конвертацию в часовой пояс пользователя следует выполнять на уровне приложения при выводе.
3. **Как учесть переход на летнее/зимнее время при работе с интервалами дат?**
   *Ответ*: Использовать объекты `DateTimeImmutable` и методы добавления интервалов через `DateInterval`, которые автоматически учитывают смещения часовых поясов.
