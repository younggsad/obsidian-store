# 30 — PHP Internals. Zend Engine и устройство языка

## 1. Теория

### Внутреннее устройство Zend Engine
- **zval**: Структура данных, представляющая переменную в памяти (содержит тип, значение и служебные флаги).
- **OPcache**: Кэш опкодов.
- **AST (Abstract Syntax Tree)**: Абстрактное синтаксическое дерево, в которое парсер преобразует исходный код перед компиляцией в опкоды.
- **Зоны памяти**:
  - `emalloc` / `efree` — выделение памяти, управляемое Zend Memory Manager (ZMM) в рамках запроса.
  - `zend_string`, `zend_array` — внутренние оптимизированные структуры для строк и массивов.

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

// Получение информации о внутренних расширениях и загруженных опкодах (при наличии Xdebug)

    $status = opcache_get_status(false);
    echo "OPcache memory used: " . $status['memory_usage']['used_memory'] . " bytes\n";
}
```

## 3. Вопросы на собеседовании

1. **Как Zend Engine обрабатывает и выполняет PHP-скрипт?**
   *Ответ*: Исходный код $\rightarrow$ Лексер (разбиение на токены) $\rightarrow$ Парсер (построение AST) $\rightarrow$ Компилятор (генерация Opcodes) $\rightarrow$ Виртуальная машина Zend Engine (поочередное исполнение опкодов).
2. **Для чего нужен Zend Memory Manager (ZMM)?**
   *Ответ*: ZMM управляет выделением и освобождением памяти для скрипта в течение одного HTTP-запроса, предотвращая утечки памяти на уровне ОС и ускоряя аллокацию за счет предварительного буферизованного выделения блоков памяти.
3. **Что такое AST (Abstract Syntax Tree) в PHP?**
   *Ответ*: Древовидное представление синтаксической структуры исходного кода, введенное в PHP 7. Промежуточный этап между парсингом токенов и генерацией байт-кода.
