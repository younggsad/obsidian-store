## 1. Фундаментальная теория и архитектура

### Основные векторы атак
1. **SQL Injection**: Защита через Prepared Statements.
2. **XSS (Cross-Site Scripting)**: Защита через экранирование вывода (`htmlspecialchars()`).
3. **CSRF**: Защита через CSRF-токены.
4. **Хеширование паролей**: Использование `password_hash()` (Argon2 / Bcrypt) и `password_verify()`.

---

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

$hash = password_hash('my_secure_password', PASSWORD_ARGON2ID);
if (password_verify('my_secure_password', $hash)) {
    // Авторизация успешна
}
```

## 3. Детальные вопросы на техническом собеседовании

1. **Почему алгоритмы MD5 и SHA-1 небезопасны для хранения паролей?**
   *Ответ*: Они работают слишком быстро, что позволяет злоумышленникам подбирать пароли методом брутфорса на GPU. Современные алгоритмы (`password_hash` на базе Argon2/Bcrypt) намеренно замедлены и используют криптографическую соль.
2. **Как защитить веб-приложение от XSS-уязвимостей?**
   *Ответ*: Экранировать все данные, выводимые пользователю в браузер, с помощью `htmlspecialchars(..., ENT_QUOTES, 'UTF-8')`, а также использовать Content Security Policy (CSP) заголовок.
3. **Что такое CSRF и как от нее защититься?**
   *Ответ*: Межсайтовая подделка запросов. Защита реализуется с помощью уникальных одноразовых токенов в POST-формах и проверки заголовков/SameSite атрибута для кук.
4. **В чем опасность использования небезопасной десериализации (`unserialize`)?**
   *Ответ*: PHP Object Injection уязвимость, позволяющая выполнить удаленный код (RCE) через магические методы десериализуемых объектов.
