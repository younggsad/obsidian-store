# 23 — Безопасность PHP-приложений

## 1. Теория

### Основные уязвимости и защита
1. **SQL Injection (SQLi)**: Внедрение вредоносного SQL-кода. Защита: Prepared Statements (PDO).
2. **Cross-Site Scripting (XSS)**: Внедрение JavaScript в браузер пользователя. Защита: Экранирование выводов (`htmlspecialchars()`).
3. **Cross-Site Request Forgery (CSRF)**: Подделка межсайтовых запросов. Защита: CSRF-токены в формах и сессиях.
4. **Хеширование паролей**: Никогда не хранить пароли в открытом виде или через слабые хэши (`md5`, `sha1`). Использовать нативные функции `password_hash()` (на базе Bcrypt/Argon2) и `password_verify()`.
5. **Remote Code Execution (RCE)**: Выполнение произвольного кода через `eval()`, небезопасную десериализацию (`unserialize()`) или системные вызовы.

---

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

// Безопасное хеширование пароля
$password = 'SecretPassword123';
$hash = password_hash($password, PASSWORD_ARGON2ID);

// Проверка пароля
if (password_verify($password, $hash)) {
    echo "Password is valid!";
}

// Защита от XSS при выводе в HTML
$userInput = "<script>alert('XSS');</script>";
echo htmlspecialchars($userInput, ENT_QUOTES | ENT_HTML5, 'UTF-8');
```

## 3. Вопросы на собеседовании

1. **Почему алгоритмы MD5 и SHA-1 устарели для хеширования паролей?**
   *Ответ*: Они работают слишком быстро, что позволяет злоумышленникам подбирать пароли методом грубой силы (Brute-force) с помощью GPU-ферм и радужных таблиц (Rainbow tables). Современные функции `password_hash()` используют медленные криптографические алгоритмы (Argon2, Bcrypt) с настраиваемой стоимостью вычислений (cost) и солью.
2. **Как защитить приложение от XSS-атак?**
   *Ответ*: Фильтровать входные данные и обязательно экранировать любой пользовательский вывод, отправляемый в браузер, с помощью функции `htmlspecialchars()` с флагами `ENT_QUOTES`.
3. **Что такое CSRF и как от нее защититься?**
   *Ответ*: CSRF (Cross-Site Request Forgery) заставляет аутентифицированного пользователя выполнить нежелательные действия на сайте злоумышленника. Защита строится на использовании уникальных одноразовых CSRF-токенов, проверяемых при каждом POST/PUT запросе, а также атрибута `SameSite` для кук.
