# 22 — Работа с базами данных. PDO, SQL и Transactions

## 1. Теория

### PDO (PHP Data Objects)
- Рекомендуемый стандартный интерфейс для взаимодействия с реляционными базами данных в PHP.
- Поддерживает подготовленные выражения (Prepared Statements), что гарантирует защиту от **SQL-инъекций**.
- Поддерживает обработку ошибок через исключения (`PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION`).

### Транзакции (Transactions)
- Гарантируют атомарность операций (ACID).
- Методы PDO: `$pdo->beginTransaction()`, `$pdo->commit()`, `$pdo->rollBack()`.

---

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

try {
    $dsn = "mysql:host=127.0.0.1;dbname=app_db;charset=utf8mb4";
    $pdo = new \PDO($dsn, 'root', 'secret', [
        \PDO::ATTR_ERRMODE => \PDO::ERRMODE_EXCEPTION,
        \PDO::ATTR_DEFAULT_FETCH_MODE => \PDO::FETCH_ASSOC,
    ]);

    // Транзакция
    $pdo->beginTransaction();

    $stmt = $pdo->prepare("INSERT INTO users (name, email) VALUES (:name, :email)");
    $stmt->execute(['name' => 'Alice', 'email' => 'alice@example.com']);

    $pdo->commit();
} catch (\PDOException $e) {
    if (isset($pdo) && $pdo->inTransaction()) {
        $pdo->rollBack();
    }
    echo "Database error: " . $e->getMessage();
}
```

## 3. Вопросы на собеседовании

1. **Как PDO защищает от SQL-инъекций?**
   *Ответ*: За счет использования подготовленных выражений (Prepared Statements). Данные передаются отдельно от SQL-запроса и интерпретируются базой данных исключительно как литералы/параметры, а не как исполняемый SQL-код.
2. **В чем разница между `fetch(PDO::FETCH_ASSOC)` и `fetch(PDO::FETCH_OBJ)`?**
   *Ответ*: `FETCH_ASSOC` возвращает результат в виде ассоциативного массива (`$row['name']`), а `FETCH_OBJ` возвращает стандартный анонимный объект (`$row->name`).
3. **Что такое транзакция и зачем нужны методы `beginTransaction()`, `commit()` и `rollBack()`?**
   *Ответ*: Транзакция объединяет группу SQL-запросов в единую неделимую операцию (ACID). Если хотя бы один запрос завершается с ошибкой, транзакция откатывается назад через `rollBack()`, предотвращая частичное повреждение или несогласованность данных в БД.
