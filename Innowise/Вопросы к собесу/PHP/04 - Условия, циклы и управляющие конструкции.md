## 1. Фундаментальная теория и архитектура

### Управляющие конструкции ветвления
- Классические `if`, `elseif`, `else` и альтернативный синтаксис с двоеточием (`if(): ... endif;`), востребованный в шаблонизаторах.
- **Match Expression (PHP 8.0+)**:
  - Выполняет строгое сравнение (`===`).
  - Возвращает значение, которое можно сразу присвоить переменной или вернуть из функции.
  - Не имеет проваливания (`fall-through`), поэтому отсутствует необходимость писать `break`.
  - Выбрасывает `UnhandledMatchError`, если ни одно условие не подошло и нет ветки `default`.

### Циклы и особенности итерации
- `while`, `do-while`, `for`.
- **`foreach`**:
  - Работает как с массивами, так и с объектами, реализующими `Traversable`.
  - При обходе по ссылке (`&$value`) создает указатель. Главная ловушка: после завершения цикла переменная `$value` продолжает ссылаться на последний элемент массива. Любое последующее изменение `$value` молча перезапишет последний элемент массива, если предварительно не вызвать `unset($value)`.

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

// Продвинутое использование Match в PHP 8+
function getShippingCost(string $country, int $weight): float {
    return match (true) {
        $country === 'BY' && $weight <= 5 => 5.0,
        $country === 'BY' && $weight > 5 => 10.0,
        in_array($country, ['US', 'CA'], true) => 25.0,
        default => 40.0,
    };
}

// Защита от багов с foreach по ссылке
$prices = [10, 20, 30];
foreach ($prices as &$price) {
    $price *= 1.1;
}
unset($price); // Обязательный сброс ссылки!
```

## 3. Детальные вопросы на техническом собеседовании

1. **Каковы ключевые архитектурные отличия между `switch` и `match` в PHP?**
   *Ответ*: `switch` использует нестрогое сравнение (`==`), поддерживает проваливание (`fall-through`), не возвращает значение напрямую и не требует обязательного покрытия всех вариантов. `match` использует строгое сравнение (`===`), возвращает значение, не имеет fall-through и выбрасывает исключение при отсутствии подходящей ветки без `default`.
2. **Опишите подробно проблему с `foreach` по ссылке (`&$val`) и как ее предотвратить.**
   *Ответ*: После окончания цикла переменная `$val` не уничтожается, а остается указателем на последний элемент массива в символьной таблице. Если дальше в коде использовать переменную с тем же именем `$val = 100;`, это непреднамеренно изменит последний элемент исходного массива. Решение — вызывать `unset($val)` сразу после цикла.
3. **Как устроен обход массивов через `foreach` в Zend Engine под капотом?**
   *Ответ*: Массивы в PHP имеют внутренний указатель (internal pointer). При обычном обходе `foreach` копирует массив или использует механизм Copy-on-Write, но итерация по ссылке или модификация массива во время обхода может привести к неочевидному поведению указателя.
4. **Почему использование конструкции `goto` считается антипаттерном?**
   *Ответ*: `goto` нарушает принципы структурного программирования, создавая «спагетти-код», который крайне тяжело читать, тестировать, отлаживать и поддерживать.
