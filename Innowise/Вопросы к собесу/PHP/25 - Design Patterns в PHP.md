# 25 — Design Patterns в PHP

## 1. Теория

### Шаблоны проектирования (Design Patterns)
Шаблоны делятся на три основных категории:
1. **Порождающие (Creational)**:
   - **Singleton**: Гарантирует наличие единственного экземпляра класса (в PHP в рамках одного HTTP-запроса). Антипаттерн при злоупотреблении, усложняет тестирование.
   - **Factory Method / Abstract Factory**: Инкапсулируют создание объектов.
   - **Builder**: Пошаговое создание сложных объектов.
2. **Структурные (Structural)**:
   - **Adapter**: Преобразует интерфейс одного класса в интерфейс, ожидаемый клиентом.
   - **Decorator**: Динамически добавляет объекту новую функциональность.
   - **Facade**: Предоставляет простой интерфейс к сложной подсистеме.
3. **Поведенческие (Behavioral)**:
   - **Strategy**: Определяет семейство алгоритмов, инкапсулирует их и делает взаимозаменяемыми.
   - **Observer**: Реализует механизм подписки на события (Pub/Sub).
   - **State**: Позволяет объекту менять поведение при изменении внутреннего состояния.

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

// Пример паттерна Strategy
interface PaymentStrategyInterface {
    public function pay(float $amount): void;
}

class PayPalStrategy implements PaymentStrategyInterface {
    public function pay(float $amount): void {
        echo "Paid {$amount} using PayPal.\n";
    }
}

class ShoppingCart {
    public function __construct(private PaymentStrategyInterface $strategy) {}

    public function checkout(float $amount): void {
        $this->strategy->pay($amount);
    }
}
```

## 3. Вопросы на собеседовании

1. **Почему паттерн Singleton часто называют антипаттерном в PHP?**
   *Ответ*: Singleton скрывает зависимости класса, создает глобальное состояние, усложняет модульное тестирование (тесты начинают зависеть друг от друга из-за разделяемого состояния) и нарушает принцип единственной ответственности.
2. **В чем разница между паттернами Adapter и Decorator?**
   *Ответ*: `Adapter` меняет интерфейс существующего класса на другой, требуемый клиентом (для обеспечения совместимости). `Decorator` сохраняет исходный интерфейс объекта, но расширяет или модифицирует его поведение динамически «поверх» оригинала.
3. **Где на практике применяется паттерн Observer (Наблюдатель)?**
   *Ответ*: В системе событий фреймворков (например, Symfony EventDispatcher или Laravel Events), когда при наступлении определенного события (например, регистрации пользователя) автоматически срабатывают несколько независимых слушателей (отправка email, логирование, начисление бонусов).
