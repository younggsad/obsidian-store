## 1. Фундаментальная теория и архитектура

### Static (Статические члены)
- Принадлежат классу в целом, а не конкретному экземпляру.
- Внутри статического метода отсутствует псевдопеременная `$this`.
- **Позднее статическое связывание (Late Static Binding)**: Использование ключевого слова `static` вместо `self` позволяет разрешать вызовы методов на уровне того класса, который фактически вызвал метод в рантайме.

### Final
- Запрещает наследование класса (`final class`) или переопределение конкретного метода (`final public function`).

### Readonly
- Защита неизменяемости свойств после инициализации. В PHP 8.2 появилась поддержка `readonly` классов.

### Анонимные классы
- Создание одноразовых объектов на лету без объявления именованного класса.

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

// Позднее статическое связывание (LSB)
class BaseModel {
    protected static string $table = 'base';

    public static function getTable(): string {
        return static::$table; // LSB: вернет имя дочернего класса
    }
}

class UserModel extends BaseModel {
    protected static string $table = 'users';
}

echo UserModel::getTable(); // 'users'
```

## 3. Детальные вопросы на техническом собеседовании

1. **В чем разница между `self::` и `static::` при вызове статических методов?**
   *Ответ*: `self` жестко привязывает вызов к тому классу, в котором написан код (на этапе компиляции). `static` использует Позднее статическое связывание (LSB) и разрешается в рантайме на основе того класса, через который был вызван метод.
2. **Какие ограничения накладывает модификатор `readonly` на свойства классов?**
   *Ответ*: Readonly-свойство может быть записано ровно один раз (в конструкторе). Оно обязано иметь явное объявление типа (нельзя `mixed`), и его значение нельзя изменить после инициализации.
3. **Зачем нужны `final` классы и методы в проектировании?**
   *Ответ*: Для реализации паттернов проектирования (например, Final class для immutable DTO) или предотвращения нежелательного переопределения критической бизнес-логики в классах-потомках (Safe by design).
4. **Где на практике оправданно применение анонимных классов?**
   *Ответ*: В модульных тестах для быстрой реализации интерфейсов-заглушек или в паттернах, где требуется создать объект с уникальной разовой структурой.
