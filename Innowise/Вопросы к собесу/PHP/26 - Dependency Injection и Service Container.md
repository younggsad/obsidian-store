# 26 — Dependency Injection и Service Container

## 1. Теория

### Dependency Injection (Внедрение зависимостей)
- Проектирование, при котором класс не создает свои зависимости внутри через `new`, а получает их извне (через конструктор, сеттеры или методы).
- Обеспечивает слабую связанность (Loose coupling) и легкую подмену зависимостей в тестах (мокирование).

### Service Container (Контейнер внедрения зависимостей)
- Инструмент (IoC Container), который автоматически разрешает зависимости классов, управляет жизненным циклом объектов (singleton или transient) и конфигурирует их создание.
- Современные контейнеры (например, в Symfony или Laravel) используют Reflection API или заранее скомпилированные конфигурации для инстанцирования сервисов.

---

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

class DatabaseConnection {
    // Database logic
}

class UserRepository {
    public function __construct(private DatabaseConnection $db) {}
}

// Простейшая ручная демонстрация контейнера (Service Container)
class Container {
    private array $bindings = [];

    public function bind(string $abstract, \Closure $concrete): void {
        $this->bindings[$abstract] = $concrete;
    }

    public function make(string $abstract): mixed {
        return $this->bindings[$abstract]($this);
    }
}
```

## 3. Вопросы на собеседовании

1. **В чем разница между Dependency Injection (DI) и Service Locator?**
   *Ответ*: При DI зависимости явно передаются классу извне (обычно через конструктор), что делает их очевидными. Service Locator — это глобальный реестр (антипаттерн), у которого класс сам запрашивает нужные зависимости внутри себя, скрывая их и затрудняя статический анализ.
2. **Что такое жизненный цикл сервиса (Service Lifetime) в контейнере?**
   *Ответ*: Основные режимы: `Transient` (новый экземпляр создается при каждом запросе), `Singleton` (один и тот же экземпляр переиспользуется на протяжении всего жизненного цикла запроса или приложения) и `Scoped` (один экземпляр в рамках текущего запроса/сессии).
3. **Как контейнер внедрения зависимостей понимает, что нужно передать в конструктор класса?**
   *Ответ*: Контейнер анализирует сигнатуру конструктора с помощью Reflection API (проверяет типы аргументов параметров) или использует заранее скомпилированный конфигурационный файл.
