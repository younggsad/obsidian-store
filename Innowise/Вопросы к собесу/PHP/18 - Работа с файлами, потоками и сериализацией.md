## 1. Фундаментальная теория и архитектура

### Работа с файлами и потоками
- Универсальные обертки потоков (Stream Wrappers) позволяют работать с файлами, сокетами и в памяти (`php://input`, `php://memory`) через единый интерфейс.

### Сериализация
- `json_encode` / `json_decode` — рекомендуемый стандарт.
- `serialize` / `unserialize` — встроенная сериализация объектов (уязвима при десериализации ненадежных данных из-за PHP Object Injection).

---

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

// Безопасное чтение тела входящего запроса
$rawInput = file_get_contents('php://input');
$payload = json_decode($rawInput, true, 512, JSON_THROW_ON_ERROR);
```

## 3. Детальные вопросы на техническом собеседовании

1. **Что такое `php://input` и почему он незаменим при работе с REST API?**
   *Ответ*: Потоковый псевдофайл `php://input` позволяет читать сырые данные (raw body) входящего HTTP-запроса. Это единственный способ получить JSON-тело запроса в PHP-приложении (так как суперглобальный массив `$_POST` заполняется только данными форм вида `application/x-www-form-urlencoded` или `multipart/form-data`).
2. **В чем заключается уязвимость PHP Object Injection при использовании `unserialize()`?**
   *Ответ*: Если злоумышленник может передать строку в `unserialize()`, он может восстановить объект произвольного класса, что приведет к немедленному вызову его магических методов (`__destruct`, `__wakeup`), способных выполнить произвольный код (RCE).
3. **Как предотвратить состояния гонки (Race conditions) при записи в файл несколькими процессами?**
   *Ответ*: Использовать файловые блокировки с помощью флага `LOCK_EX` в функции `file_put_contents()` или низкоуровневого вызова `flock()`.
4. **Зачем нужны Stream Wrappers в PHP?**
   *Ответ*: Они предоставляют единый синтаксис для работы с различными источниками данных (файлы, архивы `zip://`, сетевые протоколы `http://`, `php://memory`), скрывая детали реализации подсистемы ввода-вывода.
