# 11 — ООП. Интерфейсы, Traits, Abstract Classes

## 1. Теория

### Интерфейсы (Interfaces)
- Задают контракт (набор публичных методов), который класс обязан реализовать (`implements`).
- Не содержат реализации методов и свойств (но могут содержать константы).
- Поддерживают множественное унаследование интерфейсов (`interface B extends A`). Класс может реализовывать сколько угодно интерфейсов.

### Трейты (Traits)
- Механизм горизонтального повторного использования кода (множественного наследования поведения) для преодоления ограничения одиночного наследования.
- Позволяют встраивать набор методов в различные классы с помощью `use TraitName`.
- Поддерживают разрешение конфликтов через операторы `insteadof` и `as`.

### Абстрактные классы (Abstract Classes)
- Не могут быть инстанцированы (`new AbstractClass()`).
- Служат базовыми шаблонами для семейств родственных классов, объединяя общую логику и требования через абстрактные методы.

---

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

trait LoggerTrait {
    public function log(string $message): void {
        echo "[LOG]: " . $message . "\n";
    }
}

interface Identifiable {
    public function getId(): int;
}

class Entity implements Identifiable {
    use LoggerTrait;

    public function __construct(private int $id) {}

    public function getId(): int {
        $this->log("Getting ID: {$this->id}");
        return $this->id;
    }
}
```

## 3. Вопросы на собеседовании

1. **В чем ключевые отличия между Интерфейсом и Абстрактным классом?**
   *Ответ*: Интерфейс задает чистый контракт без реализации и состояния (только сигнатуры методов и константы). Класс может реализовывать много интерфейсов. Абстрактный класс задает базовую реализацию, может содержать свойства, конструкторы и методы с телом, но поддерживается только одиночное наследование.
2. **Для чего предназначены Трейты (`traits`) и каковы подводные камни их использования?**
   *Ответ*: Трейты позволяют шарить методы между несвязанными классами (горизонтальное наследование). Минусы: скрытые зависимости класса, сложность отслеживания происхождения методов и потенциальные конфликты имен (resolvable через `insteadof`).
3. **Может ли трейт содержать статические методы или свойства?**
   *Ответ*: Да, трейты могут содержать как статические методы, так и статические свойства, а также абстрактные методы, которые реализующий класс обязан определить.
