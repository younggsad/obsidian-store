## 1. Фундаментальная теория и архитектура

### Магические методы (Magic Methods)
Специальные методы, перехватывающие стандартные операции с объектами:
- `__get()` / `__set()`: Обращение к несуществующим или инкапсулированным свойствам.
- `__call()` / `__callStatic()`: Вызов несуществующих методов.
- `__toString()`: Преобразование объекта в строку.
- `__invoke()`: Вызов объекта как функции.
- `__clone()`: Глубокое копирование при клонировании объекта.

---

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

class LazyPropertyHandler {
    private array $cache = [];

    public function __get(string $name): mixed {
        if (!isset($this->cache[$name])) {
            $this->cache[$name] = "Loaded value for {$name}";
        }
        return $this->cache[$name];
    }
}
```

## 3. Детальные вопросы на техническом собеседовании

1. **Каковы главные недостатки использования магических методов (`__get`, `__set`, `__call`)?**
   *Ответ*: Снижение производительности из-за динамического разрешения в рантайме, отсутствие поддержки со стороны IDE (автодополнение и рефакторинг работают некорректно) и проблемы для статически анализаторов (PHPStan).
2. **Как работает метод `__clone()` и чем он отличается от поверхностного копирования?**
   *Ответ*: По умолчанию оператор `clone` делает поверхностную копию (shallow copy) — вложенные объекты остаются ссылками на те же участки памяти. Метод `__clone()` позволяет вручную выполнить глубокое копирование (deep copy) вложенных объектов.
3. **Для чего предназначен метод `__invoke()`?**
   *Ответ*: Позволяет вызывать объект как функцию (`$obj()`). Активно применяется в Single-Action Controllers (контейнерах единственного действия) в современных веб-фреймворках.
4. **Можно ли сделать магические методы приватными или стартануть без объявления `public`?**
   *Ответ*: Все магические методы (кроме `__construct` в некоторых контекстах) обязаны быть объявлены с модификатором `public`, иначе PHP сгенерирует фатальную ошибку.
