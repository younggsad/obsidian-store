## 1. Фундаментальная теория и архитектура

### Суперглобальные массивы
- `$_GET`, `$_POST`, `$_SERVER`, `$_FILES`, `$_COOKIE`, `$_SESSION`.
- `$_REQUEST` содержит смесь GET, POST и COOKIE, что делает его небезопасным из-за атак Parameter Pollution.

### REST API
- Корректное использование HTTP-методов и статус-кодов (200, 201, 400, 401, 403, 404, 422, 500).

---

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

header('Content-Type: application/json; charset=utf-8');
if ($_SERVER['REQUEST_METHOD'] !== 'GET') {
    http_response_code(405);
    echo json_encode(['error' => 'Method Not Allowed']);
    exit;
}
```

## 3. Детальные вопросы на техническом собеседовании

1. **В чем заключается уязвимость массива `$_REQUEST`?**
   *Ответ*: `$_REQUEST` объединяет данные из `$_GET`, `$_POST` и `$_COOKIE`. Это создает риск подмены параметров (Parameter Pollution), когда злоумышленник может перезаписать GET-параметр с помощью POST-запроса или куки с аналогичным именем.
2. **Как правильно организовать чтение кастомных заголовков запроса (`Authorization`)?**
   *Ответ*: Использовать функцию `getallheaders()` или обращаться к массиву `$_SERVER['HTTP_AUTHORIZATION']` (в некоторых конфигурациях сервера может потребоваться дополнительное проксирование заголовков).
3. **Какие HTTP статус-коды возвращаются при успешном создании ресурса и при ошибке валидации?**
   *Ответ*: Создание ресурса — `201 Created`. Ошибка валидации клиентских данных — `422 Unprocessable Entity` (или `400 Bad Request`).
4. **Как PHP обрабатывает загрузку больших файлов через `$_FILES`?**
   *Ответ*: Файлы сначала загружаются во временную директорию ОС (настраивается в `php.ini` как `upload_tmp_dir`), после чего скрипт должен переместить их в постоянное хранилище через `move_uploaded_file()`.
