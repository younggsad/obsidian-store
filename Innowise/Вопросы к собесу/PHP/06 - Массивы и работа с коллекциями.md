## 1. Фундаментальная теория и архитектура

### Внутреннее устройство массивов в PHP
В PHP массив — это не классический массив из C (непрерывный участок памяти), а **упорядоченная хэш-таблица (Ordered Hash Table)**.
- Каждое значение связано с ключом (`int` или `string`).
- Хэш-таблица хранит связи между ключами и элементами, а двухсвязный список поверх нее сохраняет порядок добавления элементов (благодаря чему `foreach` всегда возвращает элементы в порядке их вставки).

### Эффективность и особенности
- Поддерживают одновременное использование как числовых индексов, так и строковых ключей.
- Механизм **Copy-on-Write** минимизирует затраты памяти при чтении и копировании массивов.

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

// Эффективная работа с массивами в функциональном стиле
$transactions = [
    ['amount' => 100, 'status' => 'completed'],
    ['amount' => 50, 'status' => 'pending'],
    ['amount' => 200, 'status' => 'completed'],
];

$totalCompleted = array_reduce(
    array_filter($transactions, fn(array $tx) => $tx['status'] === 'completed'),
    fn(float $carry, array $tx) => $carry + $tx['amount'],
    0.0
);
```

## 3. Детальные вопросы на техническом собеседовании

1. **Как массивы устроены на уровне исходного кода Zend Engine?**
   *Ответ*: Массивы реализованы как упорядоченные хэш-таблицы (Ordered Hash Tables). Они сочетают в себе свойства хэш-карты (для быстрого поиска по ключу) и двусвязного списка (для сохранения порядка элементов при итерации).
2. **В чем разница между `isset()` и `array_key_exists()` при проверке ключа?**
   *Ответ*: `array_key_exists()` проверяет физическое наличие ключа в хэш-таблице (даже если его значение равно `null`). `isset()` возвращает `false`, если ключ отсутствует ИЛИ если его значение равно `null`.
3. **Как оператор распаковки `[...$arr1, ...$arr2]` ведет себя при пересечении ключей?**
   *Ответ*: Если массивы имеют одинаковые строковые ключи, то значение из правого массива перезапишет значение из левого. Если ключи числовые, то они будут переиндексированы заново (в отличие от `array_merge`, которая ведет себя аналогично для строк, но для чисел также переиндексирует, хотя старые нечисловые ключи сохраняет).
4. **Каковы временные затраты (`Big-O`) основных операций с массивами PHP?**
   *Ответ*: Поиск по ключу и доступ по индексу занимают $O(1)$ в среднем. Добавление в конец — $O(1)$. Поиск по значению (`in_array`, `array_search`) и фильтрация требуют линейного прохода $O(N)$.
