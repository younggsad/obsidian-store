# 08 — Обработка ошибок и исключений

## 1. Теория

### Эволюция обработки ошибок в PHP
1. **Old-school Errors**: Предупреждения (`E_WARNING`), уведомления (`E_NOTICE`), фатальные ошибки (`E_ERROR`). Они прерывали или продолжали выполнение скрипта, но не перехватывались блоком `try-catch`.
2. **Исключения (Exceptions)**: ООП-подход с использованием `try / catch / finally`.
3. **Throwable (PHP 7+)**: Общий интерфейс для всех перехватываемых объектов ошибок. Наследуется на две ветки:
   - `Exception` — пользовательские исключения.
   - `Error` — внутренние фатальные ошибки PHP (например, `TypeError`, `ArithmeticError`, `ParseError`), которые теперь тоже можно перехватывать!

### Иерархия основных исключений
- `Exception` -> `LogicException`, `RuntimeException`.
- `Error` -> `TypeError`, `ValueError`, `DivisionByZeroError`.

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

function divide(int $a, int $b): float {
    if ($b === 0) {
        // Выбрасываем исключение
        throw new \InvalidArgumentException("Division by zero is not allowed.");
    }
    return $a / $b;
}

try {
    $result = divide(10, 0);
} catch (\InvalidArgumentException $e) {
    echo "Caught specific exception: " . $e->getMessage();
} catch (\Throwable $e) {
    echo "Caught any other error or exception: " . $e->getMessage();
} finally {
    echo "\nExecution completed.";
}
```

## 3. Вопросы на собеседовании

1. **Что такое интерфейс `Throwable` и какая разница между `Exception` и `Error`?**
   *Ответ*: `Throwable` — базовый интерфейс для всего, что может быть выброшено через `throw`. `Exception` используется для бизнес-логики и пользовательских исключений. `Error` используется самим Zend Engine для фатальных сбоев (например, несоответствие типов `TypeError`), которые в PHP 7+ стали перехватываемыми.
2. **Можно ли перехватить старые фатальные ошибки (`E_ERROR`) через `try-catch`?**
   *Ответ*: Традиционные фатальные ошибки (`E_ERROR`) перехватить `try-catch` нельзя, но критические сбои PHP 7+ (превращенные в класс `Error` и его наследников) — можно.
3. **Зачем нужен блок `finally`?**
   *Ответ*: Блок `finally` гарантированно выполняется после блоков `try` и `catch` независимо от того, было выброшено исключение или нет. Обычно используется для освобождения ресурсов (закрытие соединения с БД, файловых дескрипторов).
