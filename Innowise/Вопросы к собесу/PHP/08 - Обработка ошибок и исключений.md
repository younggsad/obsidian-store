## 1. Фундаментальная теория и архитектура

### Эволюция обработки ошибок
1. **Традиционные ошибки PHP**: `E_WARNING`, `E_NOTICE`, `E_DEPRECATED`. Они не прерывают выполнение скрипта (если не настроено иначе) и не перехватываются блоком `try-catch`.
2. **Исключения (Exceptions)**: ООП-подход с использованием `try / catch / finally`.
3. **Интерфейс Throwable (PHP 7+)**: Объединяет все, что может быть выброшено через `throw`. Имеет две основные ветки:
   - `Exception`: Базовый класс для пользовательских исключений и бизнес-логики (`LogicException`, `RuntimeException`).
   - `Error`: Внутренние критические ошибки Zend Engine (например, `TypeError`, `DivisionByZeroError`, `ArithmeticError`), которые теперь также можно перехватывать.

## 2. Примеры кода

```php
<?php
declare(strict_types=1);

class InsufficientFundsException extends \RuntimeException {}

class BankAccount {
    public function __construct(private float $balance) {}

    public function withdraw(float $amount): void {
        if ($amount > $this->balance) {
            throw new InsufficientFundsException("Account balance is too low.");
        }
        $this->balance -= $amount;
    }
}

try {
    $account = new BankAccount(50.0);
    $account->withdraw(100.0);
} catch (InsufficientFundsException $e) {
    echo "Business error: " . $e->getMessage();
} catch (\Throwable $e) {
    echo "Unexpected error: " . $e->getMessage();
} finally {
    echo "\nOperation finalized.";
}
```

## 3. Детальные вопросы на техническом собеседовании

1. **Что такое интерфейс `Throwable` и почему в PHP 7 была введена иерархия `Error`?**
   *Ответ*: До PHP 7 фатальные ошибки движка (например, неверный тип аргумента или деление на ноль) приводили к мгновенному падению скрипта без возможности корректной обработки. Введение интерфейса `Throwable` и класса `Error` позволило перехватывать такие сбои в блоках `try-catch`.
2. **В чем разница между `LogicException` и `RuntimeException`?**
   *Ответ*: `LogicException` сигнализирует об ошибках в архитектуре или коде (например, передача некорректного аргумента, нарушение контракта), которые должны быть исправлены разработчиком. `RuntimeException` сигнализирует об ошибках, возникающих в рантайме из-за внешних факторов (нет связи с БД, файл не найден).
3. **Как работает блок `finally` и гарантирован ли его вызов при наличии `return` в `try`?**
   *Ответ*: Блок `finally` гарантированно выполняется в любом случае — даже если в блоке `try` или `catch` был вызван `return`, выброшено новое исключение или завершен скрипт.
4. **Как преобразовать старые предупреждения и notices PHP (`E_WARNING`) в исключения?**
   *Ответ*: С помощью установки обработчика ошибок через `set_error_handler()`, который будет выбрасывать `ErrorException` при возникновении любого уведомления или предупреждения.
