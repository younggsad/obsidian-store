## 📖 Базовые понятия (глоссарий)

Прежде чем погружаться в детали, разберём ключевые термины — они встречаются почти в каждом разделе ниже.

> [!abstract]+ Ядро системы
> 
> - **Claude Code** — агентный инструмент для работы с кодом от Anthropic, который работает в терминале, IDE, десктопном приложении или браузере и помогает превращать идеи в код быстрее.
> - **Агентный харнесс (agentic harness)** — совокупность инструментов, управления контекстом и среды исполнения, которая превращает языковую модель в полноценного агента. Сам Claude Code — это харнесс, а Claude — модель внутри него.
> - **Агентный цикл (agentic loop)** — цикл, через который Claude проходит при выполнении задачи: сбор контекста → действие → проверка результата → повтор до завершения. Именно в фазы этого цикла встраиваются хуки, скиллы и MCP.
> - **Agentic coding** — режим работы, при котором ИИ самостоятельно читает файлы, выполняет команды и вносит изменения, пока вы наблюдаете, направляете или отходите от компьютера — в отличие от чат-ассистентов, которые только советуют.
> - **Surface (поверхность)** — любое место доступа к Claude Code: CLI, VS Code, JetBrains, Desktop, claude.ai. Все поверхности используют один и тот же движок.
> - **Session (сессия)** — диалог, привязанный к текущей директории, со своим независимым контекстным окном. Транскрипты хранятся в `~/.claude/projects/`.
> - **Turn (ход)** — один полный ответ Claude в рамках сессии: начинается с вашего сообщения и заканчивается завершением ответа Claude, включая любое число вызовов инструментов.
> - **Tool (инструмент)** — действие, которое может выполнить Claude: прочитать файл, отредактировать код, выполнить команду в shell, найти информацию в вебе, вызвать сабагента.
> - **Context window (контекстное окно)** — рабочая память сессии: история диалога, содержимое файлов, вывод команд, CLAUDE.md, авто-память, загруженные скиллы и системные инструкции. Команда `/context` показывает, что расходует место.
> - **Compaction (компакция)** — автоматическая суммаризация диалога при приближении к лимиту контекстного окна. CLAUDE.md корневого проекта и авто-память переживают компакцию.

> [!abstract]+ Память и конфигурация
> 
> - **`.claude` директория** — место, где Claude Code хранит конфигурацию проекта: настройки, хуки, скиллы, сабагенты, правила и авто-память. У проекта — `.claude/` в корне, у пользователя — `~/.claude/`.
> - **CLAUDE.md** — markdown-файл с постоянными инструкциями, которые вы пишете для Claude. Загружается в начале каждой сессии как пользовательское сообщение после системного промпта. Подробнее: [[#🧠 CLAUDE.md и память]].
> - **Auto memory (авто-память)** — заметки, которые Claude сам пишет о себе на основе ваших правок и предпочтений, хранятся по git-репозиторию.
> - **Rules (правила)** — модульные файлы инструкций в `.claude/rules/`, которые загружаются вместе с CLAUDE.md; можно ограничить область действия через `paths:`.
> - **Settings layers (уровни настроек)** — иерархия чтения конфигурации: managed policy → аргументы командной строки → `.claude/settings.local.json` → `.claude/settings.json` → `~/.claude/settings.json`.
> - **Managed settings (управляемые настройки)** — настройки, применяемые IT/DevOps на уровне всей организации; пользовательские и проектные настройки не могут их переопределить.
> - **Project trust (доверие к проекту)** — диалог подтверждения директории перед загрузкой конфигурации; без подтверждения часть содержимого репозитория (например, project allow rules) не загружается.

> [!abstract]+ Расширение возможностей
> 
> - **Skill (скилл)** — файл `SKILL.md` с инструкциями, знаниями или workflow, который Claude добавляет в свой арсенал. Подробнее: [[#🧩 Skills (скиллы)]].
> - **Bundled skills (встроенные скиллы)** — готовые prompt-based playbook'и, входящие в поставку (`/code-review`, `/debug`, `/loop` и др.).
> - **Command (команда)** — переиспользуемая инструкция, вызываемая через `/имя`.
> - **Hook (хук)** — пользовательский обработчик, который выполняется детерминированно в определённой точке жизненного цикла Claude Code. Подробнее: [[#🪝 Hooks (хуки)]].
> - **Subagent (сабагент)** — специализированный ИИ-помощник, работающий в собственном контекстном окне с своим системным промптом и набором инструментов. Подробнее: [[#👥 Subagents (сабагенты)]].
> - **Agent teams (команды агентов)** — несколько независимых сессий Claude Code, координируемых тимлидом с общим списком задач; в отличие от сабагентов, с каждым можно общаться напрямую.
> - **MCP (Model Context Protocol)** — открытый стандарт подключения ИИ к внешним источникам данных и сервисам. Подробнее: [[#🔌 MCP servers]].
> - **MCP server** — программа, предоставляющая Claude инструменты, промпты или ресурсы через MCP.
> - **Connector (коннектор)** — MCP-сервер, добавленный в аккаунт claude.ai, а не настроенный локально.
> - **Plugin (плагин)** — набор скиллов, хуков, сабагентов и MCP-серверов, упакованный как единый устанавливаемый модуль.
> - **Output style** — конфигурация, изменяющая системный промпт Claude (в отличие от CLAUDE.md, который добавляется как пользовательское сообщение).
> - **Channel (канал)** — MCP-сервер, который отправляет события в вашу сессию, чтобы Claude мог реагировать на происходящее, пока вы не за терминалом.

> [!abstract]+ Разрешения, режимы и безопасность
> 
> - **Permission mode (режим разрешений)** — базовое поведение подтверждения действий на сессию: `default` (Manual), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`.
> - **Permission rule (правило разрешений)** — запись в настройках, разрешающая/спрашивающая/запрещающая вызов инструмента по имени и шаблону аргументов. Оценка идёт в порядке deny → ask → allow.
> - **Auto mode (авто-режим)** — режим разрешений, в котором отдельная модель-классификатор проверяет действия вместо вас; стартовый режим по умолчанию на планах Pro/Max/Team.
> - **Plan mode (режим планирования)** — режим, в котором Claude исследует и предлагает план изменений, не трогая исходные файлы, пока план не одобрен.
> - **Sandboxing (песочница)** — изоляция файловой системы и сети на уровне ОС для инструмента Bash; отдельный слой от правил разрешений.
> - **Prompt injection (промпт-инъекция)** — враждебные инструкции, встроенные в файл, веб-страницу или результат инструмента, пытающиеся перенаправить Claude на нежелательные действия.
> - **Checkpoint (чекпоинт)** — точка восстановления, создаваемая при каждом отправленном промпте; `Esc Esc` или `/rewind` откатывают код и/или диалог.
> - **Worktree isolation** — режим изоляции, при котором Claude работает в отдельном git worktree (`.claude/worktrees/`), чтобы параллельные агенты не конфликтовали.
> - **Non-interactive mode** — режим одного промпта без интерактивного ввода (флаг `-p`/`--print`); используется в CI, скриптах, пайплайнах.
> - **Extended thinking / Effort level** — видимое пошаговое рассуждение модели и настройка, регулирующая бюджет "размышлений" (`low`…`max`).

## 🏗️ Что такое Claude Code и агентный цикл

> [!quote] Определение 
> Claude Code — агентный инструмент для программирования от Anthropic, который работает в терминале и помогает превращать идеи в код быстрее, чем раньше.

### Что умеет Claude Code

- **Строит функциональность по описанию** — вы описываете задачу простым языком, Claude составляет план, пишет код и проверяет, что он работает.
- **Отлаживает и исправляет ошибки** — анализирует кодовую базу по описанию бага или сообщению об ошибке.
- **Ориентируется в любой кодовой базе** — удерживает представление о структуре всего проекта, может искать актуальную информацию в вебе и через MCP подключаться к внешним источникам (Google Drive, Figma, Slack).
- **Автоматизирует рутину** — исправление сложных lint-проблем, разрешение merge-конфликтов, написание release notes.

### Агентный цикл

Каждая задача проходит цикл: **сбор контекста → действие → проверка результата → повтор**. Каждый вызов инструмента возвращает информацию, влияющую на следующий шаг. Цикл можно прерывать в любой момент, чтобы перенаправить работу.

> [!tip] Куда встраиваются расширения 
> Большинство точек расширения — [[#🪝 Hooks (хуки)|хуки]], [[#🧩 Skills (скиллы)|скиллы]] и [[#🔌 MCP servers|MCP]] — подключаются к конкретным фазам этого цикла.

### Где работает Claude Code

- **Поверхности (surfaces)**: CLI, VS Code, JetBrains, Desktop-приложение, claude.ai (веб), Slack, Chrome-расширение.
- **Среды исполнения (execution environments)**: локально на машине, в облачной песочнице (Claude Code on the web), в self-hosted окружении, в контейнерах/devcontainer.
- Все поверхности используют единый движок, но локальные сессии читают ваш `~/.claude/`, а облачные — стартуют с чистого клона репозитория и не видят локальную конфигурацию.

### Контекстное окно

Контекстное окно — рабочая память сессии (диалог, файлы, вывод команд, CLAUDE.md, авто-память, загруженные скиллы). По мере заполнения срабатывает **компакция (compaction)** — автоматическая суммаризация: сначала очищаются старые результаты инструментов, затем суммируется диалог. Команда `/context` показывает, что расходует место.

> [!warning] Что переживает компакцию 
> CLAUDE.md корневого проекта и auto memory перечитываются с диска заново. Инструкции, данные только в переписке (без сохранения в файл), могут быть потеряны.

## 🧠 CLAUDE.md и память

> [!quote] Определение 
> CLAUDE.md — markdown-файл с постоянными инструкциями, которые Claude читает в начале каждой сессии. Это **контекст, а не принудительная конфигурация** — Claude старается следовать инструкциям, но гарантии строгого соблюдения нет.

### Где хранить CLAUDE.md

|Область|Путь|Назначение|Кем используется|
|---|---|---|---|
|**Managed policy**|`/etc/claude-code/CLAUDE.md` (Linux/WSL) и аналоги для macOS/Windows|Инструкции всей организации|Все пользователи организации|
|**User instructions**|`~/.claude/CLAUDE.md`|Личные предпочтения во всех проектах|Только вы (все проекты)|
|**Project instructions**|`./CLAUDE.md` или `./.claude/CLAUDE.md`|Общекомандные инструкции проекта|Команда через систему контроля версий|
|**Local instructions**|`./CLAUDE.local.md`|Личные предпочтения для конкретного проекта|Только вы (текущий проект)|

> [!tip] Быстрый старт 
> Запустите `/init` — Claude проанализирует кодовую базу и создаст стартовый CLAUDE.md с командами сборки, тестирования и обнаруженными конвенциями проекта. Если файл уже существует, `/init` предложит улучшения, а не перезапишет его.

### Как правильно писать CLAUDE.md

- **Размер**: держите файл до ~200 строк. Длинные файлы потребляют больше контекста и снижают точность следования инструкциям.
- **Структура**: используйте markdown-заголовки и списки — Claude сканирует структуру так же, как читатель.
- **Конкретность**: пишите проверяемые инструкции.
    - ✅ _"Используй отступы в 2 пробела"_ вместо ❌ _"Форматируй код правильно"_
    - ✅ _"Запускай `npm test` перед коммитом"_ вместо ❌ _"Тестируй изменения"_
- **Согласованность**: противоречащие друг другу правила Claude может выбирать произвольно — периодически проверяйте вложенные CLAUDE.md и правила на конфликты.

### Импорт файлов

CLAUDE.md может подключать другие файлы через синтаксис `@path/to/import`:

```text
See @README for project overview and @package.json for available npm commands.

# Additional Instructions
- git workflow @docs/git-instructions.md
```

Максимальная глубина рекурсивного импорта — 4 перехода. Чтобы упомянуть путь без импорта, используйте обратные кавычки: `` `@README` ``.

> [!warning] Внешние импорты 
> Если импорт в проектном CLAUDE.md указывает за пределы рабочей директории (например, на домашнюю папку), при первой встрече Claude Code покажет диалог подтверждения — это защита от файлов, закоммиченных другими людьми в общий проект.

### AGENTS.md

Claude Code читает **CLAUDE.md**, а не **AGENTS.md**. Если репозиторий уже использует `AGENTS.md` для других агентов, создайте `CLAUDE.md` с импортом:

```markdown
@AGENTS.md

## Claude Code
Use plan mode for changes under `src/billing/`.
```

Либо используйте симлинк: `ln -s AGENTS.md CLAUDE.md` (на Windows требуются права администратора).

### Как загружаются файлы

Claude Code загружает `CLAUDE.md` и `CLAUDE.local.md` из текущей рабочей директории и всех директорий выше неё. Все найденные файлы **конкатенируются** в контекст (не переопределяют друг друга), от корня файловой системы до рабочей директории — так что инструкции, ближе к месту запуска, читаются последними.

### Organize rules с `.claude/rules/`

Для крупных проектов инструкции можно разбить на модульные файлы в `.claude/rules/`:

```text
your-project/
├── .claude/
│   ├── CLAUDE.md
│   └── rules/
│       ├── code-style.md
│       ├── testing.md
│       └── security.md
```

Правила можно **ограничить по путям** через YAML frontmatter:

```markdown
---
paths:
  - "src/api/**/*.ts"
---
# API Development Rules
- All API endpoints must include input validation
```

> [!note] Rules vs Skills 
> Правила загружаются в контекст каждую сессию (или при открытии подходящих файлов). Для задач, не требующих постоянного присутствия в контексте, используйте [[#🧩 Skills (скиллы)|скиллы]] — они загружаются только при вызове.

### Auto memory (авто-память)

Claude накапливает знания между сессиями без вашего участия, сохраняя 4 типа заметок:

- **`user`** — ваша роль, экспертиза, рабочие предпочтения
- **`feedback`** — правки, которые вы даёте Claude, подтверждённые подходы
- **`project`** — текущая работа, дедлайны, решения, которые нельзя вывести из кода
- **`reference`** — где искать информацию вне проекта (трекер задач, дашборд)

Хранится в `~/.claude/projects/<project>/memory/` в виде индекса `MEMORY.md` (первые 200 строк / 25 КБ загружаются каждую сессию) плюс отдельные тематические файлы. Включена по умолчанию, управляется через `/memory` или настройку `autoMemoryEnabled`.

## 🧩 Skills (скиллы)

> [!quote] Определение 
> Skills расширяют возможности Claude. Создайте файл `SKILL.md` с инструкциями — и Claude добавит его в свой инструментарий. Claude использует скилл, когда это уместно, либо вы вызываете его напрямую через `/имя-скилла`.

> [!note] Когда создавать скилл 
> Создавайте скилл, когда вы вставляете одни и те же инструкции, чек-лист или многошаговую процедуру в чат снова и снова, или когда раздел CLAUDE.md разросся в процедуру, а не факт. В отличие от CLAUDE.md, тело скилла загружается **только при использовании** — длинный справочный материал почти ничего не стоит, пока не понадобится.

### Структура SKILL.md

```yaml
---
name: my-skill
description: Что делает скилл и когда его использовать
disable-model-invocation: true
allowed-tools: Read Grep
---

Инструкции скилла здесь...
```

Обязательных полей нет, но `description` настоятельно рекомендуется — именно по нему Claude решает, когда применить скилл.

### Ключевые поля frontmatter

|Поле|Назначение|
|---|---|
|`description`|Что делает скилл и когда использовать — на основе этого Claude решает, применять ли скилл автоматически|
|`disable-model-invocation`|`true` — только вы можете вызвать скилл (например, `/deploy`); Claude не вызовет его сам|
|`user-invocable`|`false` — только Claude может вызвать скилл (скрыт из меню `/`)|
|`allowed-tools`|Инструменты, предварительно одобренные на ход вызова скилла (без запроса разрешения)|
|`disallowed-tools`|Инструменты, недоступные, пока скилл активен|
|`context: fork`|Запускает скилл в изолированном сабагенте (см. [[#👥 Subagents (сабагенты)]])|
|`arguments`|Именованные позиционные аргументы для подстановки `$name`|
|`model`|Модель, используемая, пока скилл активен|
|`paths`|Glob-паттерны — скилл активируется автоматически только при работе с подходящими файлами|

### Где хранятся скиллы

|Расположение|Путь|Область действия|
|---|---|---|
|Enterprise|managed settings|Все пользователи организации|
|Personal|`~/.claude/skills/<skill-name>/SKILL.md`|Все ваши проекты|
|Project|`.claude/skills/<skill-name>/SKILL.md`|Только этот проект|
|Plugin|`<plugin>/skills/<skill-name>/SKILL.md`|Где включён плагин|

При совпадении имён приоритет: **enterprise > personal > project**; скилл плагина использует пространство имён `plugin-name:skill-name`, поэтому конфликтов не возникает.

### Типы контента скилла

- **Reference content (справочный)** — добавляет знания, применяемые к текущей работе (конвенции, паттерны, стиль). Работает "инлайново" вместе с контекстом диалога.
- **Task content (задачный)** — пошаговые инструкции для конкретного действия (деплой, коммит, генерация кода). Часто вызывается напрямую через `/имя` с `disable-model-invocation: true`.

### Динамическая инъекция контекста

Синтаксис `` !`команда` `` запускает shell-команду **до** отправки содержимого скилла в Claude — вывод команды подставляется вместо плейсхолдера:

```yaml
---
description: Резюмирует незакоммиченные изменения
---

## Текущие изменения
!`git diff HEAD`

## Инструкции
Резюмируй изменения выше в 2-3 пунктах.
```

### Bundled skills (встроенные скиллы)

Claude Code включает готовые скиллы: `/doctor`, `/code-review`, `/batch`, `/debug`, `/loop`, `/claude-api` и др. Они устроены как prompt-based playbook'и — детальные инструкции, по которым Claude самостоятельно оркестрирует работу инструментами.

### Запуск скилла в сабагенте

Поле `context: fork` запускает скилл изолированно — содержимое скилла становится промптом, управляющим сабагентом, без доступа к истории диалога:

```yaml
---
name: deep-research
description: Тщательно исследовать тему
context: fork
agent: Explore
---

Research $ARGUMENTS thoroughly:
1. Find relevant files using Glob and Grep
2. Read and analyze the code
3. Summarize findings with specific file references
```

### Аргументы и подстановки

|Переменная|Что подставляется|
|---|---|
|`$ARGUMENTS`|Все аргументы вызова скилла|
|`$ARGUMENTS[N]` / `$N`|Аргумент по индексу (0-based)|
|`${CLAUDE_SESSION_ID}`|ID текущей сессии|
|`${CLAUDE_SKILL_DIR}`|Директория с `SKILL.md` этого скилла|
|`${CLAUDE_PROJECT_DIR}`|Корень проекта|
|`${CLAUDE_PLUGIN_ROOT}`|Директория установки плагина (только для скиллов из плагинов)|

## 🪝 Hooks (хуки)

> [!quote] Определение 
> Hooks — пользовательские shell-команды (или другие обработчики), которые Claude Code запускает в определённых точках своего жизненного цикла. Это даёт **детерминированный контроль**: некоторые действия выполняются всегда, а не по усмотрению модели.

> [!tip] Зачем нужны хуки 
> Используйте хуки, чтобы принудительно применять правила проекта, автоматизировать рутинные задачи и интегрировать Claude Code с существующими инструментами — форматирование кода после правок, блокировка правок защищённых файлов, уведомления, когда Claude ждёт ввода, и т.д.

### Как устроен хук

Конфигурация хука состоит из трёх уровней:

1. **Событие (hook event)** — точка жизненного цикла (например, `PreToolUse`)
2. **Матчер (matcher)** — фильтр, какие события его вызывают
3. **Обработчик (hook handler)** — что выполняется

### Пример: уведомление, когда Claude ждёт ввод

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude Code needs your attention\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}
```

### Ключевые события жизненного цикла

|Событие|Когда срабатывает|
|---|---|
|`SessionStart`|При старте или возобновлении сессии|
|`UserPromptSubmit`|При отправке промпта, до обработки Claude|
|`PreToolUse`|Перед вызовом инструмента (можно заблокировать)|
|`PermissionRequest`|Когда нужно решение о разрешении|
|`PostToolUse`|После успешного вызова инструмента|
|`PostToolUseFailure`|После неудачного вызова инструмента|
|`Notification`|Когда Claude Code отправляет уведомление|
|`SubagentStart` / `SubagentStop`|При запуске/завершении сабагента|
|`Stop`|Когда Claude завершил ответ|
|`PreCompact` / `PostCompact`|До/после компакции контекста|
|`SessionEnd`|При завершении сессии|
|`FileChanged`|Когда отслеживаемый файл изменился на диске|
|`ConfigChange`|Когда конфигурационный файл изменился во время сессии|

> [!note] Полный список событий 
> Всего в Claude Code свыше 30 событий хуков (включая `PostToolBatch`, `WorktreeCreate/Remove`, `Elicitation`, `TeammateIdle` и др.) — см. [справочник hooks](https://code.claude.com/docs/en/hooks).

### Типы обработчиков

- **`"type": "command"`** (по умолчанию) — выполняет shell-команду
- **`"type": "http"`** — POST-запрос с данными события на URL
- **`"type": "mcp_tool"`** — вызов инструмента уже подключённого MCP-сервера
- **`"type": "prompt"`** — однократная оценка через LLM (по умолчанию Haiku) для решений, требующих суждения, а не жёстких правил
- **`"type": "agent"`** — многоходовая проверка с доступом к инструментам (экспериментально)

### Коды выхода и вывод

- **Exit 0** — хук не возражает; для `PreToolUse` это **не** равно одобрению — применяется обычный процесс разрешений
- **Exit 2** — Claude Code блокирует действие; причина пишется в stderr и (в зависимости от события) передаётся Claude как обратная связь
- **Любой другой код** + валидный JSON на stdout — структурированное решение (`permissionDecision: "allow"/"deny"/"ask"`, `additionalContext` и т.д.)

### Где регистрировать хуки

|Расположение|Область|Возможность шаринга|
|---|---|---|
|`~/.claude/settings.json`|Все ваши проекты|Нет, локально|
|`.claude/settings.json`|Один проект|Да, коммитится в репозиторий|
|`.claude/settings.local.json`|Один проект|Нет, гитигнорится|
|Managed policy|Вся организация|Да, управляется админом|
|Plugin `hooks/hooks.json`|Пока плагин включён|Да, в составе плагина|
|Skill / Subagent frontmatter|Пока активен скилл/сабагент|Да, в файле скилла/сабагента|

### Пример: блокировка правок защищённых файлов

```bash
#!/bin/bash
# protect-files.sh
INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
PROTECTED_PATTERNS=(".env" "package-lock.json" ".git/")

for pattern in "${PROTECTED_PATTERNS[@]}"; do
  if [[ "$FILE_PATH" == *"$pattern"* ]]; then
    echo "Blocked: $FILE_PATH matches protected pattern '$pattern'" >&2
    exit 2
  fi
done
exit 0
```

Регистрируется на событие `PreToolUse` с матчером `"Edit|Write"`.

## 👥 Subagents (сабагенты)

> [!quote] Определение 
> Subagents — специализированные ИИ-помощники для конкретных типов задач. Каждый работает в собственном контекстном окне со своим системным промптом, набором инструментов и независимыми разрешениями.

> [!tip] Когда использовать сабагента 
> Используйте сабагента, когда побочная задача "затопит" основной диалог результатами поиска, логами или содержимым файлов, на которые вы больше не будете ссылаться — сабагент выполняет эту работу в своём контексте и возвращает только резюме.

### Встроенные сабагенты

|Сабагент|Модель|Инструменты|Назначение|
|---|---|---|---|
|**Explore**|Наследует от основной сессии (ограничена Opus)|Только для чтения|Быстрый поиск и анализ кодовой базы|
|**Plan**|Наследует|Только для чтения|Исследование кода перед составлением плана (режим plan)|
|**general-purpose**|Наследует|Все инструменты, доступные сабагентам|Сложные многошаговые задачи с исследованием и изменениями|

> [!note] Explore и Plan 
> Эти два сабагента **пропускают** CLAUDE.md и git-статус родительской сессии, чтобы исследование было быстрым и дешёвым. Остальные сабагенты (встроенные и кастомные) загружают оба.

### Создание кастомного сабагента

Сабагенты — markdown-файлы с YAML frontmatter:

```markdown
---
name: code-reviewer
description: Проверяет код на качество и best practices
tools: Read, Grep, Glob
model: sonnet
---

You are a code reviewer. When invoked, analyze the code and provide
specific, actionable feedback on quality, security, and best practices.
```

### Где хранятся сабагенты

|Расположение|Область|Приоритет|
|---|---|---|
|Managed settings|Вся организация|1 (высший)|
|`--agents` CLI-флаг|Текущая сессия|2|
|`.claude/agents/`|Текущий проект|3|
|`~/.claude/agents/`|Все ваши проекты|4|
|Plugin `agents/`|Где включён плагин|5 (низший)|

### Основные поля frontmatter

|Поле|Обязательно|Описание|
|---|---|---|
|`name`|Да|Уникальный идентификатор (строчные буквы и дефисы)|
|`description`|Да|Когда Claude должен делегировать задачу этому сабагенту|
|`tools`|Нет|Разрешённые инструменты (allowlist); без поля — наследует все|
|`disallowedTools`|Нет|Запрещённые инструменты (denylist)|
|`model`|Нет|`sonnet`, `opus`, `haiku`, `fable`, полный ID или `inherit` (по умолчанию)|
|`permissionMode`|Нет|Режим разрешений для сабагента|
|`skills`|Нет|Скиллы, предзагружаемые в контекст сабагента при старте|
|`mcpServers`|Нет|MCP-серверы, доступные только этому сабагенту|
|`memory`|Нет|Область постоянной памяти: `user`, `project` или `local`|
|`isolation`|Нет|`worktree` — запуск в изолированной копии репозитория|

### Способы вызова сабагента

1. **Естественный язык** — упомяните имя сабагента в промпте, Claude решает, делегировать ли задачу
2. **@-упоминание** — `@"code-reviewer (agent)" посмотри изменения` — гарантирует запуск именно этого сабагента
3. **Вся сессия как сабагент** — флаг `claude --agent code-reviewer` заменяет системный промпт целиком

### Foreground / background

- **Foreground** — блокирует основной диалог до завершения; запросы разрешений передаются вам напрямую
- **Background** — работает параллельно, пока вы продолжаете работу; запросы разрешений всплывают в основной сессии с указанием, какой сабагент их запрашивает

### Fork (форк) — особый вид сабагента

**Fork** наследует **весь** диалог целиком, в отличие от обычного сабагента, стартующего "с нуля". Запускается командой `/subtask <задача>`:

```text
/subtask draft unit tests for the parser changes so far
```

### Постоянная память сабагента

Поле `memory` даёт сабагенту директорию, которая переживает сессии (накопление паттернов, архитектурных решений):

|Область|Расположение|Когда использовать|
|---|---|---|
|`user`|`~/.claude/agent-memory/<agent>/`|Знания применимы ко всем проектам|
|`project`|`.claude/agent-memory/<agent>/`|Знания специфичны для проекта, шарятся через VCS|
|`local`|`.claude/agent-memory-local/<agent>/`|Специфично для проекта, но не коммитится|

### Вложенность сабагентов

По умолчанию сабагент может порождать собственных сабагентов до **3 уровней** вглубь от основной сессии (настраивается через `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`). Одновременно может работать до **20 сабагентов** (настраивается через `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`).

## 🔌 MCP servers

> [!quote] Определение 
> **Model Context Protocol (MCP)** — открытый стандарт, позволяющий Claude Code использовать инструменты сверх встроенного набора: поиск в трекере задач, запросы к базе данных, управление браузером и т.д. Эти инструменты предоставляют **MCP-серверы**, работающие локально или как размещённые сервисы.

### Быстрый старт

```bash
# Добавить HTTP-сервер
claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp

# Проверить статус подключения
claude mcp list

# Удалить сервер
claude mcp remove claude-code-docs
```

### Статусы подключения

|Статус|Значение|
|---|---|
|`✔ Connected`|Готов к использованию|
|`! Connected · tools fetch failed`|Подключился, но не смог получить список инструментов|
|`! Needs authentication`|Требуется вход через браузер или токен|
|`✘ Failed to connect`|Сервер не ответил|
|`⏸ Pending approval`|Проектный сервер ожидает вашего подтверждения|

### Типы транспорта

|Транспорт|Когда использовать|Пример команды|
|---|---|---|
|**stdio** (локальный)|Программа-процесс на вашей машине (доступ к браузеру, ФС, БД)|`claude mcp add playwright -- npx -y @playwright/mcp@latest`|
|**HTTP**|Размещённый сервис по URL|`claude mcp add --transport http sentry https://mcp.sentry.dev/mcp`|
|**SSE**|Потоковый размещённый сервис|аналогично HTTP с `--transport sse`|
|**WebSocket**|Двунаправленное соединение|`--transport ws`|

### Области видимости (scope)

|Scope|Файл|Доступно|
|---|---|---|
|**local** (по умолчанию)|`~/.claude.json`, запись для проекта|Только вам, только в этом проекте|
|**project**|`.mcp.json` в корне проекта|Всем, кто клонирует проект (коммитится в VCS)|
|**user**|`~/.claude.json`, ключ `mcpServers`|Только вам, во всех проектах|

### Формат `.mcp.json`

```json
{
  "mcpServers": {
    "claude-code-docs": {
      "type": "http",
      "url": "https://code.claude.com/docs/mcp"
    },
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}
```

> [!warning] Безопасность 
> При первом обнаружении проектного MCP-сервера (из `.mcp.json`) Claude Code запросит подтверждение — это защита от того, что клонированный репозиторий сможет запускать процессы на вашей машине без согласия.

### Аутентификация

Сервисы вроде Sentry, Linear, Notion работают через OAuth: вы добавляете URL сервера, затем входите через браузер командой `/mcp` внутри сессии → выбор сервера → `Authenticate`. Серверы со статическим токеном принимают его через `--header "Authorization: Bearer <token>"`.

### MCP внутри сабагентов

Поле `mcpServers` в конфигурации сабагента ([[#👥 Subagents (сабагенты)]]) позволяет дать серверу доступ только конкретному сабагенту — не тратя контекст основного диалога на описания его инструментов:

```yaml
---
name: browser-tester
mcpServers:
  - playwright:
      type: stdio
      command: npx
      args: ["-y", "@playwright/mcp@latest"]
  - github
---
```

### MCP Tool Search

Механизм экономии контекста: при старте загружаются только имена инструментов и инструкции сервера, а полная схема инструмента подгружается по требованию — это не даёт неактивным MCP-серверам съедать контекст впустую.

## 🔐 Permissions, режимы и безопасность

> [!quote] Кратко 
> Permission mode — базовое поведение подтверждения действий на сессию; 
> Permission rule — точечная настройка разрешения/запрета конкретного инструмента.

### Режимы разрешений

|Режим|Поведение|
|---|---|
|`default` (Manual)|Запрашивает разрешение на каждое действие|
|`acceptEdits`|Автоматически принимает правки файлов и типовые команды ФС|
|`auto`|Отдельная модель-классификатор проверяет действия вместо вас (старт по умолчанию на Pro/Max/Team)|
|`dontAsk`|Автоматически отклоняет запросы разрешений|
|`bypassPermissions`|Пропускает все запросы разрешений (использовать с осторожностью)|
|`plan`|Режим планирования — только чтение и исследование|

### Sandboxing (песочница)

Изоляция файловой системы и сети на уровне ОС для инструмента Bash — отдельный слой поверх правил разрешений: команды выполняются внутри заранее заданной границы, что позволяет Claude работать без запроса подтверждения на каждую команду.

### Prompt injection (промпт-инъекция)

Враждебные инструкции, встроенные в файл, веб-страницу или результат инструмента, пытающиеся перенаправить Claude на нежелательные действия. Защита включает систему разрешений, обнаружение command injection и верификацию доверия; auto mode дополнительно сканирует результаты инструментов на подозрительный контент.

## 🧰 Plugins

> [!quote] Определение 
> Plugin — набор скиллов, хуков, сабагентов и MCP-серверов, упакованный как единый устанавливаемый модуль. Распространяются через **marketplace** (например, официальный `claude-plugins-official`).

```text
/plugin install skill-creator@claude-plugins-official
/plugin marketplace add anthropics/claude-plugins-official
```

Скиллы плагина используют пространство имён `plugin-name:skill-name`, поэтому не конфликтуют с локальными скиллами того же имени.
