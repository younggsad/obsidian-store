# ЧАСТЬ 1. ТИПЫ ДАННЫХ

## 1.1 Общая классификация — примитивы vs объекты

В JavaScript все значения делятся на две большие категории:

**Примитивы (primitive types)** — хранятся **по значению**, неизменяемы (immutable):

```
number, string, boolean, undefined, null, symbol, bigint
```

**Объекты (reference types)** — хранятся **по ссылке**, изменяемы (mutable):

```
Object, Array, Function, Date, Map, Set, RegExp и т.д.
```

Это разделение мы уже разбирали на практике (сравнение `obj1 === obj2`) — тут собираем полную картину.

## 1.2 Примитивные типы подробно

### `number`

```javascript
const int = 42;
const float = 3.14;
const negative = -10;
const infinity = Infinity;
const notANumber = NaN;
const hex = 0xff;        // 255 — шестнадцатеричная запись
const binary = 0b1010;    // 10 — двоичная запись
```

**Особенности:**

- Единый тип для целых и дробных чисел (в отличие от языков с раздельными `int`/`float`).
- Хранится по стандарту IEEE 754 (64-битное число с плавающей точкой) — отсюда классическая проблема:

```javascript
console.log(0.1 + 0.2); // 0.30000000000000004 — из-за особенностей двоичного представления дробей
```

- `NaN` — специальное значение "не число", результат некорректной математической операции. `NaN !== NaN` — единственное значение, не равное самому себе. Проверка: `Number.isNaN(x)`.
- `Number.MAX_SAFE_INTEGER` (2^53 - 1) — граница, до которой целые числа гарантированно точно представимы.

### `bigint` — для чисел за пределами безопасного диапазона

```javascript
const big = 123456789012345678901234567890n; // n на конце — литерал BigInt
const big2 = BigInt("123456789012345678901234567890");
console.log(typeof big); // "bigint"
```

Отдельный тип, появился в ES2020 — позволяет работать с целыми числами произвольной точности, где `number` уже теряет точность.

### `string`

```javascript
const s1 = 'одинарные';
const s2 = "двойные";
const s3 = `шаблонные ${s1}`; // с интерполяцией и многострочностью
```

Строки **иммутабельны** — методы вроде `.toUpperCase()` не меняют исходную строку, а возвращают новую.

### `boolean`

```javascript
const isActive = true;
const isDeleted = false;
```

### `undefined` vs `null` — важное различие

```javascript
let a;              // undefined — переменная объявлена, но значение не присвоено (авто-значение)
let b = null;         // null — переменная ЯВНО присвоена "пустому" значению разработчиком
```

- `undefined` — то, что JS даёт "сам", когда значения физически ещё/уже нет (необъявленный параметр функции, отсутствующее свойство объекта, функция без `return`).
- `null` — то, что разработчик **осознанно** присваивает, чтобы явно сказать "здесь намеренно нет значения".
- `typeof undefined` → `"undefined"`; `typeof null` → `"object"` (это исторический баг языка, сохранённый ради обратной совместимости — на самом деле `null` не является объектом).
- `null == undefined` → `true` (единственное исключение нестрогого сравнения); `null === undefined` → `false`.

### `symbol`

```javascript
const sym1 = Symbol("описание");
const sym2 = Symbol("описание");
console.log(sym1 === sym2); // false — КАЖДЫЙ Symbol уникален, даже с одинаковым описанием
```

Уникальный, неизменяемый примитив — часто используется как "скрытый" ключ свойства объекта (разбирали в теме инкапсуляции).

## 1.3 Проверка типа — `typeof` и его ловушки

```javascript
typeof 42;            // "number"
typeof "текст";         // "string"
typeof true;              // "boolean"
typeof undefined;           // "undefined"
typeof null;                  // "object" — историческая ошибка языка!
typeof Symbol();                // "symbol"
typeof 10n;                       // "bigint"
typeof {};                          // "object"
typeof [];                            // "object" — массивы ТОЖЕ object!
typeof function(){};                    // "function" — единственное исключение, функции имеют собственный typeof
```

**Для проверки массива** используют не `typeof`, а специальный метод:

```javascript
Array.isArray([]);   // true
Array.isArray({});    // false
```

## 1.4 Приведение типов (Type Coercion)

Разбирали ранее на практике — краткое обобщение правил:

```javascript
// К строке — если хотя бы один операнд строка при +
1 + "1"        // "11"
"5" + 2         // "52"

// К числу — во всех остальных арифметических операциях
"5" - 2          // 3
"5" * "2"          // 10
true + true          // 2 (true → 1, false → 0)

// Явное приведение
Number("42")            // 42
String(42)                // "42"
Boolean(0)                  // false
Boolean("")                   // false
Boolean(null)                   // false
Boolean(undefined)                // false
Boolean(NaN)                        // false
Boolean("0")                          // true! (непустая строка — всегда truthy)
Boolean([])                             // true! (пустой массив/объект — truthy, в отличие от многих других языков)
Boolean({})                               // true!
```

**Falsy-значения (единственные, приводящиеся к `false`):** `false`, `0`, `-0`, `""`, `null`, `undefined`, `NaN`. **Всё остальное** — truthy, включая пустой массив и пустой объект — частая ловушка для новичков, приходящих из других языков.

## 1.5 Сравнение типов — глубокое понимание `==` vs `===`

Разбирали практически ранее. Правило: `===` не приводит типы вообще, сравнивает как есть. `==` сначала приводит типы к общему виду, потом сравнивает — из-за этого возникают неочевидные результаты (`"" == 0` → `true`, `[] == false` → `true`).

**Практическая рекомендация:** использовать `===`/`!==` **всегда**, кроме единственного осознанного случая — проверки `x == null` (которая одновременно ловит и `null`, и `undefined` благодаря особому правилу равенства между ними).

# ЧАСТЬ 2. РАБОТА С МАССИВАМИ

## 2.1 Создание и базовые операции

```javascript
const arr1 = [1, 2, 3];
const arr2 = new Array(1, 2, 3);      // тот же результат, но реже используется
const arr3 = Array.from({ length: 5 }, (_, i) => i * 2); // [0, 2, 4, 6, 8] — создание с генерацией
const arr4 = Array.of(7);                // [7] — в отличие от new Array(7), который создаёт МАССИВ ИЗ 7 ПУСТЫХ ЯЧЕЕК!
```

⚠️ **Ловушка `new Array(n)`:**

```javascript
new Array(3)     // [ <3 empty items> ] — массив с тремя "дырами", а НЕ [3]!
Array.of(3)        // [3] — именно массив с одним элементом
```

## 2.2 Методы, изменяющие исходный массив (мутирующие)

```javascript
const arr = [1, 2, 3];

arr.push(4);         // добавить в конец → [1,2,3,4], возвращает НОВУЮ длину
arr.pop();              // удалить с конца → [1,2,3], возвращает УДАЛЁННЫЙ элемент
arr.unshift(0);           // добавить в начало → [0,1,2,3]
arr.shift();                 // удалить с начала → [1,2,3]
arr.splice(1, 1, "x", "y");    // с индекса 1 удалить 1 элемент, вставить "x","y" → [1,"x","y",3]
arr.sort();                       // сортирует НА МЕСТЕ (по умолчанию — как строки!)
arr.reverse();                       // разворачивает НА МЕСТЕ
```

⚠️ **`sort()` без компаратора сортирует как строки**, даже для чисел:

```javascript
[10, 1, 21, 2].sort();               // [1, 10, 2, 21] — НЕ числовой порядок!
[10, 1, 21, 2].sort((a, b) => a - b); // [1, 2, 10, 21] — правильно, с компаратором
```

## 2.3 Методы, НЕ изменяющие исходный массив (создают новый)

```javascript
const arr = [1, 2, 3, 4, 5];

arr.slice(1, 3);        // [2, 3] — вырезка (НЕ путать с splice, который мутирует)
arr.concat([6, 7]);       // [1,2,3,4,5,6,7] — объединение (то же самое делает [...arr, 6, 7])
arr.join(", ");              // "1, 2, 3, 4, 5" — в строку
arr.includes(3);                // true — проверка наличия
arr.indexOf(3);                    // 2 — индекс элемента (-1, если нет)
arr.lastIndexOf(3);                   // индекс с конца
```

## 2.4 Методы высшего порядка (принимают callback)

```javascript
const numbers = [1, 2, 3, 4, 5];

numbers.forEach((n) => console.log(n));           // просто перебор, ничего не возвращает

numbers.map((n) => n * 2);                          // [2,4,6,8,10] — НОВЫЙ массив той же длины

numbers.filter((n) => n % 2 === 0);                    // [2,4] — НОВЫЙ массив, только подходящие

numbers.reduce((acc, n) => acc + n, 0);                   // 15 — сводит к одному значению

numbers.find((n) => n > 3);                                 // 4 — ПЕРВЫЙ подходящий элемент (значение)
numbers.findIndex((n) => n > 3);                               // 3 — ИНДЕКС первого подходящего
numbers.findLast((n) => n > 3);                                   // 5 — последний подходящий (ES2023)

numbers.some((n) => n > 4);                                          // true — есть ли ХОТЯ БЫ ОДИН подходящий
numbers.every((n) => n > 0);                                            // true — ВСЕ ли подходят

numbers.flatMap((n) => [n, n * 2]);                                        // map + flat(1) за один проход
[[1, 2], [3, [4, 5]]].flat();                                                 // [1, 2, 3, [4, 5]] — разворот на 1 уровень
[[1, 2], [3, [4, 5]]].flat(Infinity);                                            // [1, 2, 3, 4, 5] — на все уровни
```

**Различие `map` vs `forEach`:** `map` возвращает новый массив с результатами callback, `forEach` — всегда `undefined`, используется только ради побочных эффектов (например, логирования). Частая ошибка — использовать `map`, когда на деле нужен `forEach` (или наоборот — пытаться "накопить" что-то через `forEach`, хотя для этого создан `reduce`/`map`).

## 2.5 Деструктуризация и spread для массивов

```javascript
const [first, second, ...rest] = [1, 2, 3, 4, 5];
// first = 1, second = 2, rest = [3, 4, 5]

const [, , third] = [1, 2, 3]; // пропуск элементов через запятые

const combined = [...arr1, ...arr2]; // объединение через spread
const copy = [...arr1];                // поверхностная копия
```

## 2.6 Проверка на равенство массивов — частая ловушка

```javascript
console.log([1, 2] === [1, 2]); // false! Разные объекты в памяти, даже с одинаковым содержимым
```

Правильное сравнение содержимого — поэлементно или через `JSON.stringify` (с оговорками про порядок ключей для вложенных объектов) либо специальные библиотеки (`lodash.isEqual`).

# ЧАСТЬ 3. РАБОТА С ОБЪЕКТАМИ

## 3.1 Создание и базовые операции

```javascript
const obj = { name: "Аня", age: 20 };

obj.city = "Москва";           // добавить свойство
delete obj.age;                  // удалить свойство
console.log("name" in obj);         // true — проверка наличия ключа (включая унаследованные из прототипа!)
console.log(obj.hasOwnProperty("name")); // true — проверка ТОЛЬКО собственных свойств
```

## 3.2 Динамический доступ через скобочную нотацию

```javascript
const key = "name";
console.log(obj[key]);          // "Аня" — доступ через переменную, точечная нотация так не может
console.log(obj["name"]);         // то же самое, явной строкой
```

## 3.3 Перебор свойств объекта

```javascript
const obj = { a: 1, b: 2, c: 3 };

for (const key in obj) {
  console.log(key, obj[key]);
}
// Важно: for...in перебирает и УНАСЛЕДОВАННЫЕ enumerable-свойства из прототипа —
// на практике часто добавляют проверку obj.hasOwnProperty(key)

Object.keys(obj);      // ["a", "b", "c"] — массив ключей (только собственные)
Object.values(obj);       // [1, 2, 3] — массив значений
Object.entries(obj);         // [["a",1],["b",2],["c",3]] — пары [ключ, значение]

Object.entries(obj).forEach(([key, value]) => console.log(key, value));
```

## 3.4 Копирование и объединение объектов

```javascript
const obj1 = { a: 1, b: 2 };
const obj2 = { b: 3, c: 4 };

const merged = { ...obj1, ...obj2 };            // { a:1, b:3, c:4 } — spread, свойства позже перезаписывают ранние
const merged2 = Object.assign({}, obj1, obj2);    // тот же результат, старый способ до spread

const shallowCopy = { ...obj1 };                    // ПОВЕРХНОСТНАЯ копия — только 1 уровень вложенности
```

⚠️ **Проблема поверхностного копирования (shallow copy) с вложенными объектами:**

```javascript
const original = { user: { name: "Аня" } };
const copy = { ...original };
copy.user.name = "Максим";
console.log(original.user.name); // "Максим" — ИЗМЕНИЛОСЬ! Вложенный объект скопирован ПО ССЫЛКЕ
```

Spread копирует только "верхний уровень" — вложенные объекты/массивы всё ещё общие по ссылке между оригиналом и копией. Для **глубокого копирования (deep copy)**:

```javascript
const deepCopy = structuredClone(original); // современный встроенный способ (не работает с функциями)
const deepCopy2 = JSON.parse(JSON.stringify(original)); // старый способ, ломается на Date/undefined/функциях/циклических ссылках
```

## 3.5 Заморозка и запечатывание объектов

```javascript
const obj = { a: 1 };

Object.freeze(obj);       // ПОЛНАЯ заморозка — нельзя менять, добавлять, удалять свойства (в нестрогом режиме — тихо игнорируется)
obj.a = 2;                    // не сработает
console.log(obj.a);              // всё ещё 1

Object.seal(obj);                  // можно МЕНЯТЬ существующие свойства, но НЕЛЬЗЯ добавлять/удалять
Object.preventExtensions(obj);       // нельзя ДОБАВЛЯТЬ новые свойства, но можно менять/удалять существующие
```

⚠️ `Object.freeze` — **неглубокая (shallow)** заморозка: вложенные объекты внутри замороженного объекта остаются изменяемыми, если явно не заморозить их тоже, рекурсивно.

## 3.6 Геттеры/сеттеры и `Object.defineProperty`

```javascript
const obj = {
  _value: 10,
  get value() { return this._value; },
  set value(v) { this._value = v * 2; }
};

Object.defineProperty(obj, 'readonly', {
  value: 42,
  writable: false,       // нельзя изменить значение
  enumerable: false,        // не появится в for...in / Object.keys
  configurable: false,         // нельзя удалить или переконфигурировать свойство
});
```

Это низкоуровневый способ настроить поведение свойства гораздо более гибко, чем обычное присваивание — используется, например, во внутренней реализации библиотек, при создании "скрытых" служебных свойств.

## 3.7 Object vs Map — когда что использовать

```javascript
const map = new Map();
map.set("key1", "value1");
map.set(42, "числовой ключ");            // ключом может быть ЛЮБОЙ тип, не только строка
map.get("key1");                            // "value1"
map.has("key1");                              // true
map.delete("key1");
map.size;                                        // количество элементов (в Object пришлось бы Object.keys(obj).length)

for (const [key, value] of map) { }              // напрямую итерируемый, в отличие от обычного объекта
```

# ЧАСТЬ 4. ПРОТОТИПЫ

_(Кратко — подробный разбор с примерами уже был в конспекте по ООП, здесь — сжатая версия для быстрого повторения перед собеседованием)_

## 4.1 Суть

У каждого объекта есть скрытая ссылка `[[Prototype]]` на другой объект. При обращении к свойству, которого нет у самого объекта, JS ищет его в прототипе, и так по цепочке — **prototype chain** — пока не дойдёт до `Object.prototype`, а затем до `null` (конец цепочки).

```javascript
const animal = { eats: true };
const rabbit = Object.create(animal);
rabbit.jumps = true;

console.log(rabbit.eats);   // true — найдено в прототипе
console.log(rabbit.jumps);   // true — собственное свойство
```

## 4.2 Способы работы с прототипами

```javascript
Object.create(proto)                     // создать объект с явным прототипом
Object.getPrototypeOf(obj)                 // получить прототип объекта
Object.setPrototypeOf(obj, proto)            // изменить прототип (медленно, не рекомендуется в проде)
obj.__proto__                                  // устаревший, но всё ещё работающий доступ к прототипу (не рекомендуется — используй getPrototypeOf)

function Animal(name) { this.name = name; }
Animal.prototype.walk = function() { console.log(`${this.name} идёт`); };  // добавить метод в ПРОТОТИП конструктора

const rex = new Animal("Рекс");
rex.walk(); // метод найден через прототип, а не создан заново для каждого экземпляра
```

## 4.3 Зачем методы кладут именно в прототип, а не в конструктор

```javascript
// ❌ Плохо — метод создаётся ЗАНОВО для каждого экземпляра (расход памяти)
function Animal(name) {
  this.name = name;
  this.walk = function() { console.log(`${this.name} идёт`); };
}

// ✅ Хорошо — ОДИН метод в памяти, используется ВСЕМИ экземплярами через прототип
function Animal(name) {
  this.name = name;
}
Animal.prototype.walk = function() { console.log(`${this.name} идёт`); };
```

## 4.4 `class` — синтаксический сахар поверх прототипов

```javascript
class Animal {
  constructor(name) { this.name = name; }
  walk() { console.log(`${this.name} идёт`); }  // автоматически кладётся в Animal.prototype
}
```

Методы, объявленные внутри `class`, автоматически попадают именно в `.prototype`, а не создаются заново на каждом экземпляре — `class` просто скрывает эту механику за более привычным синтаксисом.

## 4.5 `instanceof` — проверка через цепочку прототипов

```javascript
console.log(rex instanceof Animal); // true — Animal.prototype встречается в цепочке rex
```

# ЧАСТЬ 5. AJAX

## 5.1 Что такое AJAX

**AJAX (Asynchronous JavaScript and XML)** — техника выполнения HTTP-запросов из JavaScript **без перезагрузки всей страницы**. Название историческое — изначально данные часто передавались в формате XML, сегодня почти всегда используется **JSON**, но термин "AJAX" остался общим названием подхода.

**Суть идеи:** страница уже загружена, но приложению нужны свежие данные с сервера (или нужно отправить данные) — вместо полной перезагрузки страницы, JS-код в фоне делает HTTP-запрос, получает ответ и обновляет часть DOM, пока пользователь продолжает работать со страницей.

## 5.2 Способ 1 — XMLHttpRequest (исторический, "классический" AJAX)

```javascript
const xhr = new XMLHttpRequest();

xhr.open("GET", "/api/users/1");

xhr.onload = function() {
  if (xhr.status === 200) {
    const data = JSON.parse(xhr.responseText);
    console.log(data);
  } else {
    console.log("Ошибка:", xhr.status);
  }
};

xhr.onerror = function() {
  console.log("Сетевая ошибка");
};

xhr.send();
```

Именно `XMLHttpRequest` — объект, давший название "AJAX" технике в целом. Сегодня используется редко напрямую (громоздкий, колбэк-based синтаксис), но лежит в основе многих старых библиотек и всё ещё поддерживается всеми браузерами.

## 5.3 Способ 2 — `fetch` (современный стандарт)

```javascript
fetch("/api/users/1")
  .then((response) => {
    if (!response.ok) {
      throw new Error(`Ошибка HTTP: ${response.status}`);
    }
    return response.json(); // .json() тоже возвращает промис!
  })
  .then((data) => console.log(data))
  .catch((error) => console.log("Ошибка:", error));
```

С `async/await` (то, что уже подробно разбирали):

```javascript
async function getUser(id) {
  try {
    const response = await fetch(`/api/users/${id}`);
    if (!response.ok) {
      throw new Error(`Ошибка HTTP: ${response.status}`);
    }
    const data = await response.json();
    return data;
  } catch (error) {
    console.log("Ошибка:", error);
  }
}
```

⚠️ **Важная особенность `fetch`:** промис `fetch()` **не отклоняется (`reject`)** при HTTP-ошибках уровня `4xx`/`5xx` (`404`, `500` и т.д.) — он считается "успешно завершённым" запросом, просто с неуспешным статусом! Отклонение происходит только при **сетевых** сбоях (нет соединения, DNS не резолвится и т.д.). Именно поэтому обязательна ручная проверка `response.ok` (или `response.status`), как показано выше — иначе `404`-ответ с текстом "Not Found" тихо "проскочит" в `.then()`, как будто всё прошло успешно.

### Отправка данных через `fetch`

```javascript
fetch("/api/users", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ name: "Аня", email: "anna@test.com" }),
})
  .then((response) => response.json())
  .then((data) => console.log(data));
```

### Отмена запроса через `AbortController`

```javascript
const controller = new AbortController();

fetch("/api/data", { signal: controller.signal })
  .then((response) => response.json())
  .catch((error) => {
    if (error.name === "AbortError") {
      console.log("Запрос был отменён");
    }
  });

controller.abort(); // отменяет запрос (например, если пользователь ушёл со страницы раньше ответа)
```


## 5.4 Axios — популярная сторонняя библиотека поверх AJAX

```javascript
import axios from 'axios';

axios.get('/api/users/1')
  .then((response) => console.log(response.data)) // данные уже автоматически распарсены из JSON
  .catch((error) => console.log(error));

axios.post('/api/users', { name: 'Аня' }); // JSON.stringify делается автоматически
```

**Отличия от `fetch`:**

- Автоматически парсит JSON (не нужен отдельный `.json()`)
- Автоматически отклоняет промис (`reject`) при HTTP-ошибках `4xx`/`5xx` — не нужна ручная проверка `response.ok`
- Встроенная поддержка interceptors (перехватчиков) — удобно, например, для автоматического добавления токена авторизации ко всем запросам сразу
- Встроенная поддержка отмены запросов, таймаутов "из коробки"

## 5.5 CORS — частая проблема при AJAX-запросах на другой домен

**CORS (Cross-Origin Resource Sharing)** — механизм браузерной безопасности, ограничивающий AJAX-запросы **с одного домена на другой** (кросс-доменные), если сервер явно не разрешил это через специальные заголовки.

```http
Access-Control-Allow-Origin: https://myapp.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
```

Для "небезопасных" запросов (не `GET`/`HEAD`/простой `POST`, либо с кастомными заголовками) браузер сначала автоматически отправляет **preflight**-запрос методом `OPTIONS` — спрашивает у сервера разрешение, прежде чем отправить реальный запрос (упоминали в теме HTTP-методов).

**Важно понимать:** CORS — это ограничение **браузера**, а не сервера. Сервер физически получает и может обработать запрос с любого источника — просто браузер, если ответ не содержит нужных `Access-Control-*` заголовков, **скрывает результат от JavaScript-кода страницы**, блокируя доступ к ответу (хотя сам запрос на сервер технически может уже быть выполнен).

## 5.6 Практический пример — полный цикл AJAX-запроса с загрузкой в UI

```javascript
async function loadAndDisplayUsers() {
  const container = document.querySelector("#users-list");
  container.textContent = "Загрузка...";

  try {
    const response = await fetch("/api/users");

    if (!response.ok) {
      throw new Error(`Сервер вернул ошибку: ${response.status}`);
    }

    const users = await response.json();

    container.innerHTML = "";
    users.forEach((user) => {
      const li = document.createElement("li");
      li.textContent = user.name;
      container.appendChild(li);
    });
  } catch (error) {
    container.textContent = "Не удалось загрузить пользователей";
    console.error(error);
  }
}
```

Классический паттерн: показать индикатор загрузки → сделать запрос → обработать успех (обновить DOM) → обработать ошибку (показать сообщение) — то, что стоит за большинством динамических интерфейсов в вебе.

# ИТОГОВАЯ СВОДКА

|Тема|Ключевая мысль|
|---|---|
|Типы данных|примитивы (по значению, неизменяемы) vs объекты (по ссылке); `typeof null` === "object" — историческая ошибка; falsy-значения — всего 6|
|Массивы|мутирующие (`push`, `splice`, `sort`) vs немутирующие (`slice`, `map`, `filter`) методы; `sort()` по умолчанию сортирует как строки|
|Объекты|`Object.keys/values/entries`; spread — только поверхностное копирование; `Map` для нестроковых ключей и частых изменений|
|Прототипы|цепочка `[[Prototype]]`, методы кладут в `prototype`, а не в конструктор, чтобы не дублировать для каждого экземпляра|
|AJAX|запросы без перезагрузки страницы; `fetch` не reject-ится на HTTP-ошибках — нужна ручная проверка `response.ok`; CORS — браузерное ограничение кросс-доменных запросов|
