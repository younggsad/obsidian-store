# ЧАСТЬ 3. SEMANTIC LAYOUT (СЕМАНТИЧЕСКАЯ ВЁРСТКА)

## 3.1 Что такое семантическая вёрстка и зачем она нужна

>**Семантическая вёрстка** — использование HTML-тегов, которые своим именем **отражают смысл** содержимого, а не только его визуальное расположение. Противоположность — "div-суп" (divitis), когда вся страница собрана из безликих `<div>` и `<span>`, без какой-либо смысловой структуры.

**Зачем это важно:**

1. **Доступность (accessibility)** — скринридеры для незрячих пользователей ориентируются на семантику, чтобы озвучить структуру страницы ("это навигация", "это основной контент", "это подвал")
2. **SEO** — поисковые роботы лучше понимают, что является основным контентом, а что — второстепенным (реклама, навигация), что влияет на ранжирование
3. **Читаемость кода** — разработчику проще ориентироваться в разметке, когда теги называются по смыслу
4. **Единообразие** — меньше произвольных решений о том, как называть классы для структурных блоков

## 3.2 Семантические теги — основной набор

```html
<header>    — шапка страницы или секции (логотип, навигация, заголовок)
<nav>       — блок навигации (меню, ссылки)
<main>      — основной, уникальный контент страницы (должен быть ОДИН на странице)
<article>   — самостоятельный, независимый блок контента (статья, пост, карточка товара)
<section>   — тематический раздел страницы, обычно со своим заголовком
<aside>     — второстепенный контент (сайдбар, related-ссылки, реклама)
<footer>    — подвал страницы или секции (контакты, копирайт, ссылки)
<figure> / <figcaption> — иллюстрация с подписью
<time>      — дата/время в машиночитаемом формате
<mark>      — выделенный, подсвеченный текст (например, результат поиска)
<address>   — контактная информация
```

## 3.3 Пример полной семантической структуры страницы

```html
<body>
  <header>
    <nav>
      <a href="/">Главная</a>
      <a href="/blog">Блог</a>
      <a href="/contact">Контакты</a>
    </nav>
  </header>

  <main>
    <article>
      <header>
        <h1>Заголовок статьи</h1>
        <time datetime="2026-07-16">16 июля 2026</time>
      </header>

      <section>
        <h2>Первый раздел</h2>
        <p>Текст раздела...</p>
      </section>

      <section>
        <h2>Второй раздел</h2>
        <p>Текст раздела...</p>
      </section>

      <footer>
        <p>Автор: Аня</p>
      </footer>
    </article>

    <aside>
      <h2>Похожие статьи</h2>
      <ul>
        <li><a href="/post1">Статья 1</a></li>
      </ul>
    </aside>
  </main>

  <footer>
    <address>Контакты: info@example.com</address>
    <p>&copy; 2026 Мой сайт</p>
  </footer>
</body>
```

**Обрати внимание:** `<header>`/`<footer>` использованы дважды — один раз для всей страницы, второй раз внутри `<article>` — это допустимо, семантические теги могут повторяться в контексте разных "секций" документа, они не привязаны жёстко к странице целиком.

## 3.4 `<article>` vs `<section>` — частая путаница

- **`<article>`** — контент, который имеет смысл **сам по себе**, вне контекста остальной страницы (можно вырвать и опубликовать отдельно — пост в блоге, новость, комментарий, карточка товара)
- **`<section>`** — тематическая группировка контента **внутри** чего-то большего, обычно не имеет смысла в полном отрыве (глава книги, раздел статьи)

Правило-подсказка: если контент можно было бы целиком переиспользовать в RSS-ленте или как самостоятельный виджет — это `<article>`. Если это просто "часть" более крупного целого — `<section>`.

## 3.5 Доступность (accessibility, a11y) — тесно связано с семантикой

```html
<button aria-label="Закрыть окно">✕</button>
<img src="chart.png" alt="График роста продаж за 2026 год">
<div role="alert">Ошибка отправки формы!</div>
<nav aria-label="Основная навигация">...</nav>
```

- `alt` у `<img>` — **обязателен**, описывает изображение для скринридеров (и отображается, если картинка не загрузилась). Для чисто декоративных изображений — `alt=""` (пустой, но присутствующий атрибут).
- `aria-*` атрибуты (ARIA — Accessible Rich Internet Applications) — дополняют семантику там, где обычных тегов недостаточно (особенно в интерактивных JS-компонентах: кастомные выпадающие списки, модальные окна и т.д.)
- `role` — явно указывает роль элемента для вспомогательных технологий, когда семантика неочевидна из самого тега.

**Правило приоритета:** сначала используй нативный семантический HTML-тег (`<button>` вместо `<div onclick="...">`), и только если подходящего тега нет — добавляй ARIA-атрибуты поверх обычного `<div>`/`<span>`. Нативные теги уже имеют встроенную доступность (фокус по Tab, поведение по Enter/Space и т.д.), которую иначе пришлось бы эмулировать вручную.
