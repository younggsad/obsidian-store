# ЧАСТЬ 4. HTTPS

## 4.1 Что такое HTTPS

>**HTTPS (HTTP Secure)** — это HTTP, работающий поверх дополнительного слоя шифрования — **TLS** (Transport Layer Security, ранее — SSL, который считается устаревшим и небезопасным). Сам протокол HTTP не меняется — меняется только транспортный уровень, через который передаются данные.

## 4.2 Что именно даёт HTTPS — три ключевых свойства

1. **Шифрование (Encryption)** — данные между клиентом и сервером зашифрованы, третья сторона (например, атакующий в той же Wi-Fi сети) не может прочитать содержимое трафика, даже если перехватит его.
2. **Целостность (Integrity)** — гарантия, что данные не были изменены "по пути" между отправкой и получением (защита от атак "человек посередине" — Man-in-the-Middle).
3. **Аутентификация (Authentication)** — клиент может убедиться, что действительно общается с настоящим сервером (например, `bank.com`), а не с поддельным сайтом, притворяющимся банком — через проверку цифрового сертификата.

## 4.3 Процесс установления соединения — TLS Handshake (упрощённо)

```
1. Клиент → Серверу: "Привет, вот какие алгоритмы шифрования я поддерживаю" (Client Hello)
2. Сервер → Клиенту: "Ок, используем такой-то алгоритм, вот мой сертификат" (Server Hello + Certificate)
3. Клиент проверяет сертификат (через доверенный удостоверяющий центр — CA)
4. Клиент и сервер согласовывают общий секретный ключ (для последующего симметричного шифрования — оно быстрее, чем асимметричное)
5. Начинается зашифрованный обмен данными
```

**Ключевая деталь:** для первоначального "рукопожатия" (обмена ключами) используется **асимметричное шифрование** (публичный/приватный ключ) — оно надёжное, но медленное. После установления общего секрета обмен переключается на **симметричное шифрование** — быстрое, подходящее для передачи больших объёмов данных.

## 4.4 SSL/TLS-сертификаты

>**Сертификат** — цифровой документ, подтверждающий, что публичный ключ действительно принадлежит указанному домену, выданный **удостоверяющим центром (Certificate Authority, CA)** — доверенной третьей стороной (например, Let's Encrypt, DigiCert).

```
Браузер доверяет CA → CA подписал сертификат сайта → Браузер, видя подпись CA, доверяет и сайту
```

Если сертификат просрочен, выдан для другого домена, или подписан неизвестным CA — браузер показывает предупреждение "Соединение не защищено" вместо тихого пропуска.

**Let's Encrypt** — популярный бесплатный CA, значительно упростивший массовое внедрение HTTPS благодаря автоматизации выпуска и обновления сертификатов.

## 4.5 HTTP vs HTTPS — на уровне URL

```
http://example.com   — порт по умолчанию 80, без шифрования
https://example.com   — порт по умолчанию 443, с TLS-шифрованием
```

## 4.6 Зачем HTTPS нужен даже "не для банков"

- **SEO** — поисковые системы (Google) понижают в выдаче сайты без HTTPS
- **Доверие пользователей** — браузеры явно помечают HTTP-сайты как "Небезопасно" в адресной строке
- **Обязательное требование** для многих современных Web API (Service Workers, геолокация, доступ к камере/микрофону работают только на HTTPS, кроме localhost)
- **Защита от подмены контента** провайдерами/прокси по пути (например, внедрение рекламы в незашифрованный HTTP-трафик)

## 4.7 HSTS (HTTP Strict Transport Security)

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

Заголовок, который сервер отправляет клиенту, чтобы браузер **запомнил** — этот сайт должен посещаться **только** через HTTPS, и автоматически переводил бы даже случайные `http://` запросы в `https://` **до** отправки на сервер (защита от атак понижения протокола — SSL stripping).
