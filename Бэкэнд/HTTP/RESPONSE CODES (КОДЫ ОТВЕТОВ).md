# ЧАСТЬ 3. RESPONSE CODES (КОДЫ ОТВЕТОВ)

## 3.1 Общая классификация — пять групп

|Диапазон|Категория|Смысл|
|---|---|---|
|1xx|Informational|информационные, промежуточные|
|2xx|Success|запрос успешно обработан|
|3xx|Redirection|нужно дополнительное действие (обычно переход на другой URL)|
|4xx|Client Error|ошибка на стороне клиента (неправильный запрос)|
|5xx|Server Error|ошибка на стороне сервера|

## 3.2 1xx — Informational

```
— сервер получил заголовки, клиент может продолжать отправку тела запроса
100 Continue         

— сервер соглашается сменить протокол (например, при апгрейде до WebSocket)
101 Switching Protocols 
```

## 3.3 2xx — Success

```
— стандартный успешный ответ
200 OK                

— ресурс успешно создан (типичный ответ на POST); часто содержит заголовок Location с адресом нового ресурса
201 Created   

— запрос принят к обработке, но обработка ещё не завершена (для асинхронных операций)           
202 Accepted  

— успешно, но тело ответа пустое (типично для DELETE — удалили, возвращать нечего)            
204 No Content               
```

## 3.4 3xx — Redirection

```
— ресурс НАВСЕГДА перемещён на новый URL; поисковики обновляют индекс, браузеры кэшируют редирект
301 Moved Permanently   

— ресурс ВРЕМЕННО находится по другому URL; не должен кэшироваться так же агрессивно, как 301
302 Found        

 — ресурс не изменился с последнего запроса (используется с кэшированием — If-None-Match/If-Modified-Since); тело ответа пустое, браузер использует кэшированную версию         
304 Not Modified   

— как 302, но ГАРАНТИРУЕТ сохранение исходного метода запроса при редиректе (302 исторически допускал смену POST → GET у некоторых клиентов)   
307 Temporary Redirect        

— как 301, но с той же гарантией сохранения метода, что и 307
308 Permanent Redirect          
```

⚠️ **301 vs 302 — частый вопрос:** `301` говорит "переезжай навсегда, обнови закладки/индекс", `302` — "сходи туда один раз, но адрес остаётся прежним". Использование не того кода может навредить SEO (например, `302` вместо `301` при постоянном переезде страницы не передаёт "вес" ссылки новому адресу так же эффективно).

## 3.5 4xx — Client Error

```
— сервер не может обработать запрос из-за ошибки клиента (некорректный синтаксис, невалидные данные)
400 Bad Request            

— клиент НЕ аутентифицирован (несмотря на название "Unauthorized" — по факту это про ОТСУТСТВИЕ или невалидность учётных данных, а не про права доступа)
401 Unauthorized  

— клиент аутентифицирован, но у него НЕТ ПРАВ на этот ресурс (в отличие от 401 — сервер точно знает, кто ты, но не пускает)            
403 Forbidden  

— ресурс не найден                  
404 Not Found    

— метод (например, DELETE) не поддерживается для этого ресурса                   
405 Method Not Allowed     

— конфликт состояния (например, попытка создать пользователя с уже существующим email)            
409 Conflict          

— запрос синтаксически корректен, но семантически невалиден (например, не прошла бизнес-валидация полей)                    
422 Unprocessable Entity   

— превышен лимит запросов (rate limiting)
429 Too Many Requests                           
```

⚠️ **401 vs 403 — частый вопрос на собеседовании:** `401` — "я не знаю, кто ты, представься" (нет токена/сессии или он невалиден); `403` — "я знаю, кто ты, но тебе сюда нельзя" (прав недостаточно, даже если аутентификация прошла успешно).

## 3.6 5xx — Server Error

```
 — общая, неспецифическая ошибка на сервере (что-то сломалось, но конкретика не раскрывается клиенту из соображений безопасности)
500 Internal Server Error   

— сервер, выступающий как шлюз/прокси, получил невалидный ответ от вышестоящего сервера
502 Bad Gateway                 

— сервер временно не может обработать запрос (перегрузка, техобслуживание) — часто с заголовком Retry-After
503 Service Unavailable    

— шлюз/прокси не дождался ответа от вышестоящего сервера за отведённое время        
504 Gateway Timeout                   
```

## 3.7 Практическая шпаргалка — как быстро определить категорию

```
1xx → "Погоди, ещё не всё"
2xx → "Всё хорошо"
3xx → "Иди туда-то"
4xx → "Ты сделал что-то не так" (клиент)
5xx → "Мы сделали что-то не так" (сервер)
```
