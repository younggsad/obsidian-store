# ЧАСТЬ 1. HTTP BASICS

## 1.1 Что такое HTTP

>**HTTP (HyperText Transfer Protocol)** — протокол прикладного уровня, определяющий формат обмена сообщениями между клиентом (браузером) и сервером. Это основа передачи данных в вебе — на нём построены запросы страниц, API, загрузка файлов и т.д.

**Ключевые характеристики HTTP:**

- **Клиент-серверная модель** — клиент всегда инициирует запрос, сервер отвечает. Сервер не может сам "постучаться" к клиенту без предварительного запроса (для этого есть отдельные механизмы — WebSocket, Server-Sent Events, long polling).
- **Stateless (без сохранения состояния)** — каждый HTTP-запрос независим и не "помнит" ничего о предыдущих запросах. Сервер не хранит автоматически информацию о том, кто и что запрашивал раньше — для этого используются дополнительные механизмы (cookie, токены, сессии — см. Часть 5).
- **Текстовый протокол** (в HTTP/1.1) — запросы и ответы читаемы в текстовом виде (хотя HTTP/2 и HTTP/3 используют бинарную передачу для эффективности, но логическая структура сообщений сохраняется).

## 1.2 Структура HTTP-запроса

```http
GET /api/users/1 HTTP/1.1
Host: example.com
Accept: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
User-Agent: Mozilla/5.0
```

**Части запроса:**

1. **Стартовая строка** — метод (`GET`), путь (`/api/users/1`), версия протокола (`HTTP/1.1`)
2. **Заголовки (headers)** — метаданные о запросе (формат, авторизация, тип клиента и т.д.)
3. **Пустая строка** — разделитель между заголовками и телом
4. **Тело (body)** — данные запроса (для `GET` обычно отсутствует, для `POST`/`PUT` содержит передаваемые данные)

```http
POST /api/users HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: 38

{"name": "Аня", "email": "anna@test.com"}
```

## 1.3 Структура HTTP-ответа

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 58
Cache-Control: no-cache

{"id": 1, "name": "Аня", "email": "anna@test.com"}
```

**Части ответа:**

1. **Статусная строка** — версия протокола, код статуса (`200`), текстовое пояснение (`OK`)
2. **Заголовки ответа** — метаданные о содержимом (тип, длина, кэширование и т.д.)
3. **Пустая строка**
4. **Тело ответа** — фактические данные (HTML-страница, JSON, файл и т.д.)

## 1.4 Основные заголовки (headers) — обзор

|Заголовок|Назначение|
|---|---|
|`Content-Type`|формат тела запроса/ответа (`application/json`, `text/html`, `multipart/form-data`)|
|`Content-Length`|размер тела в байтах|
|`Authorization`|учётные данные для аутентификации (`Bearer <token>`, `Basic <base64>`)|
|`User-Agent`|информация о клиенте (браузер, ОС)|
|`Accept`|какие форматы ответа клиент готов принять|
|`Cache-Control`|правила кэширования (`no-cache`, `max-age=3600`)|
|`Cookie` / `Set-Cookie`|передача/установка cookie (подробнее в Части 5)|
|`Host`|доменное имя сервера (обязателен в HTTP/1.1, так как один IP может обслуживать много доменов)|
|`Referer`|URL страницы, с которой был сделан переход/запрос|
|`Origin`|источник запроса — важен для CORS-проверок|

## 1.5 Версии HTTP (кратко)

|Версия|Особенность|
|---|---|
|HTTP/1.0|одно соединение на один запрос-ответ, закрывается после каждого|
|HTTP/1.1|постоянные соединения (`keep-alive`), но запросы всё равно идут по очереди на одном соединении (Head-of-Line Blocking)|
|HTTP/2|мультиплексирование — несколько запросов параллельно через одно соединение; бинарный формат; сжатие заголовков|
|HTTP/3|работает поверх QUIC (на базе UDP, а не TCP) — устраняет блокировку на уровне транспорта, быстрее восстанавливается после потери пакетов|
