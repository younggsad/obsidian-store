>**Backend (серверная часть)** — это часть приложения, которая работает **не в браузере пользователя**, а на сервере. Она отвечает за:

- Хранение и обработку данных (базы данных)
- Бизнес-логику (правила работы приложения — например, "нельзя купить товар, если его нет на складе")
- Безопасность (проверка прав доступа, защита данных)
- Взаимодействие с внешними сервисами (платёжные системы, email-рассылки, другие API)
- Отдачу данных клиенту (браузеру, мобильному приложению) через API

**Простыми словами:** frontend — это то, что видит и с чем взаимодействует пользователь (кнопки, формы, анимации). Backend — это "мозг за кулисами", который решает, что можно, а что нельзя, откуда брать данные и куда их сохранять.

**Пример потока:** пользователь нажимает "Купить" на сайте →

1. Frontend отправляет запрос на backend ("хочу купить товар X")
2. Backend проверяет: есть ли товар в наличии, авторизован ли пользователь, достаточно ли у него денег
3. Backend обращается к базе данных — списывает товар со склада, создаёт запись о заказе
4. Backend отправляет ответ frontend'у — "заказ создан успешно" (или ошибку, если что-то не так)
5. Frontend показывает пользователю результат

**Почему нельзя доверять всю логику frontend'у:** любой пользователь может открыть DevTools браузера и изменить JS-код на странице, подделать запросы, обойти проверки. Backend работает на **сервере разработчика**, недоступном для прямого изменения пользователем — поэтому вся критичная логика (проверки прав, расчёты цены, работа с деньгами) должна проверяться именно на backend, а не только на frontend (frontend-валидация нужна лишь для удобства пользователя — мгновенной подсказки об ошибке, но не как единственная защита).
