>**Компилируемый язык** — исходный код **заранее**, до запуска, полностью переводится (компилируется) в машинный код (или в промежуточный байт-код) специальной программой — компилятором. Результат — исполняемый файл, который затем запускается **напрямую** процессором, без необходимости в исходном коде во время выполнения. Примеры: C, C++, Rust, Go.

>**Интерпретируемый язык** — код выполняется **построчно**, "на лету", специальной программой — интерпретатором, без отдельного предварительного шага полной компиляции в машинный код. Пример классического интерпретатора — ранние реализации Python, Ruby, Bash-скрипты.

**Плюсы компилируемых языков:**

- Обычно **быстрее** выполняются — вся оптимизация делается заранее, во время компиляции.
- Ошибки типов и синтаксиса ловятся **до** запуска программы (на этапе компиляции), а не в процессе выполнения.

**Плюсы интерпретируемых языков:**

- **Кроссплатформенность** проще — один и тот же исходный код может выполняться на любой платформе, где есть подходящий интерпретатор, без перекомпиляции под конкретную архитектуру процессора.
- **Быстрее цикл разработки** — не нужно ждать компиляции, можно сразу запускать и проверять код.

### Где здесь JavaScript

>JavaScript исторически считается интерпретируемым языком, но современные движки (V8 в Chrome/Node.js, SpiderMonkey в Firefox) на самом деле используют **JIT-компиляцию (Just-In-Time compilation)** — гибридный подход:

1. Код сначала **интерпретируется** построчно для быстрого старта (не нужно ждать полной компиляции перед первым запуском).
2. Движок **отслеживает**, какие участки кода выполняются **часто** ("горячий" код, hot code — например, функция, вызываемая в цикле тысячи раз).
3. Такие "горячие" участки **компилируются в оптимизированный машинный код** прямо во время выполнения программы (отсюда "just-in-time" — "точно вовремя", а не заранее и не построчно всегда).

Это объясняет, почему JS может быть достаточно быстрым, несмотря на то что формально является "интерпретируемым" — на практике современные движки размывают чёткую границу между компилируемыми и интерпретируемыми языками, и JIT-компиляция — стандартный подход для многих динамических языков сегодня (то же самое в Python есть частично, в Java есть похожий механизм — JIT для байткода JVM).
