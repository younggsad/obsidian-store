### Сравнения: `=`, `==`, `===`

#### `=` — это не сравнение, это присваивание

```js
let a = 5; // присваивает переменной a значение 5, это НЕ сравнение
```

Частая опечатка новичков — написать `if (a = 5)` вместо `if (a === 5)`. Это не ошибка синтаксиса, код выполнится, но `a` перезапишется на 5, и условие всегда будет truthy (если 5 не равно 0). Собеседующие любят спрашивать про эту ловушку.

#### `==` — нестрогое сравнение (loose equality)

Перед сравнением JS **приводит типы** операндов друг к другу по определённому алгоритму, и только потом сравнивает.

```js
5 == "5"        // true — строка приводится к числу
0 == false      // true — false приводится к 0
1 == true        // true
null == undefined // true — специальное правило именно для этой пары
"" == 0           // true — "" приводится к 0
```

#### `===` — строгое сравнение (strict equality)

Сравнивает **и тип, и значение**, без приведения:

```js
5 === "5"         // false — разные типы
0 === false         // false
null === undefined   // false
```

#### Алгоритм `==` в двух словах

1. Если типы совпадают — работает так же, как `===`.
2. `null == undefined` — всегда `true`, но `null`/`undefined` не равны ничему другому (даже `0` или `false`).
3. Число vs строка — строка приводится к числу.
4. Boolean vs что угодно — boolean сначала приводится к числу (`true → 1`, `false → 0`), потом сравнение продолжается по этим же правилам.
5. Объект vs примитив — объект приводится к примитиву (через `valueOf`/`toString`).

```js
[] == false     // true:  [] → "" → 0,  false → 0  →  0 == 0
[] == ![]        // true:  ![] сначала = false (объект всегда truthy → NOT даёт false), 
                  //         дальше [] == false → true (см. выше)
"0" == false      // true: "0" → 0, false → 0
[1,2] == "1,2"     // true: массив приводится к строке через join(',')
```

Эти примеры — классические «ловушки JS», которые показывают, почему `==` считается небезопасным.

#### NaN — особый случай

```js
NaN == NaN         // false — NaN не равен даже самому себе (это часть стандарта IEEE 754)
NaN === NaN         // false
isNaN(NaN)            // true — но приводит тип перед проверкой
Number.isNaN(NaN)      // true — правильный способ, без приведения типа
Number.isNaN("hello")   // false — не приводит к числу, поэтому не NaN
isNaN("hello")           // true — "hello" приводится к числу → NaN → true
```

#### `Object.is()` — ещё более строгое сравнение

Отличается от `===` в двух краевых случаях:

```js
Object.is(NaN, NaN)     // true  (=== даёт false)
Object.is(0, -0)         // false (=== даёт true — 0 === -0 это true!)
0 === -0                  // true
```

#### Сравнение объектов (и `==`, и `===`)

Объекты сравниваются **по ссылке**, а не по содержимому — ни `==`, ни `===` не сравнивают значения внутри:

```js
{ a: 1 } === { a: 1 }   // false — разные объекты в памяти
const obj = { a: 1 };
obj === obj                // true — одна и та же ссылка

[1,2,3] === [1,2,3]      // false
```

Для сравнения содержимого нужны отдельные способы: `JSON.stringify(a) === JSON.stringify(b)` (с оговорками про порядок ключей) или библиотеки типа lodash `isEqual`.

#### Правило хорошего тона

Всегда используй `===`/`!==`. Единственное осмысленное исключение — `x == null`, которое разом ловит и `null`, и `undefined`:

```js
if (x == null) { /* сработает и для null, и для undefined */ }
// эквивалентно
if (x === null || x === undefined) { /* ... */ }
```
