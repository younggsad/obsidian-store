## Часть 1. Зачем вообще нужны прототипы

>JavaScript — язык с **прототипным наследованием** (prototypal inheritance), в отличие от классического наследования через классы (как в Java, C#). Это значит: объекты наследуют свойства и методы **напрямую от других объектов**, а не от абстрактных "чертежей"-классов (хотя в современном JS есть синтаксис `class`, под капотом там всё равно работают прототипы).

**Зачем это нужно:** чтобы не дублировать одни и те же методы в каждом отдельном объекте. Представим 1000 объектов-пользователей, у каждого есть метод `sayHello()`. Если бы каждый объект хранил **свою собственную копию** этого метода — это 1000 одинаковых функций в памяти, огромный расход ресурсов впустую. Прототипы позволяют хранить `sayHello` **один раз**, в общем месте, а все 1000 объектов **ссылаются** на это общее место при поиске метода.

## Часть 2. Что такое `[[Prototype]]` и `__proto__`

>У **каждого** объекта в JS есть скрытое внутреннее свойство `[[Prototype]]` (записано в двойных квадратных скобках — так в спецификации ECMAScript обозначают внутренние, недоступные напрямую свойства). Это свойство — ссылка на **другой объект**, который называется **прототипом** данного объекта.

>**`__proto__`** — это **геттер/сеттер-аксессор**, исторически добавленный в браузеры (позже стандартизированный), который даёт доступ к этому внутреннему `[[Prototype]]` напрямую:

```js
const animal = {
  eats: true
};

const rabbit = {
  jumps: true
};

rabbit.__proto__ = animal; // теперь rabbit ссылается на animal как на свой прототип

console.log(rabbit.eats);  // true — свойство найдено не на rabbit, а на его прототипе animal
console.log(rabbit.jumps); // true — своё собственное свойство
```

**Важно:** `__proto__` считается устаревшим (legacy) способом работы с прототипом — он остался в языке ради обратной совместимости со старым кодом, но в современном коде **рекомендуется** использовать вместо него:

- `Object.getPrototypeOf(obj)` — получить прототип объекта
- `Object.setPrototypeOf(obj, proto)` — установить прототип объекта
- `Object.create(proto)` — создать новый объект с заданным прототипом сразу при создании

```js
const rabbit = Object.create(animal); // современный, предпочтительный способ
rabbit.jumps = true;

console.log(Object.getPrototypeOf(rabbit) === animal); // true
```

## Часть 3. Prototype Chain (цепочка прототипов)

Прототип объекта — это **тоже объект**, а значит у **него** тоже есть свой собственный прототип. И у того прототипа — свой прототип. Так образуется **цепочка**, связывающая объекты друг с другом через `[[Prototype]]`.

```js
const grandparent = { canBreathe: true };
const parent = Object.create(grandparent);
parent.canWalk = true;

const child = Object.create(parent);
child.canTalk = true;

console.log(child.canTalk);     // true — собственное свойство
console.log(child.canWalk);     // true — найдено у parent
console.log(child.canBreathe);  // true — найдено у grandparent
```

**Цепочка в этом примере:** `child → parent → grandparent → Object.prototype → null`

Цепочка **всегда** заканчивается на `null` — это финальная точка, у `null` уже нет собственного прототипа, дальше искать негде.

### Как работает поиск свойства через цепочку

Когда выполняется `obj.property`:

1. JS смотрит, есть ли `property` **непосредственно** на `obj` (own property).
2. Если нет — JS поднимается к `Object.getPrototypeOf(obj)` и смотрит там.
3. Если и там нет — поднимается ещё на уровень выше.
4. Продолжает, пока либо не найдёт свойство, либо не дойдёт до `null` — тогда возвращается `undefined`.

**Важный нюанс — запись свойства работает иначе, чем чтение:**

```js
const animal = { eats: true };
const rabbit = Object.create(animal);

rabbit.eats = false; // ЗАПИСЬ — создаёт НОВОЕ собственное свойство на rabbit,
                       // а НЕ изменяет eats у animal!

console.log(rabbit.eats); // false — своё собственное свойство
console.log(animal.eats); // true — прототип не тронут
```

При **записи** (присваивании) свойства через `=`, JS **не** ищет его вверх по цепочке — он **всегда** создаёт (или перезаписывает) свойство **непосредственно** на самом объекте, на котором вызвано присваивание. Поднятие по цепочке происходит **только при чтении**. Это важное отличие, которое часто спрашивают на собесе.

### `hasOwnProperty` — проверка "своё" ли свойство

```js
console.log(rabbit.hasOwnProperty('eats')); // true — после присваивания выше это уже своё свойство
console.log(rabbit.hasOwnProperty('jumps')); // зависит от того, было ли jumps своим у rabbit
console.log('eats' in rabbit); // true — оператор in проверяет ВСЮ цепочку прототипов, не только own
```

**Разница `hasOwnProperty` и оператора `in`:** `hasOwnProperty` проверяет **только собственные** свойства объекта, не поднимаясь по цепочке. Оператор `in` проверяет **всю цепочку целиком**, включая унаследованные свойства.

## Часть 4. Функции-конструкторы и `prototype`

До появления `class` в ES6 объекты с общим поведением создавали через **функции-конструкторы**:

```js
function Animal(name) {
  this.name = name; // собственное свойство КАЖДОГО экземпляра
}

Animal.prototype.eat = function() { // общий метод — один на всех
  console.log(`${this.name} is eating`);
};

const cat = new Animal('Cat');
const dog = new Animal('Dog');

cat.eat(); // "Cat is eating"
dog.eat(); // "Dog is eating"

console.log(cat.eat === dog.eat); // true — это буквально одна и та же функция в памяти
```

### Важно не путать: `prototype` vs `[[Prototype]]` / `__proto__`

Это два **разных**, хотя и связанных понятия, которые часто путают на собесе:

- **`Animal.prototype`** — это обычное свойство **самой функции** `Animal` — объект, который станет прототипом для **всех** объектов, созданных через `new Animal()`. Есть только у функций (точнее, у любых callable-объектов).
- **`cat.__proto__`** (он же `[[Prototype]]` у объекта `cat`) — это ссылка **конкретного экземпляра** `cat` на его прототип, которая **устанавливается автоматически** при вызове `new Animal()`.

```js
console.log(cat.__proto__ === Animal.prototype); // true!
```

**Что именно происходит при вызове `new Animal('Cat')`** — четыре шага, которые полезно знать наизусть для собеса:

1. Создаётся новый пустой объект `{}`.
2. У этого нового объекта `[[Prototype]]` устанавливается равным `Animal.prototype`.
3. Функция `Animal` выполняется с `this`, указывающим на этот новый объект (`this.name = name` записывает свойство именно в него).
4. Если функция **явно** не возвращает объект — новый объект (тот, что был создан на шаге 1) автоматически возвращается как результат `new Animal(...)`.

Можно написать это "вручную", без `new`, чтобы понять механику:

```js
function myNew(Constructor, ...args) {
  const obj = {};                                         // шаг 1
  Object.setPrototypeOf(obj, Constructor.prototype);      // шаг 2
  const result = Constructor.apply(obj, args);            // шаг 3
  return typeof result === 'object' && result !== null ? result : obj; // шаг 4
}
```

### `constructor` — обратная ссылка

У каждого `prototype` по умолчанию есть свойство `constructor`, ссылающееся обратно на саму функцию:

```js
console.log(Animal.prototype.constructor === Animal); // true
console.log(cat.constructor === Animal); // true — найдено через цепочку прототипов
```

Полезно, когда нужно узнать, каким конструктором был создан объект, не имея прямой ссылки на него:

```js
const anotherCat = new cat.constructor('AnotherCat'); // создаём ещё один объект того же "типа"
```

## Часть 5. `class` — синтаксический сахар поверх прототипов

Синтаксис `class`, появившийся в ES6, **не вводит новую модель наследования** — это просто более удобная, читаемая запись поверх той же самой prototype-модели, что и функции-конструкторы.

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  eat() { // этот метод автоматически кладётся в Animal.prototype, а НЕ в каждый экземпляр
    console.log(`${this.name} is eating`);
  }
}

console.log(typeof Animal); // "function" — class это всё ещё функция под капотом!
console.log(Animal.prototype.eat); // функция eat — она действительно там, как и в примере выше
```

**Наследование через `extends`:**

```js
class Dog extends Animal {
  bark() {
    console.log(`${this.name} barks`);
  }
}

const dog = new Dog('Rex');
dog.eat();  // "Rex is eating" — унаследовано от Animal
dog.bark(); // "Rex barks" — собственный метод Dog
```

`extends` устанавливает связь между прототипами автоматически:

```js
console.log(Dog.prototype.__proto__ === Animal.prototype); // true
```

Именно поэтому `dog.eat()` работает — JS ищет `eat` сначала на `dog` (нет), потом на `Dog.prototype` (нет, там только `bark`), потом поднимается по цепочке к `Animal.prototype` (есть) — та же самая логика поиска через prototype chain, которую мы разобрали в Части 3, просто теперь она выстроена через `class`/`extends`.

**`super`** — специальное ключевое слово, дающее доступ к прототипу родителя:

- `super(...)` в конструкторе — вызывает конструктор родительского класса.
- `super.method()` в методе — вызывает метод родителя, даже если в текущем классе метод с тем же именем переопределён.

```js
class Dog extends Animal {
  eat() {
    super.eat(); // вызывает Animal.prototype.eat.call(this)
    console.log(`${this.name} finishes the bowl quickly`);
  }
}
```

## Часть 6. `Object.prototype` — вершина цепочки для обычных объектов

Все обычные объекты (созданные через `{}`, `new Object()`, литералы) в конце своей цепочки прототипов упираются в **`Object.prototype`** — именно оттуда берутся такие вездесущие методы как `toString()`, `hasOwnProperty()`, `valueOf()`, `isPrototypeOf()`.

```js
const obj = {};
console.log(obj.toString); // function — это метод Object.prototype, найденный по цепочке
console.log(Object.getPrototypeOf(obj) === Object.prototype); // true
console.log(Object.getPrototypeOf(Object.prototype)); // null — конец цепочки
```

Это же объясняет, почему у **массивов** и **функций** доступны свои специфичные методы, но при этом они **тоже** имеют доступ к методам `Object.prototype` — у них более длинная цепочка:

```js
const arr = [1, 2, 3];
// Цепочка: arr → Array.prototype → Object.prototype → null

console.log(arr.map);           // есть, из Array.prototype
console.log(arr.hasOwnProperty); // есть, из Object.prototype (унаследовано ещё выше по цепочке)
```

### Объект без прототипа

Можно создать объект, у которого **вообще нет** прототипа — то есть цепочка обрывается сразу:

```js
const pureObject = Object.create(null);
console.log(pureObject.toString); // undefined — нет доступа даже к базовым методам Object.prototype!
```

Такие объекты иногда используют как "чистые словари" (dictionary objects) именно потому что у них нет никаких унаследованных свойств/методов, которые могли бы случайно "просочиться" и создать конфликт имён, если, например, среди ключей словаря вдруг окажется ключ `"toString"` или `"constructor"`.

## Часть 7. `Object.freeze` и защита прототипа

Стоит отдельно разобрать частую путаницу: `Object.freeze(obj)` защищает **собственные свойства** объекта от изменения — но **не** влияет на возможность читать/изменять его **прототип**, если только прототип не заморожен отдельно.

```js
const proto = { greet() { console.log('hi'); } };
const obj = Object.create(proto);
Object.freeze(obj);

obj.newProp = 'test'; // не сработает (obj заморожен)
proto.greet = function() { console.log('changed!'); }; // сработает! proto не заморожен
obj.greet(); // "changed!" — потому что метод ищется по цепочке, а прототип был изменяем
```

## Часть 8. Практические примеры реализации через прототипы (то, что любят просить на собесах)

### Пример 1: реализовать наследование вручную (без `class`)

```js
function Animal(name) {
  this.name = name;
}
Animal.prototype.eat = function() {
  console.log(`${this.name} is eating`);
};

function Dog(name) {
  Animal.call(this, name); // "заимствуем" конструктор родителя, аналог super()
}

// Устанавливаем цепочку прототипов вручную
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog; // восстанавливаем constructor, который "затёрся" строкой выше

Dog.prototype.bark = function() {
  console.log(`${this.name} barks`);
};

const dog = new Dog('Rex');
dog.eat();  // "Rex is eating"
dog.bark(); // "Rex barks"
```

**Важный нюанс:** `Dog.prototype = Object.create(Animal.prototype)`, а **не** `Dog.prototype = Animal.prototype` (частая ошибка) — если написать без `Object.create`, `Dog.prototype` и `Animal.prototype` окажутся **одним и тем же объектом**, и добавление методов в `Dog.prototype` (`bark`) случайно добавит их и в `Animal.prototype` тоже — сломав всех остальных "животных", не являющихся собаками.

### Пример 2: свой `instanceof`

`instanceof` под капотом как раз проверяет, встречается ли `Constructor.prototype` **где-либо** в цепочке прототипов объекта:

```js
function myInstanceOf(obj, Constructor) {
  let proto = Object.getPrototypeOf(obj);
  while (proto !== null) {
    if (proto === Constructor.prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}

console.log(myInstanceOf(dog, Dog));    // true
console.log(myInstanceOf(dog, Animal)); // true — Animal тоже есть в цепочке
console.log(myInstanceOf(dog, Array));  // false
```

## Частые вопросы на собеседовании

**В: Чем `__proto__` отличается от `prototype`?** О: `prototype` — свойство **функции-конструктора**, определяющее, каким будет прототип у объектов, созданных через `new`. `__proto__` — ссылка **конкретного объекта** на его фактический прототип. `cat.__proto__ === Animal.prototype`, но `cat.prototype` не существует (у обычных объектов, не функций, нет своего prototype).

**В: Как работает поиск свойства, если оно есть и на объекте, и на его прототипе?** О: Побеждает **собственное** свойство объекта — поиск сначала проверяет сам объект, и если находит совпадение — дальше по цепочке уже не поднимается. Это называется **property shadowing** ("затенение" свойства прототипа собственным свойством объекта).

**В: Можно ли изменить прототип объекта после его создания?** О: Да, через `Object.setPrototypeOf(obj, newProto)` или устаревший `obj.__proto__ = newProto`. Но это **не рекомендуется** делать часто — движки JS сильно оптимизируют доступ к свойствам объектов, полагаясь на то, что структура/прототип объекта не меняется после создания; частая смена прототипа резко замедляет производительность.

**В: Что выведет `console.log(Object.getPrototypeOf(Object.prototype))`?** О: `null` — это самый верх цепочки прототипов для всех обычных объектов, дальше подниматься некуда.

**В: Является ли `Function.prototype` объектом или функцией?** О: Интересный пограничный случай: `Function.prototype` сам является **функцией** (можно вызвать `Function.prototype()`, хотя это ничего не делает) — это единственный prototype-объект в языке, который одновременно является функцией. Это не входит в базовый набор знаний, но иногда всплывает как "провокационный" вопрос на очень глубоких собесах.
