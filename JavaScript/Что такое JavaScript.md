>**JavaScript** — это высокоуровневый, интерпретируемый (JIT-компилируемый), динамический язык программирования, соответствующий спецификации ECMAScript. Изначально создан для «оживления» веб-страниц, но сегодня используется на серверах (Node.js), в мобильных приложениях (React Native) и даже в десктопе (Electron).

#### 1. Ключевые характеристики (о чем нужно говорить)

- **Динамическая типизация:** Тип переменной определяется во время выполнения, и переменная может менять свой тип.
    
    ``` javascript
    let x = "строка";
    x = 42; // Ошибки нет
    ```
    
- **Интерпретируемость и JIT:** Браузер или Node.js не компилирует код заранее в машинный код, а делает это «на лету» с помощью Just-In-Time компиляции (сначала в байт-код, затем горячие участки в машинный код), что обеспечивает высокую производительность.
    
- **Мультипарадигменность:** Поддерживает объектно-ориентированный (прототипный), императивный и функциональный стили.
    
- **Однопоточность и асинхронность:** JavaScript работает в один поток (Event Loop), но благодаря Web API (браузер) или libuv (Node.js) и системе колбэков/промисов может выполнять неблокирующие операции.
    

#### 2. Фундаментальные концепции для собеседования

[[Методы примитивов]]:

- **Примитивы:** `number`, `string`, `boolean`, `null`, `undefined`, `symbol`, `bigint`. Они передаются по значению и иммутабельны.
    
- **Объекты:** Всё остальное (массивы, функции, даты). Передаются по ссылке.
    

**Области видимости и поднятие (Hoisting):**

- `var` имеет функциональную область видимости и поднимается (hoisting) с инициализацией `undefined`.
    
- `let` и `const` имеют блочную область видимости и не инициализируются до объявления (Temporal Dead Zone).
    

**Замыкание (Closure):**  
Это способность функции запоминать и получать доступ к переменным из своей внешней (лексической) области видимости даже после того, как внешняя функция завершила выполнение. _Самый частый вопрос на собесах._

**Прототипное наследование:**  
В JS объекты наследуют свойства и методы через скрытую ссылку `[[Prototype]]` (доступна через `__proto__` или `Object.getPrototypeOf()`). В отличие от классического ООП, здесь наследуются не классы, а сами объекты.

**Контекст `this`:**  
Значение `this` определяется не местом объявления функции, а тем, как она вызывается.

- В методе объекта: `this` = объект перед точкой.
    
- Функция-конструктор (`new`): `this` = новый созданный объект.
    
- Стрелочные функции: не имеют своего `this`, берут его из замыкания.
    

#### 3. Асинхронность (Эволюция)

- **Callback Hell:** Вложенные колбэки, приводящие к нечитаемому коду.
    
- **Promises:** Объект-обертка для отложенного значения. Имеет состояния: `pending`, `fulfilled`, `rejected`. Методы `.then()`, `.catch()`, `.finally()`. Позволяет избежать callback hell через цепочки.
    
- **Async/Await:** Синтаксический сахар над промисами. Делает асинхронный код похожим на синхронный. Функция `async` всегда возвращает промис. `await` приостанавливает выполнение функции, пока промис не разрешится, не блокируя основной поток.
    

#### 4. Event Loop (Цикл событий)

Ключевая архитектурная концепция.

1. **Call Stack:** Выполняет код синхронно (LIFO).
    
2. **Web API / libuv:** Фоновая обработка таймеров, HTTP-запросов, файлов.
    
3. **Task Queues:**
    
    - _Macrotasks (Callback Queue):_ `setTimeout`, `setInterval`, I/O.
        
    - _Microtasks (Microtask Queue):_ `.then/catch/finally`, `MutationObserver`, `queueMicrotask`.
        
4. **Алгоритм:** Event Loop берет задачу из стека. Если стек пуст, он сначала полностью разгребает очередь микрозадач, и только потом берет одну задачу из очереди макрозадач. _Важно: микрозадачи могут плодить микрозадачи, что может привести к зависанию._
