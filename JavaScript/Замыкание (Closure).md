## Определение

>**Замыкание (closure)** — это комбинация функции и лексического окружения, в котором эта функция была создана. Замыкание даёт внутренней функции доступ к переменным внешней функции, даже после того как внешняя функция завершила выполнение.

Ключевая идея: JS-движок **не удаляет** переменную из памяти (сборщик мусора её не трогает), пока на неё ссылается хотя бы одна "живая" функция-замыкание.

Замыкания создаются **каждый раз**, когда функция объявляется — это не какая-то особая техника, а фундаментальное свойство того, как работают функции в JS. Просто не всегда это свойство используется осознанно.

---

## Базовый пример

```js
function outer() {
  let count = 0; // переменная внешней функции

  function inner() {
    count++; // inner "видит" count, даже вызванная позже
    console.log(count);
  }

  return inner;
}

const counter = outer(); // outer() уже отработала и завершилась
counter(); // 1
counter(); // 2
counter(); // 3
```

`outer()` выполнилась один раз и завершилась. Казалось бы, `count` должна была исчезнуть из памяти. Но `inner` держит на неё ссылку через замыкание — поэтому `count` продолжает жить и обновляться между вызовами `counter()`.

## Практическое применение

### 1. Инкапсуляция / приватные переменные

До появления `#privateFields` в классах, замыкания были основным способом скрыть данные от внешнего доступа.

```js
function createCounter() {
  let count = 0; // приватная переменная — недоступна напрямую снаружи

  return {
    increment() {
      count++;
      return count;
    },
    decrement() {
      count--;
      return count;
    },
    getCount() {
      return count;
    }
  };
}

const counter = createCounter();
console.log(counter.increment()); // 1
console.log(counter.increment()); // 2
console.log(counter.count);       // undefined — прямого доступа нет
console.log(counter.getCount());  // 2 — доступ только через метод
```

### 2. Debounce

```js
function debounce(fn, delay) {
  let timeoutId; // живёт в замыкании между вызовами возвращённой функции

  return function (...args) {
    clearTimeout(timeoutId);
    timeoutId = setTimeout(() => fn.apply(this, args), delay);
  };
}
```

`timeoutId` сохраняется между разными вызовами debounced-функции именно благодаря замыканию — без него пришлось бы хранить состояние где-то во внешней (глобальной) области видимости.

### 3. Мемоизация (кэширование результатов вычислений)

```js
function memoize(fn) {
  const cache = new Map(); // кэш живёт в замыкании

  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) {
      return cache.get(key);
    }
    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

function slowSquare(n) {
  console.log('Вычисляю...');
  return n * n;
}

const memoizedSquare = memoize(slowSquare);
memoizedSquare(5); // "Вычисляю..." → 25
memoizedSquare(5); // сразу 25, без "Вычисляю..." — взято из кэша
```

### 4. Каррирование (currying) и частичное применение

```js
function multiply(a) {
  return function (b) {
    return a * b; // a "запоминается" через замыкание
  };
}

const double = multiply(2);
console.log(double(5)); // 10
console.log(double(10)); // 20
```

### 5. Фабрики функций

```js
function createGreeting(greeting) {
  return function (name) {
    return `${greeting}, ${name}!`;
  };
}

const sayHello = createGreeting('Hello');
const sayHi = createGreeting('Hi');

console.log(sayHello('Alice')); // Hello, Alice!
console.log(sayHi('Bob'));      // Hi, Bob!
```

## Классическая проблема: замыкание в цикле с `var`

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Выведет: 3, 3, 3
```

**Почему так происходит:** `var` не создаёт новую переменную на каждую итерацию цикла — это **одна и та же** переменная `i` во всех итерациях, объявленная в scope функции (или глобально). Все три стрелочные функции внутри `setTimeout` замыкаются на **одну и ту же** переменную `i`. К моменту, когда сработают колбэки (через 100 мс), цикл уже полностью завершился, и `i` имеет финальное значение — `3`.

### Способ 1: заменить `var` на `let`

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Выведет: 0, 1, 2
```

`let` имеет **блочную область видимости** (block scope) — механизм цикла `for` устроен так, что на **каждой итерации создаётся новая привязка** переменной `i`. Каждое замыкание в `setTimeout` держит ссылку на "свою" копию `i` этой конкретной итерации.

### Способ 2: обернуть в IIFE (Immediately Invoked Function Expression)

```js
for (var i = 0; i < 3; i++) {
  (function (j) {
    setTimeout(() => console.log(j), 100);
  })(i);
}
// Выведет: 0, 1, 2
```

Каждый вызов IIFE создаёт **новую функцию с собственным параметром** `j`, который копирует текущее значение `i` на момент вызова. Замыкание внутри `setTimeout` держится за `j`, а не за общую `i` — у каждой итерации своя переменная `j`.

### Способ 3: передать значение как аргумент в `setTimeout`

```js
for (var i = 0; i < 3; i++) {
  setTimeout((j) => console.log(j), 100, i);
}
// Выведет: 0, 1, 2
```

`setTimeout` принимает дополнительные аргументы после задержки и передаёт их в колбэк. Значение `i` копируется в момент вызова `setTimeout` (не в момент срабатывания таймера) — поэтому каждый колбэк получает своё, "зафиксированное" на тот момент значение.

## Частые вопросы на собеседовании

**В: Замыкания — это утечка памяти?** О: Сами по себе — нет, это нормальный механизм языка. Но если замыкание держит ссылку на большие объекты дольше, чем нужно (например, DOM-элементы, которые уже удалены со страницы, но на них остались ссылки в замыкании), это может **привести** к утечке памяти — переменная не будет собрана GC, пока жива функция-замыкание.

**В: Каждая ли функция — замыкание?** О: Технически да — любая функция создаёт замыкание над своим лексическим окружением. Но обычно термин "замыкание" используют именно тогда, когда это свойство **используется осознанно** — то есть функция реально обращается к переменным из внешней области видимости после того, как внешняя функция завершилась.

**В: Чем замыкание отличается от области видимости (scope)?** О: Scope — это область видимости переменной в принципе (где к ней можно обратиться). Замыкание — это конкретный механизм, который позволяет функции **сохранить доступ** к scope внешней функции даже после того, как эта внешняя функция закончила выполняться.
