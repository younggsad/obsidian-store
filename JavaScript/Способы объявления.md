### `var`, `let`, `const`

#### Область видимости (scope)

- `var` — **функциональная** область видимости (function-scoped). Видна во всей функции, где объявлена, игнорируя блоки `{}`.
- `let`/`const` — **блочная** область видимости (block-scoped). Видны только внутри блока `{}`, где объявлены (включая `if`, `for`, `while`, просто `{}`).

```js
if (true) {
  var x = 1;
  let y = 2;
}
console.log(x); // 1 — var "утекает" из блока
console.log(y); // ReferenceError — y не существует за пределами блока
```

#### Повторное объявление

```js
var a = 1;
var a = 2; // OK, просто перезапись

let b = 1;
let b = 2; // SyntaxError: Identifier 'b' has already been declared
```

#### Переприсваивание

```js
let x = 1;
x = 2; // OK

const y = 1;
y = 2; // TypeError: Assignment to constant variable
```

⚠️ Важная деталь: `const` запрещает **переприсваивание переменной**, но не запрещает **изменение содержимого** объекта/массива, на который она ссылается:

```js
const arr = [1, 2, 3];
arr.push(4);      // OK — сам массив меняется, ссылка (переменная arr) — нет
arr = [5, 6];       // TypeError — а вот это уже переприсваивание

const obj = { a: 1 };
obj.a = 2;          // OK
obj.b = 3;           // OK — добавили новое свойство
obj = {};             // TypeError
```

Если нужно запретить и изменение содержимого — `Object.freeze(obj)` (но помним, что это **неглубокая** заморозка, вложенные объекты остаются изменяемыми).

#### Hoisting (поднятие) и TDZ

Все три поднимаются, но ведут себя по-разному:

```js
console.log(a); // undefined — var поднимается и сразу инициализируется undefined
var a = 5;

console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 5;        // let/const поднимаются, но остаются в "temporal dead zone" до этой строки
```

Подробно TDZ разберём отдельным пунктом дальше по списку — но важно уже сейчас запомнить: `var` даёт "тихий" `undefined`, а `let`/`const` — явную ошибку при обращении до объявления. Это осознанное улучшение языка, чтобы отлавливать баги раньше.

#### Привязка к глобальному объекту

```js
var globalVar = 1;
let globalLet = 2;

console.log(window.globalVar); // 1 — var в глобальной области становится свойством window
console.log(window.globalLet); // undefined — let/const не попадают в window
```

#### Классическая задача на собеседовании — `var` в цикле

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3 3 3 — var одна на весь цикл, к моменту вызова колбэков i уже равно 3

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);
}
// 0 1 2 — let создаёт НОВУЮ переменную на каждой итерации цикла
```

Это одна из самых частых задач на понимание связки: **область видимости + hoisting + замыкания**. Стоит уметь объяснить словами, почему так происходит, а не просто помнить результат.

#### Итоговое правило по умолчанию

1. Используй `const` — по умолчанию, для всего, что не переприсваивается.
2. Используй `let` — если переменная точно будет переприсваиваться (счётчики, аккумуляторы).
3. `var` — не используй в новом коде, но знай, как он работает (частый вопрос на собеседовании, плюс встречается в legacy-коде).
