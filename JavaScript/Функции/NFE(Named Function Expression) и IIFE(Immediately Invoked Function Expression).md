### IIFE (Immediately Invoked Function Expression) — немедленно вызываемая функция

#### Что это и зачем

**IIFE** — это функция, которая объявляется и **тут же сразу вызывается**, один-единственный раз, без сохранения в переменную для повторного использования.

```javascript
(function() {
  console.log("Я выполнился сразу!");
})();
```

Разбор синтаксиса:

- `function() { ... }` — обычная функция
- Первые круглые скобки `( ... )` вокруг всей функции — превращают её из **объявления** в **выражение** (это важно, см. ниже почему)
- Вторые круглые скобки `()` в конце — это **немедленный вызов** этой функции, как обычно `fn()`

Со стрелочной функцией:

```javascript
(() => {
  console.log("То же самое, но стрелочная");
})();
```

С передачей аргументов:

```javascript
(function(name) {
  console.log(`Привет, ${name}`);
})("Аня");
```

#### Почему нужны внешние скобки — синтаксическая особенность

```javascript
function() {
  console.log("тест");
}(); // ❌ SyntaxError!
```

JavaScript, встретив ключевое слово `function` в начале строки, **всегда** ожидает Function Declaration (объявление функции), а у объявлений не может быть сразу вызова через `()` — это синтаксически некорректно. Обёртка в скобки `(function() {...})` заставляет движок воспринимать это как **выражение** (Function Expression), а выражение уже можно сразу вызвать.

Альтернативные способы "обмануть" парсер (встречаются реже, но существуют):

javascript

```javascript
(function() { console.log("вариант 1"); })();
(function() { console.log("вариант 2"); }());
!function() { console.log("вариант 3"); }();
+function() { console.log("вариант 4"); }();
```

Первый вариант — самый распространённый и читаемый, остальные — скорее история/встречаются в старом коде.

#### Зачем это нужно — практический смысл

**Главная причина — изоляция области видимости.** До появления `let`/`const` и модулей (ES6), единственным способом "спрятать" переменные от глобальной области видимости был именно IIFE:

```javascript
(function() {
  var secret = "это не видно снаружи";
  console.log(secret);
})();

console.log(secret); // ❌ ReferenceError: secret is not defined
```

Это защищало от **загрязнения глобального пространства имён** — особенно критично было в эпоху, когда на одной странице подключали много `<script>`-файлов, и переменные из разных файлов могли случайно "перезаписывать" друг друга, если объявлялись через `var` в глобальной области.

**Сегодня IIFE используется реже**, потому что:

- `let`/`const` уже создают блочную область видимости сами по себе
- Модули (`import`/`export`) дают полноценную изоляцию файлов

Но IIFE всё ещё встречается — например, для кода, который должен выполниться **один раз** сразу при загрузке, без создания лишней именованной функции в общей области видимости:

```javascript
const config = (function() {
  const isDev = true;
  const apiUrl = isDev ? "http://localhost:3000" : "https://api.example.com";
  return { apiUrl };
})();

console.log(config.apiUrl);
```

Здесь IIFE используется, чтобы посчитать что-то один раз (с промежуточными переменными типа `isDev`, которые не нужны снаружи) и вернуть только итоговый результат.

### 6. NFE (Named Function Expression) — именованное функциональное выражение

#### Что это

Обычно Function Expression пишут без имени (анонимно):

```javascript
const sayHi = function() {
  console.log("Привет");
};
```

**NFE** — это Function Expression, у которой **есть** имя, хотя она всё ещё присваивается переменной:

```javascript
const sayHi = function greet() {
  console.log("Привет");
};
```

#### Особенности — зачем вообще давать имя, если функция и так лежит в `sayHi`?

**1. Имя `greet` доступно ТОЛЬКО внутри самой функции**, но не снаружи:

```javascript
const sayHi = function greet() {
  console.log("Привет");
  console.log(typeof greet); // "function" — видно ИЗНУТРИ
};

sayHi(); // работает
console.log(typeof greet); // "undefined" — снаружи имени greet не существует!
```

**2. Главный практический смысл — рекурсия с надёжной ссылкой на саму себя**

```javascript
const factorial = function calc(n) {
  if (n <= 1) return 1;
  return n * calc(n - 1); // используем внутреннее имя, а не sayHi/factorial
};

console.log(factorial(5)); // 120
```

Почему это важнее, чем кажется — представь, что для рекурсии используется внешнее имя переменной:

```javascript
let factorial = function(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1); // ссылается на ВНЕШНЮЮ переменную factorial
};

let calc = factorial; // сохранили ссылку на функцию в другую переменную
factorial = null; // а теперь "затёрли" оригинальную переменную

calc(5); // ❌ Ошибка! Внутри функции factorial уже null, а не функция
```

Если функция ссылается на **внешнюю** переменную для рекурсии, и эта переменная случайно изменится или будет затёрта (`null`, переприсвоена и т.д.) — рекурсия сломается, потому что имя `factorial` внутри тела функции ищется в момент **вызова**, а не в момент создания.

С NFE такой проблемы нет — внутреннее имя `calc` **не зависит** от внешней переменной:

```javascript
let factorial = function calc(n) {
  if (n <= 1) return 1;
  return n * calc(n - 1); // всегда ссылается на САМУ СЕБЯ, гарантированно
};

let fn = factorial;
factorial = null;

console.log(fn(5)); // 120 — всё равно работает правильно!
```

**Важная деталь:** у Function Declaration (не Expression) эта проблема вообще не возникает, потому что там имя функции и так доступно в окружающей области видимости естественным образом:

```javascript
function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1); // просто обычное имя функции, всё ок
}
```

Поэтому NFE — это по сути способ получить для Function Expression то же самое надёжное "имя", которое у Function Declaration есть по умолчанию.

### Итоговая сравнительная таблица

|Тип|Hoisting тела|Своё `this`|`arguments`|Можно `new`|Особенность|
|---|---|---|---|---|---|
|Function Declaration|✅ Да|✅ Да (обычный)|✅ Да|✅ Да|Имя всегда доступно снаружи|
|Function Expression|❌ Нет|✅ Да (обычный)|✅ Да|✅ Да|Может быть анонимной или именованной (NFE)|
|Arrow Function|❌ Нет|❌ Нет (берёт извне)|❌ Нет|❌ Нет|Лексический `this`, компактный синтаксис|
|IIFE|—|зависит от типа (обычная/стрелочная)|зависит|—|Вызывается сразу же, один раз|
