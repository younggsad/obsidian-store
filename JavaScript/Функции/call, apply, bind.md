>Это три встроенных метода, которые есть у **любой** функции в JavaScript (потому что функции — это тоже объекты, и у них есть свои методы). Все три служат одной цели — **явно указать, чему будет равен `this`** внутри функции при её вызове, вместо того чтобы полагаться на то, как функция вызвана "естественным" образом.

#### 1. Зачем это нужно — напоминание проблемы

```javascript
const person = { name: "Аня" };

function greet() {
  console.log(`Привет, я ${this.name}`);
}

greet(); // Привет, я undefined — this не указывает на person
```

`greet` — обычная отдельная функция, не метод `person`, поэтому `this` внутри неё не связан с `person`. `call`/`apply`/`bind` позволяют это исправить — "одолжить" функцию и явно сказать, каким должен быть `this` во время её выполнения.

#### 2. `call()` — вызывает функцию немедленно, передавая `this` и аргументы по одному

```javascript
function greet(greeting) {
  console.log(`${greeting}, я ${this.name}`);
}

const person = { name: "Аня" };

greet.call(person, "Привет"); // Привет, я Аня
```

Синтаксис: `функция.call(объектДляThis, аргумент1, аргумент2, ...)`

- Первый аргумент `call()` — это то, чем станет `this` внутри функции
- Остальные аргументы передаются в саму функцию по порядку, как обычно

#### 3. `apply()` — то же самое, что `call()`, но аргументы передаются массивом

```javascript
function greet(greeting, punctuation) {
  console.log(`${greeting}, я ${this.name}${punctuation}`);
}

const person = { name: "Аня" };

greet.apply(person, ["Привет", "!"]); // Привет, я Аня!
```

Единственное отличие от `call()`: вместо перечисления аргументов через запятую, передаётся **один массив** со всеми аргументами.

**Мнемоника, чтобы не путать:** "**A**pply — **A**rray" (apply принимает массив), а call — просто перечисляет через запятую (comma).

Практическое применение `apply` — например, найти максимум в массиве без spread-оператора (актуально было до ES6):

```javascript
const numbers = [5, 2, 9, 1, 7];
console.log(Math.max.apply(null, numbers)); // 9
```

(Сегодня чаще пишут проще, через spread: `Math.max(...numbers)` — но понимать `apply` всё равно полезно, встречается в старом коде.)

#### 4. `bind()` — не вызывает функцию сразу, а возвращает НОВУЮ функцию с "прибитым" `this`

Это ключевое отличие от `call`/`apply`, которые выполняются **немедленно**.

```javascript
function greet() {
  console.log(`Привет, я ${this.name}`);
}

const person = { name: "Аня" };

const boundGreet = greet.bind(person); // НЕ вызывается, просто создаётся новая функция

boundGreet(); // Привет, я Аня — вызываем позже, this уже "прибит" навсегда
```

**Особенность:** у функции, полученной через `bind`, `this` **невозможно поменять** повторно, даже если попробовать применить `call`/`apply`/`bind` ещё раз:

```javascript
const anotherPerson = { name: "Максим" };
boundGreet.call(anotherPerson); // всё равно "Привет, я Аня" — bind нельзя переопределить
```

#### 5. Практический пример — почему `bind` особенно важен в связке с колбэками

```javascript
const person = {
  name: "Аня",
  greet: function() {
    console.log(`Привет, я ${this.name}`);
  }
};

setTimeout(person.greet, 1000); // Привет, я undefined!
```

Проблема: когда `person.greet` передаётся в `setTimeout` как отдельная ссылка на функцию, она "отрывается" от `person` (мы это разбирали в теме про `this`) — к моменту вызова через 1000мс, `this` уже не равен `person`.

**Решение через `bind`:**

```javascript
setTimeout(person.greet.bind(person), 1000); // Привет, я Аня — работает правильно!
```

`bind` создаёт новую функцию, где `this` уже навсегда закреплён за `person`, независимо от того, как и откуда её вызовут позже.

#### 6. `bind` также позволяет "заморозить" часть аргументов (partial application / каррирование)

```javascript
function multiply(a, b) {
  return a * b;
}

const double = multiply.bind(null, 2); // "замораживаем" первый аргумент как 2
console.log(double(5)); // 10 — a=2 (зафиксировано), b=5 (передано при вызове)
console.log(double(10)); // 20
```

Первый аргумент `bind` — это `this` (тут он не важен для обычной функции без объекта, поэтому `null`), а последующие — аргументы, которые "фиксируются" заранее. Это называется **partial application** (частичное применение функции) — можно заранее зафиксировать часть параметров, оставив остальные "на потом".

#### 7. Сравнительная таблица

|Метод|Вызывает сразу?|Как передаются аргументы|Возвращает|
|---|---|---|---|
|`call()`|✅ Да|По одному, через запятую|Результат выполнения функции|
|`apply()`|✅ Да|Массивом|Результат выполнения функции|
|`bind()`|❌ Нет|По одному, через запятую (можно частично)|Новую функцию (для вызова позже)|

#### 8. Важный нюанс — стрелочные функции игнорируют `call`/`apply`/`bind`

```javascript
const arrowGreet = () => {
  console.log(`Привет, я ${this.name}`);
};

const person = { name: "Аня" };
arrowGreet.call(person); // Привет, я undefined — call НЕ подействовал!
```

Так как у стрелочных функций нет собственного `this` (они берут его лексически, из окружения), `call`/`apply`/`bind` **не могут** на них повлиять — `this` всё равно останется тем, что было в момент создания функции.

#### Единственный способ дать стрелочной функции нужный `this` — это создать её **в том месте**, где `this` уже правильный, и тогда она "унаследует" его лексически:

```javascript
const person = {
  name: "Аня",
  greet() {
    // тут this = person, потому что greet — обычный метод

    const arrowFn = () => {
      console.log(`Привет, я ${this.name}`); // унаследует this от greet
    };

    arrowFn(); // Привет, я Аня — сработало, но не потому что мы что-то "передали"
  }
};

person.greet();
```

#### Итоговое правило

Если функции нужен изменяемый `this` (через `call`/`apply`/`bind`, или как метод объекта, или как обработчик события DOM) — используй **обычную функцию** (`function` или метод-сокращение `{ method() {} }`).

Стрелочные функции применяй, когда наоборот **хочешь**, чтобы `this` был "заморожен" и не зависел от того, как функцию вызовут — например, чтобы не терять контекст внутри колбэков (`setTimeout`, `forEach` и т.д. внутри метода объекта).

Это не ограничение, которое надо обходить — это осознанный выбор: какую функцию использовать зависит от того, нужен тебе гибкий `this` или, наоборот, зафиксированный.
